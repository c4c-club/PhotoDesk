# 01 · 需求规格说明书

版本 v1.0 · 目标平台 iOS 15.0+ · 语言 简体中文（首版），后续加英文

---

## 1. 产品定位

**一句话**：用上下滑动手势，把整理照片变成"刷"的动作。

**目标用户**：手机里有 5000+ 张照片、从未整理过、又不想学习复杂操作的人。

**三条产品原则**

1. **零学习成本** — 核心操作只有"上下滑"，所有高级功能都藏在第二层。
2. **绝不丢照片** — 任何破坏性操作（删除/隐藏）都有确认 + 撤销双保险。  
   **应用内"删除"一律等于移入系统「最近删除」**，30 天后由系统自动清除，**App 永不执行永久擦除**（见 FR-C4）。
3. **零上传** — 不申请网络能力，所有计算（去重、识别、评分）全部本地完成。

### C. 收藏 / 隐藏 / 移到最近删除

> **🔒 全应用强约束**：应用内任何"删除"操作**只做一件事**——调用 `PHAssetChangeRequest.deleteAssets`，把照片移入系统「最近删除」。
> - **应用内滑动不直接删除、也不做永久删除**，只"移到最近删除"。
> - 照片在「最近删除」中由系统保留 **30 天**，期间用户可在系统相册恢复，或在本 App 撤销窗口内一键恢复。
> - **App 永不提供永久擦除入口**（不二次清除「最近删除」），也不调用任何绕过回收站的路径。
> - App 侧额外在沙盒保留一份副本，**仅用于撤销窗口内恢复**（iOS 无公开 API 从「最近删除」程序化恢复），可在设置中关闭。

## 3. 核心功能详细规格：上下滑手势

### 3.1 交互流程

```
手指按下 → 方向锁判定（|dy| > |dx| × 1.5 才认垂直）
        → 显示动作浮层（图标+文案+背景色），透明度 = |dy| / threshold
        → 位移 ≥ threshold 或 (速度 ≥ 700pt/s 且位移 ≥ 40pt)
        → "锁定"：颜色加深、图标放大 1.1×、触发一次触觉反馈
        → 松手
            ├─ 未锁定 → 回弹动画，取消
            └─ 已锁定 → 播放飞出动画 → 执行动作 → 写入撤销栈 → Toast
```

### 3.2 动作池（上滑/下滑各自独立选择）

| 动作 | 说明 | 破坏性 | 需要确认 |
|---|---|---|---|
| 收藏 | `isFavorite = true` | 否 | 否 |
| 取消收藏 | `isFavorite = false` | 否 | 否 |
| 切换收藏 | 取反 | 否 | 否 |
| 隐藏 | `isHidden = true` | **是** | 默认开 |
| 取消隐藏 | `isHidden = false` | 否 | 否 |
| 移到最近删除 | 移入系统「最近删除」，30 天后由系统清除 —— **不是永久删除** | **是** | 默认开（系统弹窗必现） |
| 加入相簿… | 弹出相簿选择器（最近 5 个 + 新建） | 否 | 否 |
| 分享 | 拉起系统分享面板 | 否 | 否 |
| 查看信息 | 弹出 EXIF 面板 | 否 | 否 |
| 旋转 90° | 编辑类 | 否 | 否 |
| 关闭浏览页 | 返回网格（替代下拉关闭） | 否 | 否 |
| 无 | 禁用该方向手势 | — | — |

**默认配置**：上滑 = 收藏、下滑 = 隐藏（用户原话需求的默认落法）。

### 3.3 灵敏度三档

| 档位 | 位移阈值 | 速度阈值 | 说明 |
|---|---|---|---|
| 舒适 | 80 pt | 500 pt/s | 易触发，适合快速刷 |
| 标准（默认） | 120 pt | 700 pt/s | — |
| 保守 | 180 pt | 900 pt/s | 防误触 |

### 3.4 确认策略（"永不永久删除"的落地）

- 破坏性动作（隐藏 / **移到最近删除**）在设置中有独立开关 `confirmDestructive`（默认 **开**）。
- 开启时：越过阈值松手后先弹确认（`UIAlertController`，带缩略图预览）再执行。
- 关闭时：直接执行 + Toast 撤销（默认 5 秒窗口）。
- **「移到最近删除」始终会额外出现一次系统级确认弹窗**，无法用 API 绕过 → 设置页对此有文字说明，并提供"改用隐藏替代删除"的建议开关。
- **撤销的两条路**：
  1. **撤销窗口内**（默认 5 秒）：点 Toast「撤销」，从 App 沙盒副本重建照片写回系统相册（iOS 无公开 API 从「最近删除」程序化恢复，所以必须自留副本）。
  2. **撤销窗口过后 ~30 天内**：照片仍在系统「最近删除」，用户在系统相册可自行恢复；App 内「最近删除」页提供跳转入口。
- 沙盒副本只是**短期撤销保险**，不是长期备份：默认上限 2GB，按时间淘汰，可在设置关闭。它**不替代**系统「最近删除」。

### 3.5 手势冲突规则

| 场景 | 处理 |
|---|---|
| 图片已放大（zoomScale > 1.01） | 禁用上下滑手势，改为拖动查看 |
| 双指操作进行中 | 禁用 |
| 视频正在播放 | 允许（视频区不响应拖动） |
| 「关闭浏览页」被绑定到下滑后 | 系统下拉返回手势改为：仅从屏幕顶部 60pt 内下拉生效；同时保留左上角关闭按钮 |
| 左右横滑切页中 | 方向锁保证同一时刻只认一个方向 |

### 3.6 状态机

```
Idle ──panBegan──> Tracking ──方向为水平──> Cancelled(交还分页器)
  │                    │
  │                    └──方向为垂直──> Previewing ──松手未达阈值──> Idle(回弹)
  │                                          │
  │                                    达到阈值
  │                                          ↓
  │                                      Locked ──松手──> Confirming(若需确认)
  │                                                              │
  │                                                         确认/免确认
  │                                                              ↓
  └──────────────────────────────────────────────────── Executing ──> Toast(可撤销) ──> Idle
```

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 最低支持 iOS 15.0；不使用任何 iOS 16+ 专有 API（或用 `#available` 双实现） |
| NFR-2 | 不使用任何第三方 SDK/联网库；SPM 依赖数量 ≤ 2（建议 0） |
| NFR-3 | 崩溃率 < 0.5%；PhotoKit 写操作全部在 `performChanges` 内并有错误处理 |
| NFR-4 | 所有破坏性操作可撤销或可恢复；**应用内无任何永久删除路径**，删除一律走系统「最近删除」 |
| NFR-5 | 全量 VoiceOver 标签、动态字体支持、对比度达 AA |
| NFR-6 | 单元测试覆盖率：核心逻辑（手势判定、去重、撤销栈、日期分组）≥ 70% |
| NFR-7 | Xcode 零警告（或警告有明确 TODO 注释） |
| NFR-8 | 核心纯逻辑（手势判定、日期分组、指纹、去重分组、撤销策略）抽入 `PhotoDeskCore` SwiftPM 包，**零 Apple 框架依赖，可在 Linux 上 `swift test`**（见 06 §7.4） |

## 5. 已识别风险（详见 02 文档 §7）

- R1：免费账号自签名 → 无 iCloud / App Groups / 推送
- R2：**无 macOS 环境** → Linux/Windows 均无法编译 iOS；用 GitHub Actions `macos-14` + 按需租云 Mac（06 §7）
- R3：移到最近删除必弹系统确认框 → 手势删除体验受限（建议默认用"隐藏"）
- R4：iOS 无公开 API 从「最近删除」程序化恢复 → 撤销窗口内必须靠 App 沙盒副本重建（03 §5.1）
- R5：`.limited` 受限授权下功能范围收缩
- R6：10,000+ 张库的内存与滚动性能
- R7：去重误判 → 必须人工确认后才移到最近删除
