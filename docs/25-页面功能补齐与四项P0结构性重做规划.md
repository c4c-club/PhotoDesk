## 0. 一句话结论

前几轮不是“补丁不够多”，而是**三个抽象选错了**：

1. 用 `UIScrollView` 的 delegate-zoom 承载查看器缩放；

### 2.2 P0-1 捏合缩小/放大必崩溃

**E1 证据**：`.m13-notes/crash5/DiagnosticReports/` 25 份 `.ips` 全部为同一类 Swift 栈溢出，`app_version = 1.3.0 (4)`：

```
UIScrollView _zoomScaleFromPresentationLayer
  → UIScrollView _getDelegateZoomView
    → viewForZooming(in:)
      → DefaultStringInterpolation.appendInterpolation
        → swift_dynamicCast
          → … 循环
```

**1.4.0 的源码现状（E1）**：

| 位置 | 现状 | 风险 |
|---|---|---|
| `ZoomableImageCell.swift:430-435` | `viewForZooming` 只有 `return zoomContentView` | 旧递归的直接入口已移除，但缩放仍由 `UIScrollView` 的 delegate-zoom 事务驱动 |
| `ZoomableImageCell.swift:441-448` | `scrollViewDidZoom` 每帧读 `scrollView.zoomScale` | 该 getter 正是 `_zoomScaleFromPresentationLayer` 的入口；每帧重新进入 `_getDelegateZoomView` |
| `ZoomableImageCell.swift:344-370` | `layoutImageContent()` 在 `layoutSubviews` 里写 `zoomContentView.frame` / `scrollView.contentSize`，并在 `:352` 读 `zoomScale` | 缩放回弹动画期间 `isZooming == false`，写入会与 UIScrollView 的 transform 事务打架 |
| `ZoomableImageCell.swift:373-390` | `centerZoomContent()` 在 `scrollViewDidEndZooming` 里写 `contentInset` | 结束回调内再次触发布局/滚动回调，形成重入窗口 |
| `ZoomableImageCell.swift:189-211` / `252-280` | `prepareForReuse` / `configure` 先摘 delegate 再 `setZoomScale` | cell 复用时若缩放动画未结束，仍有 UIScrollView 内部状态不一致的风险 |
| `ViewerViewController.swift:514-550` | 缩放 idle 回调 + 待删除队列 drain | 删除事务与缩放事务共享同一 cell，任何几何写入都可能与 `performBatchUpdates` 同帧 |

**结论**：1.4.0 只拆掉了“最显眼的一根递归引线”，但缩放状态的**所有权**仍在 `UIScrollView` 手里；`layoutSubviews`、`scrollViewDidZoom`、`prepareForReuse` 都还能在缩放事务中重入。用户仍报“必崩溃”，与“同一类 reentrancy 未根除”一致。真机 1.4.0 的新 `.ips` 尚未回传，因此本轮不赌某一行，直接**移除 UIScrollView 缩放**。

### 2.3 P0-2 上次位置记不准（概率事件）

**E1 证据（源码级缺陷清单）**：

| # | 缺陷 | 位置 | 为什么导致“概率” |
|---|---|---|---|
| 1 | 位置写入 `UserDefaults`，非原子文件；杀进程/强制退出时最后一次 `set` 可能未落盘 | `LibraryPositionStore.swift:127-135` | 落盘时机取决于系统，**有时记住有时不记住** |

| 5 | `verify` 用“刚写入的 minY”反算 visualY，校验是自证循环 | `LibraryPositionCoordinator.swift:219-247` | 布局随后漂移时仍报 `done` |
| 6 | 前插补偿最多 3 个 layout pass，用户一滚动就放弃 | `LibraryViewController.swift:1416-1444` | 后台补齐全量索引时位置跳走 |

| 8 | `fetchFirstBatch` 找不到锚点时静默回退最新 500 | `LibraryViewModel.swift:309-322` | 锚点被删除/换筛选后回顶，且无提示 |

**结论**：这不是“某一处写错”，而是**保存源太多、恢复没有单一状态机、持久化不是原子的**。概率 = 上述 1/2/3/5 条在启动时是否撞上。v5 必须把“保存资格”和“恢复完成”做成同一个状态机的两个状态。

## 4. P0-A：查看器缩放重做（自管变换，彻底移除 UIScrollView 缩放）

### 4.1 目标 / 非目标

**目标**

- 1×–5× 连续捏合；以捏合中心为锚点；松手后 scale/translation 稳定在合法范围；
- 双击 1× ↔ 2.5×（点击点为中心）；
- 放大后可单指拖动查看细节；1× 时单指仍交给翻页/上下滑动作；
- 翻页、旋转、复用、删除、后台切换后不崩溃、不残留缩放；
- 真机连续 100 轮捏合 0 崩溃；模拟器 500 轮 0 崩溃。

**非目标**

- 不做旋转手势（双指旋转）；
- 不做 UIScrollView 的 bounce/scroll indicator；
- 不引入第三方库（红线：0 依赖）。

### 4.2 视图层级

```
ZoomableImageCell.contentView
└── viewportScrollView (UIScrollView，仅作容器/测试锚点；isScrollEnabled=false，delegate=nil，永不调用 zoom API)
    ├── imageView (UIImageView，frame = aspectFit 尺寸，center = viewport.center + translation，transform = scale)
    └── (可选) overlay
```

> 保留一个 `UIScrollView` 作为 viewport 是为了不破坏既有 UI 测试的 `app.scrollViews["Viewer-ZoomScrollView"]` 锚点；但它**不再承担缩放**：`delegate = nil`、`minimumZoomScale = maximumZoomScale = 1`、`isScrollEnabled = false`。代码审查必须确认 `ZoomableImageCell` 里没有任何 `UIScrollViewDelegate` 实现。

### 4.3 Core 纯几何：`ZoomTransformPolicy`

新增 `PhotoDeskCore/Sources/PhotoDeskCore/ZoomTransform.swift`（只 `import Foundation`）：

```swift
public struct ZoomTransform: Equatable, Sendable {
    public var scale: Double          // 1...5
    public var translationX: Double   // 相对 viewport 中心的偏移
    public var translationY: Double
}

public enum ZoomTransformPolicy {
    /// 捏合：保持 anchor（viewport 坐标）下的内容点不动
    public static func pinch(current: ZoomTransform,
                             pinchScale: Double,
                             anchorX: Double, anchorY: Double,
                             contentWidth: Double, contentHeight: Double,
                             viewportWidth: Double, viewportHeight: Double,
                             minScale: Double = 1, maxScale: Double = 5) -> ZoomTransform

    /// 单指拖动：translation += delta，再按边界钳制
    public static func pan(current: ZoomTransform,
                           deltaX: Double, deltaY: Double,
                           contentWidth: Double, contentHeight: Double,
                           viewportWidth: Double, viewportHeight: Double,
                           minScale: Double = 1, maxScale: Double = 5) -> ZoomTransform

    /// 双击目标：scale 1 ↔ 2.5，以点击点为锚
    public static func doubleTap(current: ZoomTransform,
                                 tapX: Double, tapY: Double,
                                 contentWidth: Double, contentHeight: Double,
                                 viewportWidth: Double, viewportHeight: Double,
                                 targetScale: Double = 2.5) -> ZoomTransform

    /// 布局/旋转变化：保持当前中心内容点，重新钳制
    public static func relayout(current: ZoomTransform,
                                oldViewport: (Double, Double),
                                newViewport: (Double, Double),
                                contentWidth: Double, contentHeight: Double) -> ZoomTransform
}
```

**必须写进 XCTest 的不变量**：

1. 锚点不变：`pinch` 前后，anchor 下的内容点坐标误差 < 1e-9；
2. scale 钳制：小于 1 → 1；大于 5 → 5；NaN/∞ → 安全值；
3. 平移钳制：内容小于 viewport 的轴 → translation = 0；内容大于 viewport 的轴 → 边缘不露白；
4. 双击 1× → 2.5×，再双击 → 1×；
5. 旋转/改 viewport 后仍满足 3；
6. 全部输入为 0/负数/NaN/∞ 时不崩溃、返回有限值。

### 4.4 UIKit：`ZoomInteractionController`

新增 `PhotoDesk/Features/Viewer/ZoomInteractionController.swift`：

- 持有 `UIPinchGestureRecognizer`、`UIPanGestureRecognizer`（1 指）、`UITapGestureRecognizer`（2 击）；
- 状态机：`idle → pinching → settling → idle` / `idle → panning → idle`；
- 回调：
  - `onTransformChanged(ZoomTransform)`：cell 只做 `imageView.transform` / `center` 适配；
  - `onInteractionStateChanged(Bool)`：VC 用来禁用翻页/上下滑动作；
- `pan` 仅在 `scale > 1.01` 时 `shouldBegin`，否则让外层手势处理；
- `pinch` 始终识别；`cancelsTouchesInView = false`；
- 动画只用于双击/回弹，使用 `UIView.animate`；动画期间 `isAnimating = true`，拒绝新手势；
- `reset(animated:)` 供复用/翻页/旋转调用。

**关键约束**：

- 不允许在 gesture 回调里读写 `UIScrollView.zoomScale` / `contentSize` / `contentInset`（因为根本没有 zoom）；
- 不允许在 `layoutSubviews` 里改 `transform`（只在 `layoutSubviews` 里重算 `imageView.bounds` 的 aspectFit 尺寸；transform 由 controller 写）；
- 所有几何计算只调用 `ZoomTransformPolicy`，App 侧不得出现第二套公式。

### 4.5 `ZoomableImageCell` 重写要点

保留对外 API：`configure(item:image:)`、`applyDownloadedImage(_:)`、`showCloudPlaceholder()`、`showFailurePlaceholder(onRetry:)`、`setImage(_:)`、`zoomScale`、`isZoomed`、`hasImage`、`beginLoad/matches/cancelLoad`、`setDownloadHandler`、`onZoomTransactionDidBecomeIdle`（可保留但语义改为“手势 idle”）。

删除：

- `extension ZoomableImageCell: UIScrollViewDelegate`；
- `viewForZooming`、`scrollViewDidZoom`、`scrollViewDidEndZooming`、`scrollViewWillBeginZooming`；
- `zoomContentView`、`contentInset`、`contentSize`、`setZoomScale` 相关代码；
- `ZoomDiagnostics` 里的 `geometryState`（改由 controller 的 `isInteracting` 表达）。

新增：

- `private let zoomController = ZoomInteractionController()`；
- `layoutSubviews` 只做：`imageView.bounds.size = aspectFit(image, viewport)`；`imageView.center = viewport.center + transform.translation`；`imageView.transform = scale`；
- `prepareForReuse` / `configure`：`zoomController.reset(animated: false)`，不调用任何 UIScrollView API；
- 旋转/尺寸变化：`layoutSubviews` 检测 viewport 尺寸变化，调用 `ZoomTransformPolicy.relayout`，再应用；
- 复用期用 `configureToken` 防止旧图片回填覆盖新 cell（沿用现有 token）。

### 4.6 `ViewerViewController` 接线

- `currentCellZoomState()` 改为读 cell 的纯值 `zoomState`（`isInteracting`、`scale`）；
- `onPan(.changed)` 的 `ViewerGesturePolicy.shouldPanBegin`：`cell.isInteracting || cell.zoomScale > 1.01` 时取消上下滑动作；
- 缩放交互期间：`collectionView.isScrollEnabled = false`；交互结束且 `scale <= 1.01` 时恢复；
- 翻页完成/`scrollTo(index:)` 后：对旧 cell 调 `resetZoom()`；新 cell `configure` 自带 reset；
- 删除/隐藏事务：保留 `pendingRemovalActions` 队列，但只按 `cell.isInteracting` 排队，不再有 `CATransaction` 几何提交；
- `wireZoomTransactionIdleIfNeeded` 改名为 `wireZoomIdleIfNeeded`，回调只做 `schedulePendingRemovalDrain`，不再 `refreshDebugBanner` 读几何。

## 5. P0-B：位置记忆 v5（单一状态机 + 原子文件）

### 5.1 语义与不变量

- **语义**：冷启动/杀进程重启后，回到上次离开时**视口内第一条完整可见 cell 的同一像素位置**（不是“同一个月”，不是“居中”）；
- **不变量 I1**：恢复完成前，任何保存都不得写盘；
- **不变量 I2**：同一 queryKey 在一次启动内只恢复一次；恢复完成后才允许 `tracking` 保存；
- **不变量 I3**：保存是原子的；进程被杀不会留下半截 JSON；
- **不变量 I4**：恢复不使用硬超时作为失败条件；锚点不在当前数据时保持等待，直到全量索引完成或用户主动接管；
- **不变量 I5**：恢复过程不改变 `contentOffset` 以外的任何状态；不触发 `scheduleSave`。

### 5.2 数据模型（schema 5）

`PhotoDesk/Core/Support/LibraryPositionStore.swift` 内的 `LibraryPosition` 升级：

```swift
struct LibraryPosition: Codable, Equatable {
    let queryKey: String
    let anchorAssetID: String
    let anchorVisualY: Double      // cell.frame.minY - contentOffset.y（视口坐标）
    let sectionID: String
    let itemIndexInSection: Int
    let offsetRatio: Double        // 最后一级 fallback
    let savedAt: Date
    let schemaVersion: Int         // 5
    // 兼容字段：v1-v4 的 assetID / anchorContentOffsetY / contentHeight / viewportHeight 保留解码
}
```

> 迁移：首次启动读 v1–v4 的 UserDefaults 键（`library.lastPosition.v2.*` / `library.lastPosition.*`），解码后写入 v5 文件；迁移成功后不删除旧键（只读兼容），但 v5 不再写 UserDefaults。`AppearanceSettingsView` 的说明文字改为“只存在本机文件”。

### 5.3 存储：原子文件

新增 `PhotoDesk/Core/Support/PositionFileStore.swift`：

- 路径：`Application Support/LibraryPosition/anchors-v5.json`；
- 结构：`{ "schemaVersion": 5, "entries": { "<queryKey>": LibraryPosition } }`；
- 写：串行 `DispatchQueue(label: "position-file-write", qos: .utility)`，`Data.write(to:options: [.atomic])`；
- 读：`init` 时一次性加载到内存字典；损坏 JSON → 备份为 `.corrupt-<timestamp>` 并从空字典开始，不崩溃；
- `flush()`：`writeQueue.sync {}`，供 `willResignActive` / `scenePhase != .active` 调用；
- 容量：最多保留 64 个 queryKey，按 `savedAt` 淘汰最旧；
- 线程：全部 `@MainActor` 读，写队列只做编码/落盘；`LibraryPosition` 是值类型。

**为什么不用 UserDefaults**：`UserDefaults` 的落盘由系统决定，杀进程时最后一笔可能丢；原子文件 + `flush()` 可控、可测试、可取证。

### 5.4 状态机

```text
idle
  └─ beginRestore(queryKey) → restoring(anchor?)
       ├─ no anchor → settled(top)          // 允许保存
       ├─ anchor 不在当前数据 & 索引未完成 → restoring（保持，不失败）
       ├─ anchor 在数据 → applying → verifying → settled
       └─ 索引完成仍无 anchor → fallback(section/ratio) → settled
  settled → tracking（用户滚动）→ 保存
```

- `restoring` 期间 `canSave == false`；
- `settled` 之后 `canSave == true`；
- 用户主动月份跳转/回到顶部：`cancelRestore` → `settled`，并立即保存新位置；
- 不设 3s 失败；只设“遮罩最长显示 1.5s”，遮罩消失不代表恢复失败，恢复可在后台继续。

新增/重写 Core：`PhotoDeskCore/Sources/PhotoDeskCore/PositionRestoreMachine.swift`（替换 `PositionRestoreStateMachine.swift`）：

```swift
public enum PositionRestorePhaseV5: Equatable, Sendable {
    case idle, restoring, applying, verifying, settled, fallback
}
public struct PositionRestoreMachineV5 {
    public private(set) var phase: PositionRestorePhaseV5
    public private(set) var attempts: Int
    public mutating func begin(hasAnchor: Bool)
    public mutating func dataAvailable(anchorPresent: Bool, indexComplete: Bool, boundsReady: Bool)
    public mutating func applied()
    public mutating func verified(ok: Bool) -> PositionRestorePhaseV5
    public mutating func settleFallback()
    public var canSave: Bool { phase == .settled }
}
```

### 5.5 恢复算法（VC 侧）

`attemptPositionRestore()` 必须按以下顺序执行，全部在主线程：

1. `guard collectionView.window != nil, bounds.width > 0`；
2. `collectionView.layoutIfNeeded()`；
3. 若 `pendingAnchor == nil` → `machine.begin(hasAnchor:false)` → `settled`；
4. `indexPath(forAssetID:)` 查锚点：
   - 存在：`collectionView.scrollToItem(at: indexPath, at: .top, animated: false)`；`layoutIfNeeded()`；读 `layoutAttributesForItem(at: indexPath)!.frame.minY` 与 `contentOffset.y`；`target = minY - anchorVisualY`；`setContentOffset(y: target, animated: false)`；`layoutIfNeeded()`；
   - 不存在且 `isIndexComplete == false`：保持 `restoring`，等下一次快照/布局；
   - 不存在且 `isIndexComplete == true`：按 section/ratio fallback；
5. **校验**：读锚点 cell 的 `frame.minY - contentOffset.y`，与保存的 `anchorVisualY` 比较，误差 ≤ 0.5pt；失败则重试一次（只调整 offset，不重新 `scrollToItem`）；两次仍失败 → `settled` 并在 DEBUG 记录 `restore=verify-failed`，不阻塞 UI；
6. `machine.settled()`；`onRestoreFinished(strategy, target, actual)`；此后 `canSave = true`。

**关键**：`scrollToItem(.top)` 让 UICollectionView 自己算目标 offset（它知道所有 section/header 的几何），比手工用 `layoutAttributes` 估算更可靠；随后只做一次像素修正。

### 5.6 保存策略

| 触发 | 行为 |
|---|---|
| `scrollViewDidEndDragging` / `DidEndDecelerating` | `saveNow`（立即，原子写） |
| `scrollViewDidScroll` | 0.5s 防抖 `scheduleSave`（只在 `tracking` 状态） |
| `UIApplication.willResignActive` | `saveNow` + `flush` |
| `scenePhase != .active` | `saveNow` + `flush` |
| `viewWillDisappear` | **只在 `isMovingFromParent || isBeingDismissed` 时保存**；打开查看器/弹 sheet 不保存 |
| 月份跳转 / 回到顶部 | 取消恢复后 `saveNow` |
| 恢复中 | 一律拒绝 |

`makePositionSnapshot` 继续选“第一条完整可见、不被粘性头遮挡”的 cell；若没有完整可见，取部分可见第一条（`anchorVisualY` 可为负），但恢复时不允许把它钳到顶部：`targetOffsetY` 的合法下界是 `-adjustedTop`，上界是 `contentHeight + bottomInset - viewportHeight`，负 visualY 自然落在合法区间。

### 5.7 前插补偿（全量索引补头）

- `applySnapshot` 前：若有 anchor，记录 `(assetID, visualY)`；
- `dataSource.apply` completion 内：`layoutIfNeeded()`，按同一 `(assetID, visualY)` 调一次 `setContentOffset`；
- 下一个 `viewDidLayoutSubviews`：再校验一次（误差 > 0.5pt 才修），**不设 3 次上限**；
- 用户正在 `isTracking` / `isDecelerating` / 恢复中 → 跳过本次，记 `pendingAnchorPreservation`，等手势结束后一次性补；
- 不允许在 `viewDidLayoutSubviews` 里每次无条件 `setContentOffset`（会自激）；只在有 pending 时执行。

## 6. P0-C / P0-D：矩形框选（Marquee）

### 6.1 语义

- **矩形框选**：从手指按下点 `start` 到当前点 `current` 形成一个矩形；与矩形相交的 cell 进入目标集合；
- **选择模式**：起手 cell 未选中 → 目标 = 起手选中集 ∪ 矩形内 cell；
- **取消模式**：起手 cell 已选中 → 目标 = 起手选中集 − 矩形内 cell；
- **回拖**：矩形缩小，目标集合自然收缩；不需要 parity/visited；
- **竖直下拉**：矩形宽度 = `|current.x - start.x|`（最小 1pt），因此左列下拉只选左列，不会整行；
- **斜向/横向拖动**：矩形覆盖多列，选中矩形内所有 cell；
- **跨 section**：矩形跨越月份头时，按各 section 的实际几何求交；
- **边缘自动滚动**：手指在顶部/底部 60pt 内时逐帧滚动，矩形按内容坐标重算。

### 6.2 几何模型

新增 `PhotoDeskCore/Sources/PhotoDeskCore/MarqueeSelectionPolicy.swift`：

```swift
public struct GridMetrics: Equatable, Sendable {
    public let columns: Int
    public let itemWidth: Double
    public let itemHeight: Double
    public let interItemSpacing: Double
    public let sectionHeaderHeight: Double
    public let sectionItemCounts: [Int]
}

public struct MarqueeRect: Equatable, Sendable {
    public let startX: Double, startY: Double
    public let currentX: Double, currentY: Double
}

public enum MarqueeSelectionPolicy {
    /// 计算矩形与网格相交的 cell 集合；O(可见行数 + 列数)
    public static func cells(in rect: MarqueeRect,
                             metrics: GridMetrics,
                             sectionOriginY: [Double]) -> Set<SlideSelectCell>

    /// select / deselect 两种模式的目标集合
    public static func resolved(base: Set<String>,
                                hitIDs: Set<String>,
                                mode: MarqueeMode) -> Set<String>
}

public enum MarqueeMode { case select, deselect }
```

**几何约定**：

- 每个 section 的 `originY` 由调用方按 `headerHeight + rows * itemHeight + gaps` 累加；
- cell 的 frame：`x = col * (itemWidth + spacing)`，`y = originY + headerHeight + row * (itemHeight + spacing)`；
- 矩形与 cell 相交：`rect.maxX >= cell.minX && rect.minX <= cell.maxX && rect.maxY >= cell.minY && rect.minY <= cell.maxY`；
- 矩形宽/高为 0 时，扩展为 1pt（保证竖直/水平拖动至少命中手指下的 cell）；
- 所有输入非有限 → 返回空集合；不崩溃。

### 6.3 手势控制器重写

`SlideSelectGestureController`：

- `began`：记录 `startPoint`（content 坐标）、`anchorCell`、`baseIDs`、`mode = baseIDs.contains(anchorID) ? .deselect : .select`；
