## 5. 修复一（61a1059）：种子部分成功去重与分批

- **现象**：全量 run 43647518272 的 Marquee 10/14 崩，取证横幅 all=340/772。
- **trace 实锤**（viewer-trace.log，run 43662103747 产物）：`seed failed count=40 attempt=1..4 committed=0 code=-1` × 4（01:26:39–42，Photos daemon 忙）+ `deep-seed done wanted=432 rounds=11`——基础种子 167 请求单事务正踩 seeder 自记载的 -1 高危形态（绿5 实测"167 请求只落 23 张"）。
- **修复**：基础种子与深种子同形 **40/批分批 + 轮间喘息**；事务结果带 `committedDates`（抛错时占位符 localIdentifier 回查真实落库日期），调用方以 locallyCommitted 并集去重——部分成功永不重插。测试断言零改动。
- **验证**：run 43662103747 的 trace 无 seed failed 重现、深种子 rounds=11 恰好 432（无重复）✓。

## 6. 修复二（1b15da0）：种子启动强制网格回 3 列

### 6.1 列数污染实锤（run 43672242625）

- 判别 run（61a1059，GridPinch→Marquee→Stability 顺序）：**GridPinch 绿 → Marquee 红 → Stability 红**，失败断言与全量轮逐字一致（all=340 同源）。
- 机制：`grid.columns` 经 @AppStorage 持久化（默认 3 列）；GridPinchUITests（M16 T02，捏合事务用例）把列数改到 2/5 并**持久化**，且按字母序排在全部按 3 列几何校准的选择类套件之前——**M17 全量是首个把 GridPinchUITests 纳入序列的全量轮**（M16 时代只定向跑），列数污染首次得逞。
- **修复**：带 `-uiTestingSeedDatedPhotos` 的启动（全部几何校准套件）在 App.init 强制 `grid.columns = 3`；GridPinchUITests 自身不带该 flag，持久化语义不受影响（其 4 条用例继续全绿）。
- **验证**：run 43672281399 **Marquee 14/14 转绿** + Stability testSlideToSelect / testToastDoesNotBlockGrid / testCategoryMenu... / testOriginallySelectedNotCleared 4 条转绿。
