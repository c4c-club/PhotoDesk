## 0. 一句话结论

本轮不继续在旧实现上打补丁，而是把三个 P0 当作三条“状态机 + 几何 + 时序”问题重做：

1. 捏合崩溃有两个入口：全屏查看器的自定义缩放状态机，以及照片库网格的连续换列布局。两条都必须修，不能只修查看器。
2. 位置记忆不是“存一个 offset”问题，而是“首批窗口截断 + 全量索引回填 + 恢复验证”三者的竞态。必须先定义可验证的锚点，再允许 settled。
3. 滑动多选不是“手势没触发”，而是命中几何用了粘性头坐标、选中角标依赖错误状态、计数更新被数量差门禁跳过。必须改为真实 layoutAttributes 命中 + 单一选中渲染 + 单一计数源。

## 4. P0-1：捏合缩小/放大必崩溃（双入口）

### 4.1 现象

- 全屏查看器双指捏合，放大后再缩小，偶发/必现崩溃。
- 照片库网格双指捏合切换列数，快速连续捏合时崩溃或布局错乱。
- 现有测试只覆盖查看器 500 轮捏合，没有网格捏合；因此“测试全绿”与用户现象不矛盾。

### 4.2 入口 A：查看器自定义缩放

证据（当前代码）：

- PhotoDesk/Features/Viewer/ZoomInteractionController.swift:141
  guard !isAnimating else { gesture.state = .cancelled; return }
- 同文件:167
  guard !isAnimating, transform.scale > 1.01 else { gesture.state = .cancelled; return }
- 同文件:228-238 在 UIView.animate 内直接 setTransform。
- PhotoDesk/Features/Viewer/ZoomableImageCell.swift:279-284 的 zoomState 把 geometryState 硬编码为 .idle。
- 同文件:417-428 的 applyTransform 直接写 CGAffineTransform 和 center，没有有限值检查。
- viewportScrollView 只是容器：isScrollEnabled=false、delegate=nil、min=max zoom=1；真正的缩放靠 imageView.transform + center 手工维护。

根因假设（按优先级）：

1. R1：在手势回调里直接给系统 UIGestureRecognizer 的 state 赋 .cancelled，破坏 UIKit 手势状态机；连续捏合/动画中捏合时可能触发断言或重入。
2. R1：applyTransform 没有 isFinite 检查。布局尚未完成、bounds 为 0、复用或旋转时，缩放计算可能产生 NaN/Infinity，写入 CALayer 几何直接崩溃。
3. R2：zoomState 的 geometryState 永远 idle，VC 误以为几何稳定，可能在动画/捏合中触发翻页、删除、批量更新。
4. R2：UIView.animate 的 completion 没有代际 token；cell 复用后旧动画仍写新 cell。
5. R4：测试只做捏合循环，没有动画中捏合、极限缩放、旋转、复用、三指等组合。

### 4.3 入口 B：网格捏合换列

证据：

- PhotoDesk/Features/Library/LibraryViewController.swift:258-287 的 onPinch 在每个 .changed 跨阈值时调用 setColumns(target, animated:true, anchor:pinchAnchorIndexPath)。
- 同文件:1576-1608 的 setColumns 每次都 collectionView.setCollectionViewLayout(makeLayout(columns:), animated:true)。
- completion 里 reloadItems(at: indexPathsForVisibleItems) 并 scrollToItem(at: anchor, at: .centeredVertically)，anchor 是捏合开始时的旧 IndexPath。

根因假设：

1. R1：快速连续捏合会叠加多个 setCollectionViewLayout 动画；UICollectionView 在布局过渡未完成时再次更换 layout，内部索引/可见 cell 不一致，触发崩溃。
2. R2：completion 使用旧 IndexPath 和 reloadItems，布局已经变化，滚动目标可能越界或指向错误 item。
3. R2：列数变化没有“单飞事务”，没有 pending target 合并，导致一次手势产生多次布局提交。
4. R4：没有网格捏合 UI 测试，无法证明 200 轮快速捏合稳定。

### 4.4 修复方案

#### 4.4.1 先下沉 Core 纯逻辑

在 PhotoDeskCore 新增（或重写）两个纯类型，禁止 UIKit/Photos 依赖：

- ZoomTransform：scale、translationX、translationY；提供 clamped(min:max:)、isFinite、zoomed(by:around:in:)、panned(by:in:)、identity。所有输入输出为 Double。
- PinchColumnReducer：输入 startColumns、startScale、currentScale、currentColumns、阈值；输出 targetColumns 2...5；提供 shouldCommit、pendingTarget。

XCTest 先写红测试，覆盖：0/负数/NaN/Infinity、最小最大列、连续缩放、阈值滞回、重复提交幂等。

#### 4.4.2 查看器事务化

1. 删除 ZoomInteractionController 中所有 gesture.state = .cancelled 赋值；改为直接 return，让手势自然结束，或用 gesture.isEnabled 的受控切换，禁止改 state。
2. 所有 transform 写入统一走 applyTransform(_:animated:transactionID:)；入口先做 isFinite 和 bounds 非零检查，非法则 reset 到 identity 并记录诊断事件。
3. 动画使用代际 token；completion 只在 token 仍匹配且 cell 未复用时提交。
4. zoomState 的 geometryState 由实际 phase 推导，不再硬编码 .idle；缩放手势/动画期间 ViewerViewController 禁止翻页、删除、dismiss 和批量 reload。
5. layoutSubviews、旋转、cell 复用时取消旧动画并重建 base frame；prepareForReuse 必须 reset identity。
6. 增加诊断日志：non-finite transform、非法 bounds、动画中手势、复用中回调；只在本地日志，不发网络。

#### 4.4.3 网格捏合事务

1. onPinch 只更新事务状态，不直接换 layout：
   - .began：记录 startColumns、pinchAnchorAssetID（捏合中心对应的 assetID，不是 IndexPath）、startScale。
   - .changed：用 PinchColumnReducer 计算 target；若与当前列数不同，写入 pendingTarget；不调用 setCollectionViewLayout。
   - .ended/.cancelled：提交一次最终 target。
2. setColumns 改为单飞：
   - 若已有 layout transition，只更新 pendingTarget，直接 return。
   - 无 transition 时，取出 pendingTarget，调用一次 setCollectionViewLayout(animated:true)。
   - completion 只做：清 transition 标志；按 anchorAssetID 找当前 IndexPath；一次 scrollToItem 到该 asset 的视觉位置；如果还有 pendingTarget，再提交一次。
   - 禁止在 completion 里 reloadItems(at: indexPathsForVisibleItems)；DiffableDataSource 负责增量。
3. 列数变化期间冻结下拉刷新、批量编辑、删除和筛选重载；结束后恢复。
4. 失败/中断时取消 pending，保持当前列数，不留下半过渡状态。

#### 4.4.4 测试矩阵

Core：

- ZoomTransformTests：至少 20 条，覆盖 NaN/Infinity/0 bounds/极限 scale/焦点缩放/边界平移/幂等。
- PinchColumnReducerTests：至少 12 条，覆盖 2...5 列、连续缩放、阈值、快速反向、重复提交。

iOS 单测：

- ZoomableImageCellTests：非法 transform 复位、reuse 复位、动画取消、零 bounds 不崩。
- LibraryGridPinchTests：模拟 200 次 target 变更，断言最多一次在途 transition，最终列数正确，anchorAssetID 不变。

UI：

- ZoomStabilityUITests 扩展：500 轮捏合；双击放大动画中立即捏合；min/max 极限；三指；旋转后捏合；翻页复用后捏合；前后台切换后捏合。
- GridPinchUITests 新增：2→5→2 快速 200 轮；跨月锚点；粘性头存在时捏合；捏合后滚动不跳。
- 真机：采集 .ips 和屏幕录制，记录设备/系统/构建号。

验收：

- 查看器 500 轮 0 崩溃；网格 200 轮 0 崩溃。
- 无 non-finite 日志；无 layout 过渡重入日志。

## 5. P0-2：上次浏览位置记不准（概率事件）

### 5.1 语义

“上次位置”定义为：同一 queryKey（同一相簿/筛选/排序）下，用户离开时视口中第一张完整可见的照片 assetID，以及该照片顶部相对视口顶部的视觉 y。恢复后应看到同一张照片在同一视觉 y，允许 ±2pt。

非目标：不要求恢复滚动惯性、不要求恢复正在进行的多选、不要求跨 queryKey 复用位置。

### 5.2 现有实现与概率根因

证据：

- PhotoDesk/Core/Support/LibraryPositionStore.swift：schema 5，anchorAssetID、anchorVisualY、anchorContentOffsetY、sectionID/itemIndex/ratio/contentHeight/viewportHeight，文件 anchors-v5.json，容量 64。
- PositionFileStore.swift：原子写 + 串行队列 + flush。
- PositionRestoreMachine.swift：idle/restoring/applying/verifying/settled/fallback；canSave 只在 settled。
- LibraryPositionCoordinator.swift:147-181 的 attemptRestore 有 contentWaitAttempts < 30 的估算布局门禁；applyAnchor:184-203 用 scrollToItem(.top) + layout + target=minY-visualY+clamp；verify:233-267 在 anchorMinY 为 nil 时把 visualOK 默认 true。
- LibraryViewController.swift:1239-1271 makePositionSnapshot 取第一条完整可见 cell；:1273-1324 attemptPositionRestore；:1497-1520 enforceHeadInsertAnchor；:1330-1334 在 settled 时清空 pendingHeadInsertAnchor。
- LibraryViewModel.swift:311-324 fetchFirstBatch 用 anchor 全局 index - 250 作为首批窗口；:366-381 后台从 offset 0 取 head 并前插 earlier items。
- LibraryViewController.swift:1094-1101 在 positionCoordinator.isRestoreInFlight 时禁止登记前插补偿；恢复 settled 又清空补偿。

概率链：

1. 首批窗口从锚点所在 month 的中间开始，首屏 section 是截断的；此时布局高度不是最终高度。
2. head 回填从 0 开始前插 earlier items，锚点 minY 增大；如果补偿没有登记，视觉位置向下漂移。
3. 恢复是否先 settle、head 是否先插入，取决于异步时序；所以同一份数据有时准、有时不准。
4. verify 在 anchorMinY 为 nil 时默认通过，导致“恢复完成”是假成功。
5. 保存触发不统一，某些退出路径保存的是旧 offset 或恢复中的 offset。

### 5.3 schema v6

新文件：Application Support/LibraryPosition/anchors-v6.json；保留 v5 只读迁移。

| 字段 | 类型 | 说明 |
|---|---|---|
| schemaVersion | Int | 固定 6 |
| queryKey | String | 相簿/筛选/排序的规范化 key |
| anchorAssetID | String | 锚点照片 localIdentifier |
| anchorGlobalIndex | Int? | 全量索引中的位置；未知则 nil |
| anchorSectionID | String | 月份 section identifier |
| anchorSectionItemIndex | Int | 在 section 内的序号 |
| anchorVisualY | Double | 锚点 cell 顶部相对视口顶部的 y |
| anchorContentOffsetY | Double | 保存时 contentOffset.y |
| gridColumns | Int | 保存时列数 2...5 |
| contentInsetTop | Double | adjustedContentInset.top |
| contentHeight | Double | 保存时 collectionView.contentSize.height |
| viewportHeight | Double | 可视高度 |
| savedAt | Date | 保存时间 |

约束：

- anchorVisualY 必须在 [0, viewportHeight) 内；超出则视为无效记录。
- anchorGlobalIndex 仅用于首批窗口定位，不作为最终身份；最终身份永远是 anchorAssetID。
- 记录损坏/字段缺失时回退到 sectionID + sectionItemIndex；再不行则 fallback 到顶部，并记录原因。

### 5.4 状态机 v6

状态：idle → loading → waitingForWindow → waitingForHead → applying → verifying → settled；任一步失败 → fallback。

关键门禁：

- canSave 仅在 settled 且不在恢复/布局过渡中为 true。
- 如果 fetchFirstBatchWindowStart > 0，说明会发生 head 回填，必须进入 waitingForHead；禁止直接 applying。
- waitingForHead 结束条件：isIndexComplete == true 且 headInsertGeneration 连续两轮不变，且没有 pending head batch。
- applying 只允许一次；重复调用直接返回。
- verifying 必须拿到真实 anchor cell 的 layoutAttributes；nil 视为失败，不得默认 true。

### 5.5 恢复算法

1. 读取 v6；无记录或 queryKey 不匹配 → 正常首批加载，不恢复。
2. 用 anchorGlobalIndex - 250 计算首批窗口；若 anchorGlobalIndex 为 nil，用 anchorSectionID 找该月起点。
3. 加载首批后判断 firstBatchWindowStart：
   - 等于 0：无 head 回填，直接 applying。
   - 大于 0：进入 waitingForHead；先把锚点所在 section 显示出来，但不 settle。
4. 每个 head batch 前插后：
   - 记录插入前 contentHeight、contentOffset.y。
   - 插入后计算 delta = contentHeightAfter - contentHeightBefore。
   - 如果插入的 item 全局 index 小于 anchorGlobalIndex，则 contentOffset.y += delta；否则不调整。
   - 调整后不得立即 verify；等索引完成。
5. 索引完成后 applying：
   - 通过 dataSource 找 anchorAssetID 的 IndexPath；找不到 → fallback。
   - scrollToItem(at: anchorIndexPath, at: .top)；layoutIfNeeded。
   - 取 layoutAttributesForItem(at:) 的 frame.minY；targetOffset = frame.minY - anchorVisualY - adjustedContentInset.top；clamp 到 [0, maxOffset] 后设置。
6. verifying：
   - 再次取真实 attributes；若 nil、cell 不在可见窗口、或 |actualVisualY - anchorVisualY| > 2.0 → 失败。
   - 失败时先尝试一次重试（重新 layout + scroll）；仍失败则 fallback 到锚点 cell 顶部，并记录 fallback 原因。
7. settled 后才允许保存；保存时重新取第一张完整可见 cell，不沿用旧 snapshot。

### 5.6 保存触发矩阵

| 触发 | 行为 |

| scrollViewDidScroll 静止 1.5s | debounce 保存 |
| scrollViewDidEndDragging(decelerate=false) | 立即保存 |
| scrollViewDidEndDecelerating | 立即保存 |

## 6. P0-3：滑动多选不显示选中、数量不对

### 6.1 语义

从某张照片开始拖动，矩形经过的 cell 被选中；从已选 cell 开始拖动则取消经过的 cell；反向拖回可取消；松手后计数等于 SelectionState.selected.count；粘性月份头不能造成整体偏移。

### 6.2 现有实现与根因

证据：

- SlideSelectGestureController.swift：pan .began 才记录 startPoint，6pt 阈值后可能已经换格；baseIDs 快照；mode = 锚点已选 ? deselect : select；矩形 hits → itemID → MarqueeSelectionPolicy.resolved。
- LibraryViewController.swift:893-924 marqueeGeometry 用 DSSpacing 重建 GridMetrics，sectionOriginY 取 layoutAttributesForSupplementaryView 的 header.minY；粘性头 pin 时可能是 pinned 位置而非 section 原点，命中整体偏移。
- 同文件:926-943 applySlideSelection 只遍历 visible cells 的差量，只有 previous.count != current.count 才 updateSelectionCount；同数量换成员不刷新。
- PhotoGridCell.swift:70-73 setSelectionVisible、75-79 isSelectedCell、82-93 setSelected：badge 是否显示同时依赖 isSelectingVisible 和 isSelectedCell；AX value 在 setSelected 中更新，所以可以 AX 显示 selected 但视觉 badge 被隐藏。
- MarqueeSelectionUITests 主要断言 AX value 与宽松计数范围；PhotoGridCellTests 只测 AX 同步。
- LibraryViewController.swift:729-733 enterSelectionMode 的默认 scope 取 currentItemsBySection（仅当前已加载 section），不是 viewModel.filteredItems 全量；索引未完成/只加载首批时，「全选」和计数会少算未加载月份（本轮补充证据）。
- LibraryViewController.swift:865-878 selectAll 虽先 ensureIndexComplete，但之后仍用 currentItemsBySection 重建 scope；若索引窗口/筛选结果未覆盖全库，scope 仍可能短于筛选总数（本轮补充证据）。

根因分级：

1. R2：命中几何不该用 DSSpacing 重建，应该用 collectionView 当前真实 layoutAttributes。
2. R2：手势起点不是 touch-down 点，导致首个 cell 判断错误。
3. R1/R4：cell 的视觉选中状态由两个布尔值交叉控制，AX 与视觉不同步；测试只看 AX，假绿。
4. R2：计数更新被 previous.count != current.count 门禁跳过；同数量换成员时 UI 计数不刷新。
5. R4：UI 测试没有像素/角标可见性断言。

### 6.3 修复方案

#### 6.3.1 真实几何命中

1. 新增 GridHitRegion（Core 已有则复用）：最小/最大 x/y、contains(rect)、intersects(rect)。
2. 在 LibraryViewController 中不再重建 GridMetrics；遍历 collectionView.indexPathsForVisibleItems，对每个 indexPath 调 layoutAttributesForItem(at:)，把 frame 转为 collectionView content 坐标，构造 GridHitRegion。
3. 矩形与 region 做二维相交；只有相交面积 > 0 才命中，边界按半开区间处理，避免整行误选。
4. 粘性头不参与命中；section header 只用于显示，不作为 section 原点。
5. 自动滚动时，每出现新可见 cell 就重新计算当前矩形命中集，并与 base 快照合并；不依赖旧 visibleCells 差量。

#### 6.3.2 手势起点

1. 用 UILongPressGestureRecognizer(minimumPressDuration: 0, allowableMovement: .greatestFiniteMagnitude) 或自定义 UIGestureRecognizer 子类记录 touch-down 点；不能等 pan .began 才取 location。
2. 起点 cell 用真实 attributes 命中，而不是取最近 IndexPath。
3. 手势状态只维护 idle/dragging/ended；拖动中不改 collectionView layout，不 reloadData。

#### 6.3.3 选中渲染单一入口

PhotoGridCell 改为一个入口：

    applySelection(isSelected: Bool, isSelecting: Bool)

规则：

- isSelected 为 true 时，无论 isSelecting 是否为 true，都显示 badge、压暗遮罩和边框。
- isSelecting 为 false 时隐藏多选工具条相关状态，但不能隐藏已选 badge。
- prepareForReuse 必须复位 badge.isHidden、dimView.alpha、layer.borderWidth、accessibilityValue。
- accessibilityValue 与视觉状态从同一个 isSelected 派生，禁止两套布尔值。

#### 6.3.4 计数单一来源

1. SelectionState 是唯一计数源；每次手势 apply 后都 updateSelectionCount(selectionState.selected.count)，删除 previous.count != current.count 条件。
2. 同数量换成员也要刷新计数和可见 cell。
3. 顶部计数文案用“已选择 N 张”；0 时显示“选择照片”。
4. 结束手势时做一次 reconfigureItems（不是 reloadData），保证复用 cell 状态一致。

#### 6.3.5 测试矩阵

Core：

- MarqueeSelectionPolicyTests：矩形相交、边界、空矩形、反向拖动、从已选开始取消、section 边界。
- GridHitRegionTests：二维相交、半开区间、零面积、包含。

iOS 单测：

- PhotoGridCellTests：applySelection 后 badge.isHidden == false、dimView.alpha > 0、borderWidth > 0；reuse 后全部复位；AX value 与视觉一致。
- LibraryMarqueeTests：200 个随机矩形，命中集合与暴力几何一致；粘性头偏移不影响。

UI：

- MarqueeSelectionUITests：左列下拉只选左列；跨行矩形；反向取消；自动滚动；粘性头存在时选择；计数精确等于可见 badge 数。
- 每个用例附截图；断言 badge accessibilityIdentifier 存在且 hittable，不只查 AX value。
- 像素级检查：截图取 badge 中心颜色/压暗区域 alpha，允许 5% 容差；至少一条用例做真实像素断言。

验收：

- 手指经过的 cell 100% 出现可见角标。
- 计数与 SelectionState 完全一致，同数量换成员也刷新。
- 粘性头存在时无整体偏移；无整行误选。
- AX 与视觉一致；测试不再使用宽松范围。
