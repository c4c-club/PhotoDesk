## 3. 逐项判定

### 3.1 操作系统 = Windows 10 原生主机

`uname` 输出 `MINGW64_NT-10.0-19045 … Msys`：这是 Git Bash（MSYS2 模拟层）在 Windows 之上报告的内核标识，**不是 Linux，更不是 Darwin**。Agent 与用户共用同一台 Windows 物理机（主机名 `DESKTOP-PFDD3SO`），不存在伪装成 Linux 的沙箱容器。

### 3.2 Xcode / iOS 工具链 = 完全缺失

`xcode-select` 与 `xcrun` 均报 `command not found`（127）。Xcode 是 macOS 独占软件，Windows 上无法安装。**本机不具备任何 iOS 编译、签名、模拟器操作能力。**

### 3.3 WSL2 / Docker = 有基础设施，未就绪

- WSL2 内核已启用，但唯一发行版是 Docker Desktop 自带的 `docker-desktop`（处于 Stopped 状态），**没有 Ubuntu**。`AGENTS.md §1` 规划的「WSL2（Ubuntu）+ Swift 官方工具链跑 `swift test`」在当前机器上**尚未落地**。
- Docker 29.8.2 已安装，但 daemon 未运行（Docker Desktop 应用未启动）。启动后可用官方 `swift` Linux 镜像跑核心包测试，作为免装 Ubuntu 的替代路径。

### 3.4 ZCode 插件市场「iOS 模拟器」插件调查

用户在插件市场看到 Z.ai 出品的「iOS 模拟器」插件（v0.1.0，含 MCP 服务器 `ios-simulator`、技能 `ios-dev`、命令 `/ios-dev`）。**该插件已被 ZCode 缓存到本地**，直接检查其源码与文档：

**① 自述的运行要求**（`README.md` Requirements 节）：

> - **macOS**。
> - **Full Xcode** selected by `xcode-select`（仅 Command Line Tools 不够）
> - An installed iOS Simulator runtime.
> - Node.js 24.
> - 可选：`idb` / `idb-companion`（点按、滑动等 UI 自动化）

**② 源码证据**——对其 `dist/` 全量 grep，底层调用仅有三个 macOS 本地工具，**无任何云端后端**：

```text
44 idb          （UI 自动化，Facebook idb）
34 simctl       （模拟器控制）
13 xcodebuild   （编译）
—— appetize / ssh / 任何远程后端：0 处
```

且预检代码含硬性平台判断：

```js
// dist/mcp/server.js:33896
ok: process.platform === "darwin",
```

**③ 技能文档自证**（`skills/ios-dev/SKILL.md`）：preflight 检测不到 Xcode/simctl 时，工作流直接终止。

**结论**：该插件是「Mac 上 Xcode Simulator 的自动化遥控器」——把 `xcodebuild → simctl boot/install/launch → screenshot → logs → idb 点按` 封装成 MCP 工具。它**不包含模拟器本体**（渲染依赖 macOS 的 Simulator.app），也**不是 Appetize.io 一类云服务**。在 Windows 上安装后 MCP 进程可以启动，但第一个 `ios_preflight` 即因 `platform !== "darwin"` 失败，后续全部工具不可用。

**它的正确启用时机**：获得任何一台 Mac 后（含 `docs/06 §7.4` 方案 B/D 的云 Mac / 二手 Mac mini），可立即用该插件建立「编译→装包→启动→截图→UI 自动化」闭环。

## 5. 待办与建议

1. **锁定方案 A**（`docs/06 §7.4`）：Windows 编辑 → Git 推送 → Actions 编译 → 产物上传 Appetize.io 验证。本次探测无需再走 §7.1 决策树的其他分支。
2. **补齐 `swift test` 本地环境**（二选一，建议前者）：
   - `wsl --install -d Ubuntu`，随后按 `AGENTS.md §1` 安装 Swift 官方 Linux 工具链；
   - 或启动 Docker Desktop，用 `swift:<version>` 官方镜像挂载 `PhotoDeskCore/` 跑测试（免装发行版，但每次有容器冷启动开销）。
3. **暂不安装「iOS 模拟器」插件**（或装了搁置）：0.1.0 版仅支持 macOS 本地 stdio，对本机零增益；待有 Mac 硬件时再启用。
4. **环境变化后复测**：任何声称"能编译/能跑模拟器"的新环境（云 Mac、新 Agent 主机），重跑 §2 的三条命令即可按 `docs/06 §7.1` 表格重新归类，无需重新调查。

## 6. 后续决策（2026-10-24 追加）

探测完成后，用户据此拍板了最终构建方案（已回写进 `docs/06 §7`）：

1. **锁定链路**：Windows 编辑 → Git 推送 → GitHub Actions `macos-14` 编译 → **手机验证**。
2. **不安装 Ubuntu**：本地跑 `PhotoDeskCore` 的 `swift test` 改走**已有的 Docker 29.8.2 + `swift:6.0-noble` 容器**，
   用完即弃，不引入 Linux 系统（对应本报告 §5 待办 2 的**路线 B**，路线 A 已废弃）。
3. **验证从"云端模拟器"改为"真机"**：CI 增加产出**未签名 ipa**（`CODE_SIGNING_ALLOWED=NO` + `Payload` 打包），
   Windows 上用 **AltServer** 签名安装到 iPhone，免费 Apple ID 7 天续签；付费账号可升级为 CI 全自动签名。
   Appetize.io 降级为可选的补充手段。
4. **ZCode「iOS 模拟器」插件**：维持"暂不安装"（本报告 §5 待办 3）。

> 本报告的探测事实（§1–§4）仍然有效；§5 待办中与上述决策冲突的部分以本节为准。
