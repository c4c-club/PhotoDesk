## 3. 手势仲裁裁决（回答 docs/36 §4 Q3/Q8）

**裁决：保留方向锁，产品不改裁决。**

1. **pressing 阶段方向锁保留**（`SelectionGestureMachine.swift:178-195`）：横向占优（|dx| > |dy|×1.2）进入轨迹；纵向占优让位滚动；对角未决在 ≤8pt（`allowableMovement`）预算内继续等待。理由：a) 交互表第 4 行「单指纵向快速滑允许滚动、不得误选」是硬需求，45° 斜率滚动起手若直接进轨迹会误选；b) 对角未决窗口 ≤8pt 位移不足以构成滚动意图，且超预算即判长按死亡（:176），无卡死路径。
2. **armed 起任意方向**（`:196-204`，现状已对）：长按已表达选择意图，不设方向限定——交互表第 2 行「长按不抬手继续拖」、第 3 行「多选模式斜拖」由此满足；「任意方向拐弯都跟手」由 dragging 态逐帧 moved 不限方向（`:205-207`）保证。
3. **scrollStarted 任意阶段收尾**（`:224-245`）保留：轨迹进行中系统滚动接管（边缘回弹触发 scrollViewWillBeginDragging）时 endTrail 落定路径事务，避免半开事务泄漏。
4. **不退回双指专属规则**：marqueePan `maximumNumberOfTouches = 1`（`LibrarySelectionController.swift:115`）+ B03 审查项锁死 `minimumNumberOfTouches = 2` 禁止（`LibraryViewController.swift:856` 注释明示不再修改）。

**最小可验证仲裁状态表**（iOS 16.4 模拟器验证 = T08 UI 套件；真机 = T09）：

```text
idle --touchDown(cell)--> pressing --holdElapsed--> armed --moved≥6pt(任意方向)--> dragging
pressing --moved 横向占优--> dragging（必要时先 enterSelection）
pressing --moved 纵向占优--> idle（releaseScroll 让位滚动）
dragging <--edgeEntered/edgeExited--> autoScrolling
dragging/autoScrolling --scrollStarted--> idle（endTrail + releaseScroll 落定）
armed/dragging/autoScrolling --ended/cancelled--> ending --下一事件--> idle
```

**影响的测试**：`SelectionGestureMachineTests` 的 `testDiagonalUndecidedStaysPressing`(:86)、`testRow3HorizontalLock*`(:96/:105)、`testRow4VerticalDragDuringPressingFailsToIdleAndReleasesScroll`(:116)、`testScrollStartedDuringDraggingFinishesMarquee`(:387) —— T04 改名后断言语义不变；UI 侧 `testSingleFingerScrollWorksInSelectionMode`（`MarqueeSelectionUITests.swift:250`）保留并纳入 T08 新套件。

## 5. 两个基线与路径事务取证帧（回答 docs/36 §4 Q5）

**anchorInitiallySelected（select/deselect 模式判定）——touchDown 帧、enterSelection 之前**：

## 6. UIKit 系统多选 API 不采用的裁决（回答 docs/36 §4 Q7）

**不启用 `collectionView(_:shouldBeginMultipleSelectionInteractionAt:)` 及系统多选交互**（UICollectionViewDelegate 多选 API，Apple 文档标注 Available iOS 13.0+，非本项目基线问题）。理由：

1. **双事实源冲突**：启用后 UIKit 接管长按→编辑态（`isEditing`、系统 selectedIndexPaths、系统勾选 UI），与唯一事实源 `SelectionState`（Core `SelectionPolicy.swift:7-15`：scope/插入顺序/月 scope/`applyDelta`）形成双轨；Diffable 增量更新（`LibraryViewController.swift:1023-1031`）、月 scope 全选（`:874-880`）、TrashBin 批量（`:1041-1077`）都要追加系统态桥接，偏离「Feature 层不直接引用系统选中态」的架构规则 1。
2. **渲染不可承载**：自定义选中渲染（角标 spring/12% 压暗/2pt 边框/AX value 同源，`PhotoGridCell.swift:84-118`）会被系统 selected 视觉替代，AX 取证协议（`"<assetID> selected/none"`，`:200-204`）失配。
3. **语义不足**：系统 API 只表达「进入/退出编辑态 + 点选切换」，无轨迹扫掠、无路径栈回滑取消——与 M18 核心交互（docs/38 §1.1 第 5/6 行）不匹配。
4. **iOS 16 基线无害**：不启用则 iOS 13/16/17 差异为零，B02 审查项不涉。

本裁决写入 docs/38 §2.1（T01 修订），audit-m18 以 P05-P08 锁自建链路存在、B03 锁双指禁止。

## 7. 自动滚动采样顺序（回答 docs/36 §4 Q9）

**每 displayLink tick 的固定顺序**（`LibrarySelectionController.swift:421-445`）：

1. `SlideSelectPolicy.edgeVelocity` 算速度（指尖视口 y → −min…+max 2–12pt/帧，Core `SlideSelectPolicy.swift:11-45`）。
2. `SlideSelectPolicy.clampedOffset` 钳制目标 contentOffset（`SlideSelectPolicy.swift:48-75`）→ `setContentOffset(animated: false)`（`:441-442`）。
3. `feedEdgeEvents()`（`:443`）：内容触底/顶后方向保持、位移钳制；边缘进出事件严格配对（Core `:249-270`）。
4. `processTrail()`（`:444`，现为 processFinger）：**先滚动、后采样**——采样线段 = `lastTrailContentPoint`（上一帧指尖 content 坐标）→ 本帧指尖 content 坐标。

**不漏格/不逆序的保证**：

- 手指窗口坐标不动、内容流过：offset 变化使指尖的 **content 坐标**随内容流动，帧间线段恰好覆盖流过的屏外 cell——不需要额外补扫；快速拖动的屏内跨格由同一机制覆盖（线段扫掠按 t 升序入栈）。
- 指尖静止停在边缘（无 pan .changed）：`edgeMonitorLink` 逐帧仍滚动；若本帧线段两端重合 → `consume([])` 幂等无操作，不产生幽灵命中；新内容流过指尖 → content 端点变化 → 正常入栈。
- 顺序承诺在 Core：`TrailHitResolver.orderedIDs` 按进入参数 t 升序输出，`SlideSelectTrail` 单调 append/截断——T03/T07 单测锁（乱序/重复 frame、快跨补扫、2 万 frame <20ms 预算）。
