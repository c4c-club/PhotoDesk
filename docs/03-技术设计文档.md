## 2. 导航方案（iOS 15 兼容的 Router）

`NavigationStack` 不可用，但 `NavigationView` + 一堆 `isActive` binding 会导致导航状态散落在 View 里。因此自建轻量 Router：

```swift
// Core/Routing/Router.swift
enum Route: Hashable {
    case viewer(startIndex: Int, scope: PhotoScope)
    case album(albumID: String)
    case cleanup(ScanKind)
    case metadata(assetID: String)
    case settings
    case vault      // 需生物识别
}

final class Router: ObservableObject {
    @Published var path: [Route] = []          // 我们自己维护栈
    @Published var sheet: Route?
    @Published var cover: Route?

    func push(_ r: Route)   { path.append(r) }
    func pop()              { _ = path.popLast() }
    func popToRoot()        { path.removeAll() }
    func replaceTop(_ r: Route) { if !path.isEmpty { path[path.count-1] = r } }
}
```

- 根容器：`NavigationView { RootView().background(NavigationLink 隐藏桥接) }`，用 `PathHost` 把 `path` 映射为 `NavigationLink(isActive:)` 链（层级固定 5 层以内即可）。
- **更简单可靠的备选**：`RootView` 用 `ZStack` + 自定义 `Transition` 手工管理 push/pop（因为本项目页面栈很浅，最多 3 层）。→ **首版推荐此路**，代码量小、可控；Viewer 用 `.fullScreenCover` 呈现。

## 5. 关键技术方案

### 5.1 上下滑手势引擎（核心）

**位置**：`Features/Viewer/SwipeGestureEngine.swift`（纯 Swift，不依赖 UIKit 视图，可单测）

```swift
struct SwipeConfig {
    let distanceThreshold: CGFloat      // 80 / 120 / 180
    let velocityThreshold: CGFloat      // 500 / 700 / 900 pt/s
    let minDistanceForVelocity: CGFloat // 40
    let confirmRequired: Bool
}

enum SwipeDirection { case up, down }

struct SwipeResolver {                       // 纯函数，100% 可单测
    let config: SwipeConfig
    func direction(of translation: CGSize) -> SwipeDirection? {
        guard abs(translation.height) > abs(translation.width) * 1.5 else { return nil }
        return translation.height < 0 ? .up : .down
    }
    func progress(translation: CGSize) -> CGFloat {          // 0...1
        min(abs(translation.height) / config.distanceThreshold, 1)
    }
    func isLocked(translation: CGSize, velocity: CGSize) -> Bool {
        let d = abs(translation.height), v = abs(velocity.height)
        return d >= config.distanceThreshold
            || (v >= config.velocityThreshold && d >= config.minDistanceForVelocity)
    }
}
```

**UIKit 手势挂载**（`ViewerViewController`）：

```swift
let pan = UIPanGestureRecognizer(target: self, action: #selector(onPan(_:)))
pan.delegate = self                 // 实现 gestureRecognizerShouldBegin / simultaneouslyWith
pan.maximumNumberOfTouches = 1
pagerContainerView.addGestureRecognizer(pan)

// 关键 delegate 逻辑
func gestureRecognizerShouldBegin(_ g: UIGestureRecognizer) -> Bool {
    currentZoomScale <= 1.01 && !isPlayingTransition && !isTwoFingerZooming
}
func gestureRecognizer(_ g: UIGestureRecognizer,
    shouldRecognizeSimultaneouslyWith other: UIGestureRecognizer) -> Bool { true }
```

- 平移量不真正移动图片（图片固定），只驱动 **ActionOverlay**（图标 + 文案 + 颜色 + 透明度 + 轻微 scale 1.0→1.15）。
- 方向锁：`UIPanGestureRecognizer` 与 `UICollectionView` 的 paging gesture 同时识别，靠 §5.1 的方向判定决定谁生效：垂直 → `pager.isScrollEnabled = false`；水平 → overlay 隐藏。
- 触发后：`UIImpactFeedbackGenerator(style: .medium).impactOccurred()`（`hapticsEnabled` 为真时）。

**执行管线**：

```
locked && ended
  → 若 confirmRequired && action.isDestructive
        → UIAlertController(title:"隐藏这张照片？", 带缩略图) → 确认才继续
  → 飞出动画（Reduce Motion 时改为淡出）
  → action.execute(asset)               // PhotoWriter / VaultService / TrashBin
  → UndoCenter.push(entry)              // 内存 + Core Data
  → 若 autoAdvance && action != .showInfo → 前进到下一张
  → Toast(action.displayName + " · 撤销")  // 5 秒倒计时
```

**撤销实现**：

| 动作 | 撤销方式 |
|---|---|
| 收藏/取消收藏 | `isFavorite` 取反 |
| 隐藏/取消隐藏 | `isHidden` 取反 |
| 加入相簿 | `PHAssetCollectionChangeRequest` 移除 |
| 移到最近删除 | **主路径**：用户可在系统相册「最近删除」中自行恢复（30 天内）；**撤销窗口内**：从 `TrashBin` 沙盒副本用 `PHAssetCreationRequest.fromImage(atFileURL:)` 重新写入，并恢复 `creationDate` / `location` |
| 旋转 | 反向旋转保存 |

> **删除语义红线**：`deleteAssets` 是唯一的删除实现，只把照片移入系统「最近删除」。  
> **App 内不实现任何永久擦除**（不提供"彻底删除"、不清除「最近删除」）。  
> 沙盒 `TrashBin` 只是**撤销保险**（弥补 iOS 无法程序化恢复「最近删除」的缺口），不是备份——上限 2GB、按时间淘汰、可关闭。

**TrashBin：执行"移到最近删除"之前必做**（否则撤销窗口内无法恢复）：

```swift
// 0. 前置校验：iCloud-only 且未下载 → 直接拒绝，提示"请先下载原件"
// 1. 请求原始数据
asset.requestContentEditingInput(with: nil) { input, _ in
    // input.fullSizeImageURL 或 AVAssetExportSession 导出视频
    // 2. 拷贝到 ApplicationSupport/_Trash/<uuid>.<ext>
    // 3. 写 TrashItem（含 creationDate/location/UTType）
    // 4. 再执行 PHAssetChangeRequest.deleteAssets  ← 只是移入系统「最近删除」
}
```
- 若原始数据获取失败（iCloud 未下载）→ **拒绝删除并提示"请先下载原件"**。
- 副本写入成功但删除失败 → 清理该副本，不留垃圾。
- 撤销窗口过后副本即无意义，由 `TrashPolicy` 按容量/时间自动淘汰。

### 5.2 图片加载管线

```swift
protocol ImagePipelineProtocol {
    func thumbnail(for id: String, size: CGSize, scale: CGFloat) async -> UIImage?
    func prefetch(ids: [String], size: CGSize)
    func cancel(id: String)
    func fullImage(for id: String, progress: @escaping (Double)->Void) async -> UIImage?
}
```

- 内存：`NSCache<NSString, UIImage>`，`totalCostLimit = 60MB`，`countLimit = 500`；收到 `didReceiveMemoryWarning` 清空。
- 磁盘：`Library/Caches/ThumbCache/<md5(id + size)>.jpg`，LRU 按 `modifiedDate`，超限清最老；上限 200MB；设置页可清。
- PhotoKit：`PHCachingImageManager`，`allowsCachingHighQualityImages = false`（首版只缓存缩略图）。
- 请求合并：同一 `id+size` 在途请求用字典合并回调，避免重复请求。

### 5.4 去重扫描（Cleanup）

```swift
final class ScanCoordinator {
    func scan(kind: ScanKind) async throws -> ScanResult
    // 1. 取全量 assets 的 localIdentifier 列表（分批，每批 500）
    // 2. 过滤已计算指纹（Core Data 存在且 algoVersion 匹配）
    // 3. 并发（maxConcurrent = 4）取 256px 缩略图 → dHash
    // 4. 写入 Core Data（批量 save，每 200 条一次）
    // 5. 分组：按 (aspect 近似 + |Δt| ≤ 2s) 分桶 → 桶内两两汉明距离
    // 6. 生成 DuplicateGroup，推荐 bestAssetID
    // 7. 每步更新 ScanSession.cursor，支持中断恢复
}
```

- 取消：`Task.isCancelled` 检查点放在每批之间。
- 内存：缩略图用完即弃，只留 64-bit 指纹（8 字节/张，10,000 张 = 80KB）。
- 结果展示：并排卡片 + 差异高亮（可选）+ 推荐标签 + 一键"保留推荐项，其余加入待清理清单"。

### 5.5 模糊检测（P2）

`CIFilter(name: "CILaplacian")`? — 更简单：用 `CIAreaAverage`/自建卷积核。推荐用 `VNGenerateImageFeaturePrintRequest` 不适配；改用：
- 缩放至 512px 长边 → 灰度 → `CIFilter.convolution3X3` 拉普拉斯核 → 计算 `CIAreaHistogram`? 
- **实用做法**：用 `CIFilter(name:"CIUnsharpMask")` 不直观 → 直接用 `vImage`（Accelerate）做 3×3 卷积 + 方差统计，约 30 行代码，性能好。
- 阈值：方差 < 60（0–255 灰度）判为模糊，设置可调。

### 5.10 `PhotoDeskCore`：无 Mac 环境下的可测性设计

**动机**：本机是 Windows 10 原生，Xcode 编译要走 CI，反馈周期长（分钟级）。把纯逻辑抽成独立包后，在 **Docker 容器（`swift:6.0-noble`）** 里 `swift test` 可给出**秒级**反馈——容器用完即弃，**不需要安装 Ubuntu 或引入任何 Linux 系统**（用户明确决策）。

**边界规则（写进 AGENTS.md）**：

| 允许 | 禁止 |
|---|---|
| `import Foundation` | `import UIKit` / `SwiftUI` / `Photos` / `Vision` / `CoreImage` |
| 值类型、`struct`、纯函数 | 任何 `PHAsset` / `UIImage` 引用 |
| `struct` 化的 `Clock` 协议注入 | 单例、全局可变状态 |

**App 侧如何复用**（不重复实现）：

```swift
// PhotoDesk/Features/Viewer/SwipeGestureEngine.swift
import PhotoDeskCore

struct SwipeResolverAdapter {                 // 只做 CGSize → 包内类型的适配
    private let resolver: SwipeResolver
    func direction(of t: CGSize) -> SwipeDirection? {
        resolver.direction(dx: Double(t.width), dy: Double(t.height)).map { ... }
    }
}
```

- `Package.swift` 中 `platforms:` **留空**（不声明 `.iOS(...)`），保证 Linux 可编译；App 工程通过本地 path dependency 引入：
  ```swift
  .package(path: "../PhotoDeskCore")
  ```
- CI 增加一步 Linux job：`swift test --package-path PhotoDeskCore`，push 即知核心逻辑是否回归
  （Windows 主机本地则在 Docker 里跑同一条命令，见 06 §7.2）。

## 6. 线程模型

| 工作 | 队列 |
|---|---|
| PhotoKit fetch / 写操作 | `performChanges` 内部自行调度；fetch 放 `Task.detached(priority: .userInitiated)` |
| 缩略图解码 | ImagePipeline 内部串行队列（避免并发解码爆内存，max 4） |
| 指纹/模糊/OCR 计算 | `DispatchQueue.global(qos: .utility)` + `TaskGroup(maxConcurrent: 4)` |
| Core Data 写 | 私有 `NSManagedObjectContext`（`performBackgroundTask`），主线程只读 `viewContext` |
| UI 更新 | `@MainActor` |
