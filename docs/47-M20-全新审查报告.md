## 1. 用户问题与验收原话

用户当前提出三条：

1. 首次启动如果没有授予照片权限，下次启动不会再次拉起授权；页面上也没有手动授权或导入照片按钮。
2. 滑动多选仍然不对。按每行 4 张的坐标：
   - 按住 (1,1) 进入多选，只选中 (1,1) 这一张；
   - 向右滑依次选中 (1,2)、(1,3)、(1,4)；
   - 从 (1,4) 向下到 (2,4)，选中第 1、2 行；
   - 再向下到 (3,4)，选中第 1、2、3 行；
   - 从 (3,4) 向左到 (3,2)，取消 (3,4)、(3,3)，第 1、2 行保持选中。
3. 用「选择」按钮进入多选后，无法触发滑动选择。

用户另要求：详细规划文档 + 启动提示词；执行 Agent 必须按任务卡分段读取，一次只读一个任务，不预读、不污染上下文；全部完成后打包 IPA 并报告路径。用户明确要求本轮不修改代码（重复两次）。

## 3. F1：授权恢复路径

### 3.1 当前实现事实

PhotoDesk/Core/Photos/PhotoLibraryService.swift:20 在 init 中一次性读取 PHPhotoLibrary.authorizationStatus(for: .readWrite)。第 28-33 行的 requestAccess 只在被调用时更新 access；第 36-38 行有 presentLimitedLibraryPicker；没有任何 refresh 方法。

PhotoDesk/Features/Library/LibraryViewModel.swift:23-30 的 ViewState 只有 notDetermined / loading / ready / empty / denied / restricted，没有 .limited。第 126-138 行 start() 把 .limited 与 .authorized 一起交给 loadIfNeeded()；第 302-307 行在 totalCount == 0 时统一设置 .empty。于是「限制访问且一张都没选」和「全量授权但空库」得到同一个普通空态。

PhotoDesk/UI/DesignSystem/DSEmptyState.swift:24-35 的 .empty 只有「去拍一张或导入几张试试」文案，没有按钮；第 61-83 行已经写好 .limited 的横幅，但全仓没有实例化。

PhotoDesk/Features/Library/LibraryContainer.swift:47-60 的根 switch 没有 .limited；第 167-176 行 onAppear 只调用 viewModel.start()；第 186-194 行 scenePhase 只保存位置，onReceive(access) 只启动 VM。没有「回前台重新读系统授权」的路径。

PhotoDesk/Features/Onboarding/PermissionIntroView.swift 有 intro/denied/restricted 三模式；denied 模式主按钮在 LibraryContainer.swift:51-54 调用 requestAccess，次按钮才是「去系统设置」（第 57 行，ID Permission-Open-Settings）。主按钮没有 accessibilityIdentifier；第 89-95 行 denied 主按钮标题是「重新检查授权」。iOS 在用户选择「不允许」后不会再次弹系统框，requestAccess 只会立刻返回 .denied，因此这个按钮名不副实，也没有任何可见反馈。

### 3.2 根因

1. 授权状态是启动快照，不是每次前台恢复都刷新的实时状态。
2. 受限授权空库没有独立 ViewState，导致正确的 .limited 空态永远不出现。
3. denied 页缺少正确的「去系统设置」主路径，且「重新检查」不能产生系统弹窗。
4. 全量授权空库没有导入入口，用户只能退出 App 去系统相册导入。

### 3.3 正确的产品行为

iOS 的硬约束必须写进 UI 文案：

- .notDetermined：首次启动显示「允许访问照片」，点击后系统弹窗；用户不点，下次启动仍显示该页。
- .denied：系统不会再弹授权框。页面必须把「去系统设置」作为主操作；「重新检查授权」只能刷新状态，必须说明「若仍为未授权，请到系统设置开启」。
- .restricted：显示限制说明，提供「重新检查」；能否打开设置由系统能力决定，失败时给文案。
- .limited 且 0 张可见照片：显示受限空态，主按钮「管理可见照片」，点击调起系统 limited picker；返回后自动刷新并重新加载。
- .limited 且有照片：正常网格 + 顶部/底部受限横幅，提供「管理可见照片」入口。
- .authorized 且空库：普通空态 + 「导入照片」按钮，点击打开 PhotosPicker。
- 从设置或 limited picker 返回 App：scenePhase 变为 active 时自动刷新授权并重新加载，不要求用户猜按钮。

### 3.4 F1 验收场景

1. fresh install → .notDetermined → 允许 / 拒绝 / 限制访问三条分支都能进入正确页面。
2. 拒绝后杀掉重启 → denied 页出现「去系统设置」主按钮；点「重新检查授权」不会假装弹系统框。
3. 去系统设置授权后返回 App → 不点任何按钮，一次前台刷新后出现网格。
4. 限制访问且选中 0 张 → limited 空态，出现「管理可见照片」；选择若干张返回 → 网格出现且受限横幅可见。
5. 全量授权空库 → 空态出现「导入照片」按钮。
6. Dynamic Type XXXL / iPhone SE 尺寸 → 授权页两个按钮不被裁切；VoiceOver 可读；所有按钮有稳定 accessibilityIdentifier。

## 4. F2：滑动多选语义

### 4.1 当前生产路径

LibraryViewController.swift:794-806 把 rowBandHitProvider 接到 GridHitTester.rowBandHitTest(from:to:)。

GridHitTester.swift:278-307 的实现把 from/to 两个 y 都映射到 bandIndex，然后无条件取 bandSequence 并展开整行：

    guard let fromBand = map.bandIndex(atContentY: Double(from.y), clipTop: clipTop),
          let toBand = map.bandIndex(atContentY: Double(to.y), clipTop: clipTop) else { return [] }
    let sequence = map.bandSequence(from: fromBand, to: toBand)
    let expanded = map.items(forBandIndices: sequence)
    return expanded.map { IndexPath(item: $0.item, section: $0.section) }

无论水平同带、垂直跨带还是零长度，都返回整行。LibrarySelectionController.swift:277-307 的 beginTrail 又用 (press, press) 零长度查询；如果结果包含锚点，beginIDs 被替换成整行。因此长按起手第一帧就整行选中。

同带左滑时，rowBandHitTest 仍返回从左到右的升序整行，例如 [3,1,3,2,3,3,3,4]，而不是手指方向的反序。SlideSelectTrail 看到 3,1 是路径中更早的 id，会截断回 3,1 再重新追加整行，净结果仍是整行，无法取消 3,4/3,3。

### 4.2 现有测试锁定旧契约

- PhotoDeskTests/LibraryGridGeometryTests.swift:578-594 testRowBandHitTestHorizontalDragExactRow：横向拖动断言整行。
- 同文件 :629-640 testRowBandHitTestZeroLengthReturnsWholeBand：零长度断言整行。
- PhotoDeskUITests/RowBandSelectUITests.swift:657 testHorizontalPressDragSelectsWholeRow：横向按压拖动整行。
- PhotoDeskCore/Tests/PhotoDeskCoreTests/RowBandTrailTests.swift:80-101：第一次 consume 行带就断言选中 3 格，回滑整行撤销。
- PhotoDeskCore/Tests/PhotoDeskCoreTests/SelectionGestureMachineTests.swift:106-113：已处于多选时断言只产生 .beginTrail。

这些用例是旧语义的证据，T06 必须重写或删除，不能保留为「兼容旧行为」。

### 4.3 本轮唯一真值

| 手势段 | 命中单元 | 顺序 |
|---|---|---|
| 长按起手 | 只选锚点 cell | 单个 |
| 同一行内横向拖动（左/右） | 手指线段扫过的 cell | 按手指方向；反向即反序 |
| 跨行且纵向占优、向下 | 新进入的行带整行（含当前行需补齐的 cell；不含已访问行重复项） | 行带向下顺序；行内列升序 |
| 跨行且纵向占优、向上 | 回退到目的行最后一个已访问 cell | 反向出栈，目的行保持 |
| 跨行但横向占优的斜拖 | 线段扫过的 cell | 按线段 tEnter 排序 |
| 回滑 | 由 SlideSelectTrail 路径栈按访问顺序出栈 | 回滑到哪个 id，就取消它之后访问的 cell |
| 选择按钮进入后直接拖 | 与长按进入相同，不需要再次长按 | 同左 |

关键不变量：垂直行模式不能把「已访问的起始行整行」重新喂给 SlideSelectTrail。路径栈是单调的；重喂起始行会截断回左侧 cell，导致当前行只选中一部分。T04/T05 必须把「当前行补齐」和「新行展开」分开处理。

## 5. F3：「选择」按钮无法滑动选择

### 5.1 根因链

1. 点 Library-Select → toggleSelectionMode() → enterSelectionMode(selecting: nil)（LibraryViewController.swift:838-860），isSelecting == true，但没有 anchor。
2. 不按长按，直接从 cell 横向拖动：SelectionGestureMachine 从 .pressing 进入 .dragging。
3. SelectionGestureMachine.swift:178-187 只在不处于多选时发 .enterSelection；已多选时只发 .beginTrail。
4. LibrarySelectionController.swift:273-285 只在 .enterSelection 里设置 trailAnchorID；.beginTrail 的 guard let anchor = trailAnchorID 失败，直接 break。触摸被消费、滚动被禁用、轨迹没有建立，所以滑不动。
5. 长按路径会先发 .enterSelection，掩盖了这个缺陷。

### 5.2 修复方向

把 anchor 放进 .beginTrail 载荷：

    case beginTrail(anchorID: String)

两条路径都发：

- holdElapsed：[haptic, .enterSelection(anchorID:), .beginTrail(anchorID:)]
- pressing 横向锁定：未在多选时先 .enterSelection(anchorID:)，然后始终 .beginTrail(anchorID:)

控制器收到 .beginTrail(anchorID:) 后直接设置 trailAnchorID = anchorID，并只 consume [anchorID]。不要从 .enterSelection 间接取 anchor；不要重复触发 onSelectionEntered 或重置 SelectionState。

## 6. 与旧结论的冲突声明

本轮以 docs/47 与 docs/48 为准，以下旧结论作废：

1. docs/42 §1.2「横向拖过一行 → 该行整行选中」作废；新语义为 cell 级。
2. docs/42 §1.2「零长度 = 所在整行」作废；新语义为零长度只选锚点。
3. docs/42 §1.2「斜向拖 = 行带序列全部整行」需按方向细分：纵向占优才整行；横向占优走 cell 线段。
4. LibraryGridGeometryTests 的横向整行/零长度整行断言、RowBandSelectUITests.testHorizontalPressDragSelectsWholeRow、RowBandTrailTests 首帧整行断言，均为旧契约，T06 必须重写或删除。
5. M19 的「右侧下滑整行」仍保留，但只作为纵向跨行行为，不是所有行带命中的默认行为。

## 7. 风险与未决

1. iOS 不允许 denied 后再次弹系统授权框；产品文案必须说「去系统设置」，不能说「重新授权」。
2. .limited 零照片与全量授权空库必须区分，否则用户会以为照片丢了。
3. 选择按钮后的直接拖动与纵向滚动存在手势竞争：横向锁定才进入选择，纵向仍让位滚动。
4. 当前 Windows 无 Xcode，F1/F2/F3 的最终确认必须在 GitHub Actions（Xcode 16.4；MINOS 16.0，模拟器 runtime 以 workflow env 为准）+ 真机完成；静态审查不能冒充运行结果。
5. PhotosPicker 导入需要写权限；denied 下只能引导去设置，不能假装能导入。
6. 行模式与 cell 模式切换时，任何「重喂已访问行」的实现都会破坏 SlideSelectTrail 的单调路径；T04/T05 必须用测试锁死。

## 8. 审查结论

三条问题都能在当前源码中定位到明确根因：

- F1 是授权状态模型 + 空态分支缺失，不是单纯「iOS 不再弹窗」；
- F2 是命中层把行带当成唯一单元，导致起手、横向、回滑全部过粗；
- F3 是 .beginTrail 缺少 anchor 载荷，导致选择按钮路径没有轨迹事务。
