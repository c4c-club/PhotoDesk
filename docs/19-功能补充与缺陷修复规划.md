### 0.3 修复原则（执行 Agent 不得删减）

1. 用户原文 6 条多选硬约束**逐字落地**，每条对应至少一条自动化测试；不得用 M12 的「矩形相交 + 基线每帧重算」冒充「经过即切换 + 滑回恢复快照」。

3. **一条根因一个 commit**；主路径的修改、测试、`git push`、CI 核对、截图逐张查看、IPA SHA256 核对必须由主 Agent 亲自完成。
4. **同一时刻最多 1 个子智能体**；确需只读审计必须串行「启动 → 等待其最终报告 → 吸收 → 再决定是否启动下一个」，严禁嵌套（子智能体不得再建子智能体），累计不超过 4 个，本轮建议 0–1 个。

## 3 逐项根因与修复方案

> 统一模板：**现象 → 根因 → 必须做到 → 先写失败测试 → 不变量 → 验收**。

### 3.1 P1 / R-M13-01：捏合缩小放大必崩溃

**现象**：用户真机在查看器里捏合缩小再放大必崩；M12 已加 `ViewerGesturePolicy` 与 `isFinite` 护栏仍复现。

**根因（按优先级）**：
1. 缩放事务活跃期（`isZooming || zoomScale > 1.01 || secondsSinceZoomActivity < DSMotion.zoomActivityGrace`）内，`configure` / `layoutSubviews` / `layoutImageContent()` / `updateCenteringInset()` / `scrollViewDidZoom` 仍可写 `zoomContentView.frame`、`scrollView.contentSize`、`contentInset`；UIScrollView 在 pinch 事务中收到几何突变易进入不一致状态。
2. `performStaged` 的 `performBatchUpdates` + `deleteItems` 与 `scrollViewDidZoom` 可能同帧；`allowsRemovalTransaction` 只在入口 guard，事务排队语义缺失。
3. `viewForZooming(in:)` 在 `contentSize` 或 `zoomContentView.frame` 为零时返回 nil，未记录原因，真机 `.ips` 里若出现 `CALayer position contains NaN` / `SWIFT TASK CONTINUATION MISUSE` 无法定位。
4. Release 无关键面包屑；CI 合成 pinch 打在 `ViewerRoot` 未命中 cell 内 `UIScrollView`，`app.state` / DEBUG 横幅是假绿。

**必须做到**：
- 引入显式**缩放事务状态机**：`ZoomTransactionState = idle | active | settling`。进入 pinch / `zoomScale != 1` / double-tap 动画即 `active`；`active` 期间 `layoutImageContent()` 与 `updateCenteringInset()` **只记录 pending 几何，不写 UIKit 属性**；`scrollViewDidZoom` 只刷新时间戳 + 日志 + `onZoomChanged`，不改 `contentInset`（或改为在 `settling` 单一提交点写）。
- `settling` 用一次 `CATransaction` / `layoutIfNeeded` 批量提交 pending 的 `frame` / `contentSize` / `contentInset`，提交前校验全部有限且 > 0；任一非有限值丢弃本次提交并写 `ViewerTrace`。
- 删除 / 隐藏事务与缩放事务互斥：`allowsRemovalTransaction == false` 时把动作**排队**到 `pendingRemovalActions`，待 `idle` 后串行执行；不得在 pinch 中 `performBatchUpdates`，不得用 `cancel()` 手势掩盖。
- `viewForZooming` 返回 nil 时写一条含 `contentSize` / `zoomContentView.frame` / `imageView.frame` / `zoomScale` 的 `ViewerTrace` 面包屑。
- **Release 可观测**：`ViewerTrace` / `AppCrashLogger` 在 Release 也写 `zoom=`、`img=`、`appear`、`pendingDeleteCount`、`frame/contentSize` 非有限值；只写本地文件、零上传、不含用户照片像素。
- 边界：本项**不改** `ViewerViewController.setupPanGesture()` 的上滑 pan 语义（那是查看器上滑收藏 / 删除，与本轮网格滑选无关）；用户要求的 `cancelsTouchesInView = false` 只作用于 §3.3 网格新加的 `slideSelectPan`，避免误改 viewer 引入新崩。

**先写失败测试**：
- UI：构造命中 `ZoomableImageCell` 内层 `UIScrollView` 的合成 pinch（坐标取 cell 的 `scrollView` 实际 frame，不打 `ViewerRoot`）；30 次缩小→放大 + 10 次双击 + 旋转，断言 `pendingDeleteCount == 0`、`imageView.frame.width > 0`、像素非背景色、App 不崩溃、`viewer-trace.log` 无 `non-finite`。
- 单测：`ZoomGeometry` 增加「事务活跃期几何提交被合并为一次」「非有限 pending 被丢弃」用例（Core 纯逻辑）。
- 既有 `testPinchZoom20Times` / `testPinchDoesNotTriggerRemoval` / `testPinchKeepsCollectionViewScrollEnabled` 保留且不得弱化。

**不变量**：`zoomScale.isFinite`；`zoomContentView.frame` 与 `contentSize` 的 width/height 恒 > 0；`contentInset` 由未变换 bounds 计算且不双倍；缩放事务与删除事务不同帧；Release 有崩溃前 5 条面包屑。

**验收**：CI 该组全绿 + 真机取证 5 项回传后由用户确认；Agent 侧写「自动化零崩溃 / 真机待验」。

### 3.2 P2 / R-M13-02：上次浏览位置记不准、打开软件不能保持

**现象**：冷启动后位置漂移，不能直接停在上次浏览处。

**根因**：保存取 `indexPathsForVisibleItems.sorted().first`（首可见 cell，不是用户注视的视觉锚点）；恢复用 `.centeredVertically` 把该 cell 强行居中（每次重启向上漂移）；`finishPositionRestore()` 在 `applyRestore` 后立刻解除回写禁令，恢复期中间态被 `scrollViewDidScroll` / 0.3s Timer / 减速结束写回覆盖；`LibraryRootView` 按 `viewState` switch 可能重建 `LibraryContainer` → `makeUIViewController` 新建 controller；`saveViewerAssetID` / `loadViewerAssetID` 零调用点。

**必须做到**：
- `LibraryPosition` 升到 **v3**：新增 `anchorAssetID`、`anchorVisualY`（= 锚点 cell 的 `layoutAttributes.frame.minY - contentOffset.y`，即视口内 y）、`anchorContentOffsetY`、`schemaVersion = 3`；v1/v2 解码补默认，保留 `assetID / sectionID / itemIndexInSection / offsetRatio` 仅作 fallback。
- 保存：以**视觉锚点 cell**为准（取 `contentOffset.y` 对应的可见 cell 中 `frame.minY <= contentOffset.y + 安全区` 的最近者，或用户最后交互的 cell），写 `anchorAssetID + anchorVisualY + anchorContentOffsetY`；不再用 `sorted().first` 单独决定。
- 恢复：按 `anchorAssetID` 在新快照里找到新 `layoutAttributes`，计算 `targetOffsetY = newAttributes.frame.minY - anchorVisualY`，用 `setContentOffset(_:animated:false)` **精确像素**落地；**禁止** `.centeredVertically` 作为主路径；assetID 找不到才依次退到 `sectionID + itemIndexInSection`、再退到 `offsetRatio`（每级 fallback 写一条 `ViewerTrace` 风格的 `PositionTrace`）。
- 恢复完成条件改为：`bounds > 0` + `numberOfSections > 0` + 快照 drain 完成 + 精确 offset 已应用 + 一次 `layoutIfNeeded` 后**才**解除 `isPositionRestoreInFlight`；解除前所有 `savePositionNow` 调用直接 return（含 0.3s Timer / `didEndDecelerating` / `didEndDragging` / `viewWillDisappear` / `scenePhase`）。遮罩 `restoreMaskView` 只作视觉防跳，**不作为正确性依据**。
- 宿主复用：`LibraryContainer` 的 controller 必须跨 `viewState` 切换复用（提升 controller / positionStore 到 `AppContainer` 注入，或用稳定 `.id` + `updateUIViewController` 只 `wire` 不重建）；禁止用 `DispatchQueue.main.asyncAfter` 延迟重建掩盖。
- 消除悬空 API：推荐把 `positionStore` 注入 `AppContainer.makeViewerViewModel(context:)`，打开 viewer 时 `saveViewerAssetID`、恢复上下文时 `loadViewerAssetID`；若不接线则删除这两个方法及注释，二选一但必须消除悬空。
- 保留 M12 的锚点窗口首屏（`LibraryViewModel.fetchFirstBatch` 以 `anchorIndex - batchSize/2` 为中心）、分批 500、`LibraryQuery` FNV-1a 稳定 key、Diffable 布局门禁（0-section 不 apply、apply completion 内不嵌套 apply、前插 section 补偿）——**不得因抬 iOS16 删除**。

**先写失败测试**：
- `PhotoDeskTests/LibraryPositionRestoreTests.swift` 增加：`testSaveUsesVisualAnchorNotFirstVisibleCell`、`testRestoreUsesPixelOffsetNotCentered`、`testNoWritebackDuringRestoreInFlight`、`testHostReuseAcrossViewStateDoesNotResetOffset`、`testV3DecodeV2Fallback`、`testRotationKeepsSameVisualAnchor`（既有 5 条保留）。
- UI：`testPositionRestoredAfterRelaunch` / `testColdLaunchRestoresDeepMonthAnchorWithoutVisibleJump` / `testRotationKeepsAnchorWithinOneRow` 改为断言「同一 assetID 的视口 y 偏差 ≤ 1 行且像素 offset 差 ≤ 1pt」；不得删 `docs/15 §3.2` 六条 🟨 中的任何断言。

**不变量**：`queryKey` 跨进程稳定（禁 `hashValue`）；恢复期零回写；`scrollToItem(.centeredVertically)` 不在精确恢复主路径；冷启动首屏一次到位无可见跳变；筛选态 / 旋转 / 查看器返回后锚点不漂移。

**验收**：单测 + UI 逐项转绿；`docs/18 §2.4` 的位置族 6 条在 iOS16 CI 上重新分类（真实缺陷必须修，平台限制才标 ⚠️）。

### 3.3 P3 / R-M13-03：单指滑动连续多选（用户 6 条硬约束，逐字落地）

**现象**：M12 长按矩形框选动作不优雅；用户要求改为 UIKit + `UICollectionView` 类 iPhone 相册的单指滑选，最低 iOS 16。

**根因**：当前是 `UILongPressGestureRecognizer` + `GridHitRegion` 二维相交 + `mergedSelection` 每帧重算，语义是「框到即选、基线重算」；用户要的是「手指经过即切换、反向滑回恢复滑动前原状」，两者状态模型不同，必须整条替换而非叠加。

#### 用户原文硬约束（执行 Agent 不得删减、不得改写）

1. **手势配置**：添加一个 `UIPanGestureRecognizer`，设置 `maximumNumberOfTouches = 1`，并设置 `cancelsTouchesInView = false`，确保不会吞掉轻点事件。手势的 delegate 必须实现 `gestureRecognizerShouldBegin` 和 `gestureRecognizer(_:shouldRecognizeSimultaneouslyWith:)`，以便在非选择模式下让 CollectionView 正常滚动。
2. **方向锁定（关键）**：在 `.began` 状态先记录起始点，在 `.changed` 状态比较累计位移。只有水平位移绝对值大于垂直位移绝对值时，才将 `isDragSelecting` 置为 `true` 并开始执行选择逻辑；如果垂直位移占优，手势应让位给 CollectionView 的纵向滚动，`isDragSelecting` 保持 `false`，**直到手势结束都不再激活选择**。不要在 `.began` 就贸然激活，否则纵向滚动会被打断。
3. **状态快照（往返恢复关键）**：在 `isDragSelecting` 首次变为 `true` 的那一刻，对当前 CollectionView 的选中状态做一次快照。用一个 `[IndexPath: Bool]` 字典（或 `Set<IndexPath>` 记录「开始时已选中」的集合）保存每个 cell 在滑动开始前的原始选中状态。后续手指经过某个 cell 时：如果该 cell 在快照中，恢复为快照中的值；如果该 cell 不在快照中（滑动开始时未选中），则设为 `true`。这样就能天然支持「反向滑回时取消选中」，且不会错误地取消掉滑动开始前就已经选中的 cell。
4. **indexPath 追踪与去重**：在 `.changed` 中通过 `collectionView.indexPathForItem(at: location)` 获取手指下的 indexPath。维护一个 `lastProcessedIndexPath`，只有当前 indexPath 与上一次不同时才执行状态更新，避免同一 cell 被重复处理导致状态闪烁。
5. **滚动协同**：`isDragSelecting == true` 期间，将 `collectionView.isScrollEnabled` 设为 `false`；手势进入 `.ended` / `.cancelled` 后立即恢复为 `true`，并清空快照和 `isDragSelecting` 标记。
6. **边缘自动滚动（必须实现）**：当手指的 y 坐标进入 CollectionView 可见区域的顶部或底部缓冲区（建议 60pt）时，启动一个 `CADisplayLink`，根据手指距边缘的距离计算滚动速度，逐帧修改 `contentOffset`，使屏幕外的 cell 也能被滑过选中。手指离开缓冲区或手势结束时，销毁 `CADisplayLink`。

## 4 目标架构与 Core 下沉

### 4.1 `SlideSelectPolicy` / `SlideSelectConfig`（Foundation-only）

- `SlideSelectConfig`：`edgeBuffer = 60`、`minStep`、`maxStep`、`directionLockEpsilon`（方向锁相等时判垂直）、`activationMinTranslation`（可选，防止 1pt 抖动误激活，但**不得**改变 `abs(dx) > abs(dy)` 判定语义）、`contentInsetTopKey` 等全部收口；禁止在 VC 里散落数字。
- `SlideSelectPolicy` 纯函数：
  - `shouldActivate(dx: Double, dy: Double, wasLocked: Bool) -> SlideSelectActivation`（`.horizontal / .verticalLocked / .none`）
  - `resolvedSelection(originallySelected: Set<SlideSelectCell>, visited: [SlideSelectCell]) -> [SlideSelectCell: Bool]`（快照恢复语义）
  - `edgeVelocity(fingerY: Double, top: Double, bottom: Double, buffer: Double, minStep: Double, maxStep: Double) -> Double`（带符号，0 表示不在缓冲区）
  - `clampedOffset(current: Double, delta: Double, min: Double, max: Double) -> Double`
- 全部只用 `Foundation`；输入用 `Double` / 自定义 `struct`，**禁止** `CGPoint` / `CGRect` / `IndexPath`（`IndexPath` 虽属 Foundation，仍统一用值类型以清晰适配）。
- 新增 `PhotoDeskCoreTests/SlideSelectPolicyTests.swift`，覆盖：水平激活、垂直锁定不可复活、相等位移判垂直、快照内恢复、快照外置 true、回拖顺序、边缘上/下速度单调性、离开缓冲区归零、offset 钳制、重复 visited 去重。

### 4.2 App 侧适配层

`SlideSelectGestureController`（`@MainActor`）持有：`dragStartPoint`、`isDragSelecting`、`verticalScrollLocked`、`originalSelection: [IndexPath: Bool]`、`lastProcessedIndexPath`、`autoScrollLink`、`lastFingerLocation`；把 Core 纯函数结果映射到 `UICollectionView` / `SelectionState`。`LibraryViewController` 只负责装配与回调，不重写判定逻辑。

### 4.3 位置锚点模型 v3

`LibraryPositionStore` 增 v3 编解码；`LibraryViewController` 的 `savePositionNow` / `restorePositionIfNeeded` / `applyRestore` / `applyRatioRestore` / `finishPositionRestore` 按 §3.2 重写；新增 `PositionTrace` 本地日志（零上传）。

### 4.4 缩放事务状态机

`ZoomableImageCell` 增 `ZoomTransactionState` + `pendingGeometry`；`ViewerGesturePolicy` 增 `allowsGeometryCommit(cell:)`；`ViewerViewController.performStaged` 增 `pendingRemovalActions` 队列。Core 侧 `ZoomGeometry` 增「合并提交 / 非有限丢弃」纯函数与单测。

```
        originalSelection = snapshotOfCurrentSelection()   // [IndexPath: Bool]
        collectionView.isScrollEnabled = false
        startEdgeAutoScrollIfNeeded()
    }
}

let loc = pan.location(in: collectionView)
guard let ip = collectionView.indexPathForItem(at: loc) else { return }
guard ip != lastProcessedIndexPath else { return }          // 去重，防闪烁
lastProcessedIndexPath = ip
let target = originalSelection[ip] ?? true                 // 快照内恢复，快照外置 true
applySelection(ip, to: target)                            // selectionState + selectItem/deselectItem + 徽标 + 计数
updateEdgeAutoScroll(fingerY: loc.y)                      // 进/出 60pt 缓冲区 -> 启停 CADisplayLink

// displayLink tick
let v = SlideSelectPolicy.edgeVelocity(fingerY: lastFingerY, top: ..., bottom: ...,
                                        buffer: SlideSelectConfig.edgeBuffer,
                                        minStep: ..., maxStep: ...)
if v == 0 { invalidateAutoScroll(); return }
let newY = SlideSelectPolicy.clampedOffset(current: contentOffset.y, delta: v, min: ..., max: ...)
collectionView.setContentOffset(CGPoint(x: contentOffset.x, y: newY), animated: false)
reprocessIndexPathUnderFinger()                            // 屏幕外 cell 也能被滑过选中

// .ended / .cancelled / .failed
finishSlideSelection()
  collectionView.isScrollEnabled = true
  originalSelection.removeAll()
  isDragSelecting = false
  verticalScrollLocked = false
  lastProcessedIndexPath = nil
  autoScrollLink?.invalidate(); autoScrollLink = nil
```
