S01 捏合缩放必卡死闪退
- 现象：查看器双指放大/缩小几次就卡住闪退；双击也可能崩。
- 根因：ZoomableImageCell 在 cell 未布局时把 imageView.frame 设为 zero；layoutSubviews / scrollViewDidZoom
  在缩放过程中直接改被缩放视图的 frame；双击在 UIView.animate 内先 zoom(to:) 再 setZoomScale；
  没有 NaN/零尺寸守卫。
- 必须做到：
  1) 新增 PhotoDeskCore/ZoomGeometry.swift（纯 Double）：aspectFitSize / centeredInset / clampedZoomRect /
     sanitizedScale，全部对 0/负/NaN/∞ 返回安全值，≥12 条单测；
  2) 重写 ZoomableImageCell：scrollView → zoomContentView → imageView；viewForZooming 返回 zoomContentView；
     只有 bounds > 0 且 image != nil 时才允许缩放；缩放中绝不改 zoomContentView.frame；
     scrollViewDidZoom 只更新 contentInset；双击只调用一次 scrollView.zoom(to:animated:)；
  3) image == nil 时 scrollView.isUserInteractionEnabled = false；
  4) prepareForReuse 取消加载、清图、resetZoom（先判 bounds）；
  5) DEBUG 横幅显示 zoom=<有限数字>，UI 测试断言不含 nan/inf。
- 验收：StabilityUITests.testPinchZoom20Times 全绿（20 次放大/缩小/双击，app 始终 runningForeground）；
  ZoomGeometryTests ≥12 全绿。

S02 快速滑动必卡死闪退
- 现象：查看器快速左右连续滑十几张，卡住后闪退（常为 jetsam）。
- 根因：ViewerViewController.prefetchAround 每次翻页以全屏像素 startCachingImages 且从不 stopCachingImages；
  ImagePipeline.fullImage 用 PHImageManagerMaximumSize + .opportunistic + withCheckedContinuation，
  无取消、无单次 resume 保护；FilmStripView.highlight 每次 reloadData。
- 必须做到：
  1) 新增 ResumeOnce<T>（NSLock + didResume），所有 continuation 必须经它 resume；
  2) ImagePipeline 改为可注入 ImageRequesting（生产 PHCachingImageManager，测试 Fake）；
     fullImage 用 .highQualityFormat（单次回调）+ .fast + targetSize = min(screenPixel*1.25, 2048)，
     保存 PHImageRequestID，cancel 可取消；
  3) prefetch 维护 prefetchedIDs，差量 stop/start，窗口 ≤ 7 张，尺寸 ≤ 2048；
  4) 新增 fullImageCache（countLimit 6 / costLimit 60MB）与 cancelAll()；
  5) FilmStripView.highlight 不再 reloadData，只刷新旧/新两个 cell 的 isCurrent；
  6) ViewerViewController.prefetchAround 只在页码变化时调用，加 100ms 防抖，items 为空/越界直接 return；
  7) viewDidDisappear 调 pipeline.cancelAll()。
- 验收：ImagePipelineResumeTests 全绿（Fake 连续回调两次/取消后回调，不崩且只 resume 一次）；
  StabilityUITests.testFastSwipe50Times 全绿；5,000 张 100 次滑动内存峰值 < 250MB。

S03 选择年份后卡死闪退
- 现象：筛选面板选年份并应用，或点右侧年份刻度，卡住后闪退；持久化筛选后重启也可能崩。
- 根因：LibraryViewModel.setFilter 在主线程同步全量过滤/分组；LibraryViewController.applySnapshot 在
  dataSource.apply 未完成时立刻 restorePositionIfNeeded()/syncIndexBar()，并按新 section index
  scrollToItem；索引条 entries 先于快照更新；后台索引与用户筛选的 apply 交错；索引续拉可能产生重复 id。
- 必须做到：
  1) setFilter 改为后台 Task.detached + filterGeneration 代际令牌，主线程只赋值与推快照；
  2) LibraryViewController 增加 isApplyingSnapshot + pendingSnapshot + drain()：同一时间只允许一个
     dataSource.apply；新快照覆盖 pending；筛选/年份变化一律 animatingDifferences:false；
  3) currentSections/currentItemsBySection、syncIndexBar、restorePositionIfNeeded 全部移到 apply completion；
  4) scrollToSection / restore 前校验 collectionView.numberOfSections 与 numberOfItems(inSection:)，
     用 dataSource.indexPath(for:) 拿有效 index path；
  5) rebuildSections 前对 filteredItems 按 id 去重（保序）；runIndexCompletion 追加后去重；
     DEBUG 下断言 id 唯一，Release 去重后继续；
  6) LibraryFilterSheet.previewCount 改 @State + 200ms debounce，不在 body 里全量扫描；
  7) isApplyingSnapshot 时 indexBar.isUserInteractionEnabled = false，完成后恢复。
- 验收：StabilityUITests.testFilterYearsRepeatedly（2026→2024→2020 循环 5 次）全绿；
  testFilterPersistedAfterRelaunch 全绿；5,470 张筛选 < 500ms，主线程无 >100ms 阻塞。

S04 无法记住上次整理到的位置
- 现象：滚到某月/某张，切 Tab 或杀进程重启，回到顶部或错误位置。
- 根因：didRestorePosition 在 positionStore.load 之前就置 true；首快照只有 500 张，保存的 asset 找不到时
  用部分 contentSize 算 ratio；保存只靠滚动停止 0.5s + viewWillDisappear；queryKey 读的是保存时的值；
  sectionID 存了但恢复时完全没用；每次恢复都弹底部 Toast。
- 必须做到：
  1) LibraryPosition v2：assetID/sectionID/itemIndexInSection/offsetRatio/savedAt/schemaVersion；
     LibraryPositionStore 用 library.lastPosition.v2.<queryKey>，兼容 v1 读取（失败不崩）；
  2) LibraryViewController 捕获 currentSnapshotQueryKey，保存时用它，不用 viewModel.query.key；
  3) 统一 savePositionNow(reason:)：scrollViewDidEndDecelerating、scrollViewDidEndDragging(willDecelerate:false)、
     viewWillDisappear、UIApplication.willResignActiveNotification、scenePhase .background、
     scrollToSection 完成后、0.3s 滚动停止兜底；
  4) LibraryViewModel 增加 isIndexComplete；恢复策略：assetID → sectionID + itemIndexInSection → offsetRatio；
     索引未完成且 assetID 找不到时保持 pending，等下一批；不要提前置 didRestorePosition；
  5) 恢复成功不弹 Toast，只在 DEBUG 横幅显示 restore=ok section=<id>；
  6) 设置页「清除位置记忆」保留并清空 v2。
- 验收：LibraryPositionStoreTests 全绿；StabilityUITests.testPositionRestoredAfterRelaunch 全绿
  （滚到 2024-05 → terminate → launch → header 含「2024年5月」）；testPositionSavedOnTabSwitch 全绿。

  2) override hitTest：isHidden 或 alpha<=0.01 返回 nil；只允许 undoButton 命中，其余返回 nil；
  3) LibraryViewController：batchToast 不再常驻；删除恢复 Toast；多选时 toast 上移到 selectionBar 之上

  4) 首次捏合提示改为顶部提示/2 秒自动消失，不占底部；
  5) Viewer/SessionReview 的 Toast 同样走新 DSToast。
- 验收：StabilityUITests.testToastDoesNotBlockGrid 全绿（启动等 5s，点最后一个可见 cell 能打开查看器；
  DSToast 不存在或 isHittable=false）；截图 s05-toast.png 底部无空胶囊。

S11 通过时间刻度跳转后，重启应用无法记住位置

  1) scrollToSection 完成后同步保存 LibraryPosition（assetID=目标 section item 0，sectionID，itemIndex=0），

- 验收：StabilityUITests.testMonthJumpPersistsAfterRelaunch 全绿（跳 2024-05 → terminate → launch →
  header 2024年5月）。

S12 删除、隐藏图片必闪退（先跳第一张，再闪退）
- 现象：查看器下滑删除/隐藏任意一张，画面先跳到第一张后闪退；多选批量删除也可能崩。
- 根因：ViewerViewModel.stage 先 items.remove，再等 0.35s flyOut 完成才 performBatchUpdates deleteItems；
  期间 collectionView 仍按旧 index 取新数组；performBatchUpdates 在布局已更新后再删 → 数量不一致；
  currentIndex=plan.nextIndex ?? 0 可能跳 0；无串行化；cellForItemAt 无边界检查。
- 必须做到：
  1) ViewerViewModel 拆分 planRemoval（只入队+算 plan，不改 items/currentIndex）/
     commitRemoval（在 batch block 内改 items + 返回 nextIndex/shouldClose）/ rollbackRemoval；
  2) ViewerViewController：isRemovalInFlight 串行；取 cell snapshotView 加到 view 上做飞出动画；
     **立即**在同一 runloop 执行 performBatchUpdates { commitRemoval + deleteItems }；
     completion 里 scrollTo(next)/dismiss/刷新 filmstrip/prefetch；不要等 0.35s；
  3) 删除 flyOut 真实 cell 的逻辑；snapshot 动画不阻塞数据源；
  4) cellForItemAt/willDisplay/prefetchItemsAt 全部 guard 边界；numberOfItemsInSection 返回 max(0, count)；
  5) prefetchAround 用 items[index..<min(index+4, count)]，空数组/越界 return；
  6) 多选批量删除仍走 ReviewSession + SessionReviewView，不直接操作网格；网格通过 diffable 快照移除；
  7) 新增 ViewerRemovalPlannerTests ≥8 条（首/中/末/唯一/连续两次/plan 不改数组/commit 后 index/回滚）。
- 验收：StabilityUITests.testDeleteFirstMiddleLastNoCrash、testHideFirstMiddleLastNoCrash、
  testDelete20InARowNoCrash 全绿；每次 app 始终 runningForeground；横幅 id 为预期邻居；计数正确。
