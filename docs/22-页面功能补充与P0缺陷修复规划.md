## 0. 结论摘要

本轮不是再复述 M13 的“28 条红测试已转绿”，而是以用户 2026-11-08 的四条实测反馈为唯一入口，重新审查源码、崩溃栈、CI 日志和真机行为。结论如下：

1. **捏合崩溃的根因没有被上一轮彻底移除。** 25 份 `.ips` 的崩溃线程都是 `ZoomableImageCell.viewForZooming(in:)` 内部的字符串插值触发 `UIScrollView._getDelegateZoomView` → `_zoomScaleFromPresentationLayer` 重入，最终栈溢出（`EXC_BAD_ACCESS / SIGSEGV / KERN_PROTECTION_FAILURE`）。上一轮提交 `36c0e7a` 只把 `scrollView.zoomScale` 换成了 `zoomContentView.transform.a`，同一行仍然插值 `scrollView.contentSize`、`zoomContentView.frame`、`imageView.frame`，因此仍有重入路径。**修复方式必须是“该委托方法零 UIKit 属性读取、零日志插值”，而不是再加一个状态机补丁。**
2. **位置记忆是“多写入源 + 恢复触发点单一 + 首帧 bounds 竞态”，不是保存开关问题。** `didRestorePosition` 在真正应用 offset 之前就被置为 `true`，之后 `viewDidLayoutSubviews` 不会重试；滚动停止定时器、`willResignActive`、`scenePhase`、`viewWillDisappear` 没有统一代际令牌，旧定时器可以在恢复开始后把顶部位置写回。表现就是“有时记得住、有时记不住”。
3. **滑选当前是“手指经过哪个单格就只选哪个单格”，不是官方相册的整行区间语义。** 因此沿右列向下滑时左列不会被选中；同时 `initiallySelectedIndexPaths` 读的是 `collectionView.indexPathsForSelectedItems`，而全选/月份全选只改内部 `selectionState`、没有同步 `selectItem`，快照经常为空；每帧还重算整个访问序列，长距离拖动是 O(n²)，手感必然差。
4. **页面层存在一批“静默失败/无空态/无重试”的缺口**（相簿无封面与错误提示、搜索无历史与空态、查看器加载失败仍黑屏、设置页版本号硬编码 `1.0.0 (1)`、月份索引条结束拖动后清空高亮等）。这些放在 P0 之后逐页处理，但不得为了凑数引入新风险。

本轮完成的判定标准只有一条：**用户能在真机上按四条复现步骤连续操作而不崩溃、位置每次都能落回、右列下滑能选中整行、滑选手感达到官方相册的可接受水平**；CI 绿只是必要条件，不是充分条件。

## 3. P0-1：捏合缩小/放大必崩溃

### 3.1 用户现象

- 进入查看器，双指捏合放大或缩小，**必现崩溃**；不是偶发。
- 崩溃可能发生在放大过程中、缩小回 1× 时、或双击缩放后继续捏合时。
- 用户无法提供稳定录屏，但系统“分析数据”里应有 `.ips`。

### 3.2 现有证据

`.m13-notes/crash5/DiagnosticReports/` 下 25 份 `.ips`（2026-11-07 06:34–07:00）全部同型：

```
EXC_BAD_ACCESS / SIGSEGV / KERN_PROTECTION_FAILURE at 0x...（栈地址）
main thread:
  libswiftCore ... swift_conformsToProtocolMaybeInstantiateSuperclasses
  libswiftCore ... DefaultStringInterpolation.appendInterpolation<A>(_:)
  PhotoDesk.debug.dylib ZoomableImageCell.viewForZooming(in:)
  UIKitCore -[UIScrollView _getDelegateZoomView]
  UIKitCore -[UIScrollView _zoomScaleFromPresentationLayer:]
  PhotoDesk.debug.dylib ZoomableImageCell.viewForZooming(in:)
  ...（同一组帧重复数百次，最终栈溢出）
```

这是**无限递归**，不是普通的“几何 NaN”或“删除事务同帧”问题。

当前源码对应位置：`PhotoDesk/Features/Viewer/ZoomableImageCell.swift:510-523`

```swift
func viewForZooming(in scrollView: UIScrollView) -> UIView? {
    guard scrollView.contentSize.width > 0, scrollView.contentSize.height > 0,
          zoomContentView.frame.width > 0, zoomContentView.frame.height > 0 else {
        ViewerTrace.log("viewForZooming nil contentSize=\(scrollView.contentSize) zoomContentView=\(zoomContentView.frame) imageView=\(imageView.frame) zoomScale=\(zoomContentView.transform.a) state=\(zoomTransactionState)")
        return nil
    }
    return zoomContentView
}
```

即使 `36c0e7a` 已把 `scrollView.zoomScale` 换成 `transform.a`，这一行仍然在**委托回调内部**读取 `scrollView.contentSize`、`zoomContentView.frame`、`imageView.frame` 并做字符串插值。`UIScrollView` 在计算 `zoomScale` 时会调用 `_getDelegateZoomView` → `viewForZooming`；`viewForZooming` 里再读这些属性/做反射插值，就可能再次触发 `_zoomScaleFromPresentationLayer`，形成递归。

### 3.3 根因链（按重要性排序）

1. **委托方法内做 UIKit 属性读取与字符串插值**（直接根因，E1 已证）。
2. **`viewForZooming` 在内容尺寸为 0 时返回 nil**：捏合过程中如果 cell 被复用、图片被清空、`contentSize` 瞬时为 0，`UIScrollView` 会反复查询 zoom view；nil 会加剧内部状态不稳定。正确做法是“没有图时禁用缩放交互”，而不是在捏合中返回 nil。
3. **`scrollViewDidZoom` 每帧调用 `beginZoomTransaction()` 并重新调度 `Timer`**（`ZoomableImageCell.swift:530-545`、`453-469`）：Timer 强引用 cell，缩放期间反复创建/销毁；`commitPendingGeometry` 在缩放未结束时写 `zoomContentView.frame` / `scrollView.contentSize`（`395-451`），与 UIScrollView 内部 transform 打架。
4. **VC 在缩放回调里重入 collectionView**：`handleZoomCallback`（`ViewerViewController.swift:955-974`）→ `refreshDebugBanner`（`256-266`）→ `collectionView.cellForItem(at:)`；`logGeometryBreadcrumb`（`980-995`）还会读当前 cell 几何。该回调可能由 `cellForItemAt` 内的 `configure → resetZoom → setZoomScale` 触发，形成“数据源回调中再次访问数据源”的重入。
5. **`configure` / `prepareForReuse` 在 `scrollView.isZooming` 时调用 `resetZoom` / `setZoomScale`**（`173-186`、`231-248`、`286-294`）：cell 复用时的缩放状态没有先冻结，容易在 pinch 中途把 zoom view 的 frame 改成 0。
6. **上一轮的 `ZoomTransactionState` 是补丁而非根治**：它把“活跃期写几何”改成“活跃期只记 pending、settling 一次提交”，但提交仍然在缩放未结束时写 frame/contentSize；且 `viewForZooming` 仍保留日志，所以崩溃路径未被切断。

### 3.4 修复设计（以 Apple 标准 zoom 模式为基线）

**目标：`viewForZooming` 成为一个常量返回函数，方法体内不读任何 `UIScrollView` / `UIView` 属性、不写日志、不做字符串插值。**

#### 3.4.1 视图层级与状态

保持 `contentView → scrollView → zoomContentView → imageView`，但简化状态：

- `zoomContentView.translatesAutoresizingMaskIntoConstraints = true`（手动 frame）。
- `imageView` 四边约束到 `zoomContentView`，`contentMode = .scaleAspectFit`。
- `scrollView.minimumZoomScale = 1`、`maximumZoomScale = 5`、`bouncesZoom = true`。
- 新增两个**普通 Bool**（只在布局/配置路径写，不在 delegate 查询路径写）：
  - `private var hasValidZoomContent = false`
  - `private var isApplyingZoomLayout = false`
- `viewForZooming` 只返回 `zoomContentView`，不判断 `hasValidZoomContent`；没有图时通过 `scrollView.isUserInteractionEnabled = false` 和 `scrollView.pinchGestureRecognizer?.isEnabled = false` 禁止捏合。

#### 3.4.2 布局

```swift
override func layoutSubviews() {
    super.layoutSubviews()
    guard !isApplyingZoomLayout else { return }
    guard imageView.image != nil,
          scrollView.bounds.width > 0, scrollView.bounds.height > 0 else { return }
    if scrollView.zoomScale <= 1.001 {
        let fit = ZoomGeometry.aspectFitSize(...)   // Core 纯函数
        zoomContentView.frame = CGRect(origin: .zero, size: fit)
        scrollView.contentSize = fit
        hasValidZoomContent = fit.width > 0 && fit.height > 0
    }
    centerZoomContent()
}
```

`centerZoomContent()` 只在 `layoutSubviews` 与 `scrollViewDidEndZooming` 调用，使用未变换的 `zoomContentView.bounds` 计算 `contentInset`；**不在 `scrollViewDidZoom` 每帧写 `contentInset`**（若必须每帧居中，加 `isApplyingZoomLayout` 重入保护，且只写 `contentInset`，不写 frame/contentSize）。

#### 3.4.3 缩放回调

```swift
func viewForZooming(in scrollView: UIScrollView) -> UIView? {
    zoomContentView
}
```

- 该方法上方加注释：**禁止在此读取任何 scrollView / view 属性，禁止 ViewerTrace.log，禁止字符串插值**。
- `scrollViewWillBeginZooming` / `scrollViewDidZoom` / `scrollViewDidEndZooming` 只更新一个 `ZoomDiagnostics` 值类型（纯数字），由 VC 以 1Hz 或翻页时读取；**不回调 VC 的 `refreshDebugBanner` / `collectionView.cellForItem`**。
- 删除 `beginZoomTransaction`、`pendingGeometry`、`settleTimer`、`commitPendingGeometry`、`applyInsetOnlyAfterZoom`、`apply(commit:)` 这套事务状态机；保留 `ZoomGeometry` / `ZoomGeometryTransaction` 的纯函数用于数值钳制与测试，但不再在缩放活跃期写 UIKit 几何。
- `scrollViewDidZoom` 只做：`lastZoomActivity = CACurrentMediaTime()`；更新 `diagnostics.currentScale`（有限值时）；不写任何几何。
- `scrollViewDidEndZooming`：`centerZoomContent()`；`refreshInteraction()`；`diagnostics.zoomEndCount += 1`。

#### 3.4.4 配置与复用

- `configure(item:image:)`：
  1. `scrollView.delegate = nil`（临时摘除，避免 reset 触发回调）。
  2. `scrollView.isUserInteractionEnabled = false`。
  3. `imageView.image = image`。
  4. 若 `scrollView.bounds > 0` 且 `scrollView.isZooming == false`：`scrollView.setZoomScale(1, animated: false)`；否则只置 `needsResetZoomOnEnd = true`。
  5. `layoutImageContent()`（按 1× aspectFit 设 frame/contentSize）。
  6. `scrollView.delegate = self`；`refreshInteraction()`。
- `prepareForReuse()`：先 `scrollView.delegate = nil`，再 `cancelLoad()`、清图、`setZoomScale(1)`（仅在 bounds>0 且非 zooming），最后 `scrollView.delegate = self`。
- `resetZoom()`：若 `scrollView.isZooming`，置 `needsResetZoomOnEnd = true` 并 return；否则 `setZoomScale(1)` + `centerZoomContent()`。
- `scrollViewDidEndZooming` 若 `needsResetZoomOnEnd`，执行一次 reset。

#### 3.4.5 交互护栏

- `refreshInteraction()`：`image != nil && bounds > 0 && contentSize > 0 && !cloudBox.isHidden` 时启用 `scrollView.isUserInteractionEnabled` 与 `pinchGestureRecognizer?.isEnabled`。
- 双击：`handleDoubleTap` 只在 `!scrollView.isZooming` 时执行；`zoom(to:animated:)` 的 rect 由 `ZoomGeometry.clampedZoomRect` 钳制，且限制在 `zoomContentView.bounds` 内。
- 查看器 pan 的互斥仍按 `ViewerGesturePolicy`，但 `currentCellZoomState()` 改为读取 `ZoomDiagnostics`（纯值），不直接读 `scrollView.zoomScale`。

### 3.5 文件级改动

| 文件 | 改动 |
|---|---|
| `PhotoDesk/Features/Viewer/ZoomableImageCell.swift` | 删除缩放事务/定时器/日志插值；`viewForZooming` 改为常量返回；重写 `layoutSubviews`/`configure`/`prepareForReuse`/`resetZoom`/双击；新增 `ZoomDiagnostics` 值类型 |
| `PhotoDesk/Features/Viewer/ViewerViewController.swift` | 移除 `handleZoomCallback` 中的 `refreshDebugBanner`/`logGeometryBreadcrumb` 重入；改为翻页/定时读取 `ZoomDiagnostics`；`currentCellZoomState` 适配新值类型 |

### 3.6 测试与验收

**单元测试**

- `ZoomGeometryTests`：aspectFit 宽图/高图/正方形/1×1/零尺寸；`centeredInset` 不小于 0；`clampedZoomRect` 在边界内。
- `ViewerCellGeometryTests`：`viewForZooming` 返回同一 `zoomContentView`；连续调用 1,000 次不改变任何几何；`configure` 后 `contentSize == aspectFit`。
- `ViewerGestureGuardTests`：缩放活跃期 pan 被拒绝、删除动作入队；drain 门禁不变。

**UI 测试**

- `testPinchAfterPageChange`：捏合放大 → 翻到下一张 → 再捏合 → 返回上一张 → 再捏合。

**真机**

### 3.7 风险

- 去掉事务状态机后，缩放结束的居中 inset 可能短暂偏移；用 `scrollViewDidEndZooming` + `layoutSubviews` 两处 `centerZoomContent()` 收敛，UI 测试加“缩放后图像仍居中”的像素断言。
- 双击 `zoom(to:)` 在极小图/极大图上可能 rect 为空；`clampedZoomRect` 必须返回 nil 并早退，不能把空 rect 传给 UIScrollView。
- 若新构建仍出现 `.ips`，**不得**继续套用本方案；按新栈重新定位，优先检查 `viewForZooming` 是否又被加了日志。

## 4. P0-2：上次浏览位置记不准、概率性丢失

### 4.1 用户现象

- 退出 App 再打开，有时回到上次位置，有时回到顶部/别的月份。
- 不是“完全没记忆”，而是**概率事件**；说明存在时序竞态，而不是存储键写错。

### 4.2 现有实现的关键路径

| 环节 | 代码 | 问题 |

| 首批锚点窗口 | `LibraryViewModel.swift:311-317` | 用 `positionStore.load` 决定首批窗口；如果 `globalIndex` 失败，窗口从 0 开始，深月份锚点不在首批 |
| 保存 | `LibraryViewController.swift:1167-1190` | `visualAnchorCandidate()` 取“最接近 safeTop 的 cell”，可能是被粘性头遮住一半的 cell；保存时没有 `isApplyingSnapshot` 门禁 |
| 锚点选择 | `LibraryViewController.swift:1195-1208` | `filter { minY <= safeTop + screenPadding }.max`，不是“第一条完整可见 cell” |
| 恢复入口 | `LibraryViewController.swift:1211-1267` | 只在 `applySnapshot` completion 的 `DispatchQueue.main.async` 里调用；`didRestorePosition = true` 在真正应用 offset 之前 |
| 首帧 bounds 竞态 | `LibraryViewController.swift:1231-1232` | `guard collectionView.bounds.width > 0 ... else { return }`；如果此时 bounds 还是 0，直接返回，之后不会从 `viewDidLayoutSubviews` 重试 |
| 二次读取 | `LibraryViewController.swift:1224` | `fetchFirstBatch` 已经 load 过一次，这里再 load；中间若有旧定时器保存，会读到被覆盖的位置 |
| 保存触发点 | `LibraryViewController.swift:1630-1649`、`191-197`、`163-170`；`LibraryContainer.swift:185-189` | 0.3s idle Timer、decelerating、dragging、viewWillDisappear、willResignActive、scenePhase 六个写入源，无统一代际令牌 |
| 前插补偿 | `LibraryViewController.swift:1410-1440` | 只对“首可见 asset”做 anchor keep；用户一拖动/减速就放弃；恢复与索引补齐可能互相抢 offset |
| 恢复完成门禁 | `LibraryViewController.swift:1291-1303` | `didApplyRestoreOffset` 与 `reason == "no-anchor"` 的组合容易提前/延迟；`isPositionRestoreInFlight` 解除后旧 Timer 仍可能回写 |

### 4.3 根因归纳

1. **恢复不是状态机，而是一次性函数调用**：`didRestorePosition` 过早置 true，首帧 bounds 无效时没有重试入口 → 概率性不恢复。
2. **保存没有单一写入源与代际令牌**：多个 Timer/通知在恢复前、恢复中、恢复后都能写；旧 Timer 可以覆盖新位置。
3. **锚点选择不是稳定视觉锚点**：`layoutAttributesForItem` 在快照 apply / 前插 / 估算高度期间可能是过渡值；“最接近 safeTop”会选到半遮挡 cell。
4. **两次 `positionStore.load` 之间没有一致性保护**：首批窗口与恢复读取可能拿到不同值。
5. **前插补偿与恢复没有共享同一锚点**：头部回填（0..windowStart）会整体推 contentOffset；现有的 anchor keep 在用户接管时放弃，造成“刚恢复又漂走”。
6. **保存发生在主线程同步 JSON 编码 + UserDefaults 写**：不是崩溃根因，但会造成滚动/退出卡顿，间接放大“保存没来得及”的错觉。

#### 4.4.2 锚点选择（Core 纯函数）

新增 `PhotoDeskCore/PositionAnchorSelector.swift`：

```swift
public struct VisibleGridCell: Equatable, Sendable {
    public let section: Int
    public let item: Int
    public let minY: Double
    public let maxY: Double

public enum PositionAnchorSelector {
    /// 选择“第一条完整可见、且不被粘性月份头遮挡”的 cell：
    /// 1) 按 (section, item) 升序；
    /// 2) 过滤 maxY > effectiveTop 且 minY >= effectiveTop - 0.5；
```

#### 4.4.3 保存协调器

新增 `PhotoDesk/Features/Library/LibraryPositionCoordinator.swift`（App 层，持有 store）：

- 单一入口：`save(reason:)`、`cancelPendingSaves()`、`beginRestore(queryKey:)`、`attemptRestore(...)`、`forceSaveOnExit()`。
- 保存流程：
  1. 主线程抓取几何快照（只读 `collectionView`，在 `isApplyingSnapshot == false`、`!isPositionRestoreInFlight` 时）。
  2. 生成 `revision = currentRevision + 1`；`currentRevision = revision`。
  3. 在串行 utility 队列编码 JSON + `defaults.set`；写前检查 `revision == currentRevision`，旧 revision 直接丢弃。
  4. 记录 `position.save.v4 reason=... revision=...` trace。
- 触发点：
  - `scrollViewDidScroll`：0.35s 防抖（`DispatchWorkItem`，不用 Timer 持 cell）。
  - `scrollViewDidEndDragging`：无论是否 decelerate 都保存一次（当前只在 `!decelerate` 保存，是漏洞）。
  - `scrollViewDidEndDecelerating`：保存。
  - `viewWillDisappear`：保存并 `cancelPendingSaves()`。
  - `scenePhase != .active`：保存。
  - `applicationWillTerminate`：同步保存（`defaults.synchronize()` 兜底）。
- 所有保存都必须检查 `isApplyingSnapshot == false`；apply 期间位置是过渡态，禁止写。

#### 4.4.4 恢复状态机

新增 `PhotoDeskCore/PositionRestoreStateMachine.swift`：

```swift
public enum PositionRestorePhase: String, Equatable, Sendable {
    case idle, waitingSnapshot, waitingLayout, applying, verifying, done, failed
}

public struct PositionRestoreState: Equatable, Sendable {
    public private(set) var phase: PositionRestorePhase
    public private(set) var attempts: Int
    public let maxAttempts: Int
    public let timeout: TimeInterval
    // begin / snapshotAvailable / layoutAvailable / applied / verified / timeout 事件
}
```

App 侧 `LibraryPositionCoordinator` 驱动：

1. `beginRestore(queryKey:)`：**只 load 一次**，保存到 `pendingAnchor`；进入 `.waitingSnapshot`；`saveGeneration += 1`，取消所有旧保存。
2. `viewDidLayoutSubviews` / `applySnapshot completion` / `viewDidAppear` 都调用 `attemptRestore()`：
   - bounds 为 0 → `.waitingLayout`，不置 `didRestore`；
   - `numberOfSections == 0` → `.waitingSnapshot`；
   - anchor 不在当前快照且 `!isIndexComplete` → `.waitingSnapshot`（保持遮罩，但 3s 超时后 best-effort）；
   - anchor 在 → `.applying`：`layoutIfNeeded` → `setContentOffset` → `layoutIfNeeded`；
   - 下一轮主循环 `.verifying`：检查 `abs(actual - target) <= 1` 且 `layoutMinY(anchor) - actual ≈ anchorVisualY`；不满足则重试，最多 3 次；满足 → `.done`。
3. `isPositionRestoreInFlight = phase in [.waitingSnapshot, .waitingLayout, .applying, .verifying]`；此期间保存全部拒绝。
4. 遮罩：
   - 开始恢复时 `alpha = 0`；若 0.15s 后仍未 done，淡入；
   - `.done` / `.failed` / 超时淡出；
   - 超时 3s：`ViewerTrace.log("position.restore.v4 timeout")`，按当前最佳 offset 显示，不无限遮挡。
5. 恢复完成后 `lastRestoredQueryKey = queryKey`；只有 queryKey 变化才重置状态机。

#### 4.4.5 前插补偿与恢复共享锚点

- `applySnapshot` 前记录“当前视觉锚点”（`PositionAnchorSelector` 的结果：assetID + visualY）。
- `dataSource.apply` completion 后，用新布局找同一 asset 的 `minY`，`setContentOffset(y: newMinY - visualY, animated: false)`。
- 若用户正在 `isTracking` / `isDecelerating`，不调整（尊重用户）；否则最多 3 个 layout pass 收敛。
- 恢复完成后，如果 `runIndexCompletion` 的头部回填触发快照，仍按同一 asset 补偿；不再用“首可见 cell”临时任务。

## 5. P0-3 / P0-4：滑动多选逻辑错误 + 手感差

### 5.1 用户现象

- 在多选模式，从右侧某一列向下滑，只有右列被选中，左侧图片不选；官方相册会选中整行。
- 滑动过程中卡顿、跳格、回滑取消不跟手、边缘自动滚动不选新 cell。

### 5.2 现有实现与根因

| 现象 | 代码 | 根因 |
|---|---|---|
| 右列下滑只选右列 | `SlideSelectGestureController.swift:113-123` `processFinger` 只取 `indexPathForItem(at: location)` | 单点命中，没有“行带”概念 |
| 垂直下滑根本不进入选择 | `SlideSelectGestureController.swift:70-88` + `SlideSelectPolicy.shouldActivate` | 只在 `horizontal > vertical + epsilon` 时激活；垂直占优直接 `verticalLocked`，让给滚动 |
| 全选后拖选快照为空 | `LibraryViewController.swift:673-676` 读 `collectionView.indexPathsForSelectedItems` | 全选/月份全选只改 `selectionState`，没有 `selectItem`；`reloadSelectionBadges` 只改徽标 |
| 长距离拖动卡顿 | `SlideSelectPolicy.resolvedSelection`（`39-55`）每次重算整个 `visited`；`SelectionState.selectedSet`（`SelectionPolicy.swift:15`）每次 O(n) 构造 Set | O(n²) + 每 cell 一次 Set 构造 |
| 边缘自动滚动不选新格 | `SlideSelectGestureController.swift:138-160` | `lastFingerLocation` 是 collectionView 内容坐标；`setContentOffset` 后同一坐标不再对应手指下的 cell |
| 结束拖动后滚动恢复，下一次纵向拖动又变滚动 | `finishSlideSelection`（`180-193`）只恢复 `isScrollEnabled = true` | 选择模式下没有“单指选、双指滚”的永久策略 |
| 手感差 | 无 haptic、每帧 `collectionView.selectItem`、`updateSelectionCount` 每帧刷新、无区间 diff | 交互反馈与性能都不足 |

### 5.3 官方相册语义（本轮采用）

多选模式下，单指从任意 cell 起手拖动：

- **按行选择**：从起手 cell 所在行到当前 cell 所在行，**整行所有列**都进入选中范围。
- 纵向拖动沿右列下滑时，左侧同行的 cell 必须一起选中。
- 回拖到起始行，之前由本次拖动新增的 cell 恢复为“拖动开始前的状态”；拖动前已选中的 cell 不会被误取消。
- 跨月份分组时，每个 section 内按同样行带规则处理；中间完整经过的 section 整段选中。
- 单月 scope 只在当月内生效。
- **单指拖动 = 选择；双指拖动 = 滚动**。这是官方相册在选择模式下的核心手感来源。

### 5.4 新 Core 纯逻辑

新增 `PhotoDeskCore/SlideSelectRangePolicy.swift`：

```swift
public struct SlideGridMetrics: Equatable, Sendable {
    public let columns: Int
    public let sectionItemCounts: [Int]
}

public enum SlideSelectRangePolicy {
    /// 行带：anchor 与 current 之间的每个 section，按行区间取整行。
    public static func cells(anchor: SlideSelectCell,
                             current: SlideSelectCell,
                             metrics: SlideGridMetrics) -> Set<SlideSelectCell>

    /// 行号：item / columns。
    public static func row(of cell: SlideSelectCell, columns: Int) -> Int

    /// 某一 section 的行区间 [startRow, endRow] 展开为 item 集合。
    public static func items(inSection section: Int,
                             rows: ClosedRange<Int>,
                             itemCount: Int,
                             columns: Int) -> Set<SlideSelectCell>
}
```

语义细节：

- `startSection = min(anchor.section, current.section)`，`endSection = max(...)`。
- 对 `section == anchor.section`：`startRow = anchor.item / columns`；否则 `startRow = 0`。
- 对 `section == current.section`：`endRow = current.item / columns`；否则 `endRow = (itemCount - 1) / columns`。
- 若 `startRow > endRow`（反向拖动），交换。
- 每个 row 的 item 范围：`row*columns ..< min((row+1)*columns, itemCount)`。
- 返回 `Set<SlideSelectCell>`；排序由调用方按 `(section, item)` 生成有序 ID 数组。
- 纯函数，只依赖 Int / Set；零 UIKit / IndexPath。

`SelectionState` 优化：

- 增加 `private(set) var selectedSet: Set<String>` 与 `selected` 数组同步维护；`select/remove/toggle/replaceSelection/selectAll/deselectAll/invert/intersectScope` 全部 O(1) 或 O(delta)。
- 新增 `applyRange(base: Set<String>, range: Set<String>)`：`selected = ordered(base ∪ range)`；或 `applyDelta(add:remove:)`。
- 新增 `contains(_ id:)` O(1)。
- 保留 `selected` 的插入顺序，批量操作展示稳定。

### 5.5 手势控制器重写

`SlideSelectGestureController` 改为显式状态机：

```
idle → pressing（手指按下，记录 anchor cell）
     → selecting（移动超过 6pt 且起点在 cell 内）
     → autoScrolling（手指进入上下 60pt 边缘）
     → finished（抬手/取消）
```

关键点：

1. **激活条件**：`isSelecting == true` 且起点 `indexPathForItem(at:) != nil`；移动超过 `SlideSelectConfig.activationThreshold = 6pt` 即激活，不再做方向锁。纵向/横向都进入选择。
2. **滚动冲突**：
   - 进入多选时设置 `collectionView.panGestureRecognizer.minimumNumberOfTouches = 2`；退出多选恢复 1。
   - `gestureRecognizerShouldBegin`：单指 pan 仅在起点位于 cell 上时返回 true；双指 pan 交给 collectionView。
   - `gestureRecognizer(_:shouldRecognizeSimultaneouslyWith:)`：slide pan 不与 collectionView pan 同时识别（单指已由 minimumNumberOfTouches 分离）。
3. **anchor / current**：
   - `anchorCell = indexPathForItem(at: startPoint)`；
   - 每次 move/auto-scroll tick 用**窗口坐标**重新换算：`let point = collectionView.convert(windowPoint, from: window)`；`currentCell = indexPathForItem(at: point)`。
   - 存 `lastFingerWindowPoint`，不要存 content 坐标。
4. **区间应用**：
   - `baseIDs = selectionState.selectedSet`（拖动开始帧快照）；
   - `range = SlideSelectRangePolicy.cells(...)`；
   - `targetIDs = baseIDs ∪ range`（按 section/item 排序）；
   - 与上一帧 `lastRange` 做 diff：`added = range - lastRange`、`removed = lastRange - range`；
   - 只对 `added` / `removed` 的可见 cell 调 `cell.setSelected`；对不可见 cell 不遍历；
   - `selectionState.applyRange(base:range:)` 一次替换；`updateSelectionCount()` 只在 count 变化时调。
5. **回拖**：`range` 缩小后，`removed` 的 cell 恢复 `baseIDs.contains(id)`（原本已选保持选中，原本未选取消）。
6. **自动滚动**：
   - `CADisplayLink` 每帧：按 `edgeVelocity` 滚动；然后 `collectionView.layoutIfNeeded()`？不需要；直接 `indexPathForItem(at: convertedPoint)` 取当前手指下的 cell。
   - 顶部/底部 60pt；速度 2–12pt/帧，按距离线性；`preferredFramesPerSecond = 60`（iOS 16 可设）。
   - 手指离开边缘立即销毁 display link。
7. **触觉**：每次 `range` 新增一行时 `UISelectionFeedbackGenerator.selectionChanged()`；进入/退出选择模式一次 `impactOccurred()`。
8. **点选**：`allowsSelection = false` 只在拖动激活期间；结束时下一轮主循环恢复。`didSelectItemAt` 继续处理普通点选。
9. **性能预算**：一次 move 最多 O(rows × columns) 的 range 计算 + O(delta) 的可见 cell 更新；禁止在 move 中调用 `collectionView.reloadData` / `selectItem` 循环 / `selectedSet` 全量构造。

### 5.7 测试与验收

**Core 单测（必须覆盖用户原话场景）**

- `testVerticalDragOnRightColumnSelectsWholeRows`：3 列，anchor `(0,2)`（第 0 行右列），current `(0,14)`（第 4 行右列）→ 选中 `(0,0)...(0,14)` 共 15 个；显式断言 `(0,0)`、`(0,1)` 在集合内。
- `testDragBackRestoresOriginalSnapshot`：原选中 `(0,4)`；拖到第 4 行再回到第 0 行；最终仍只选中 `(0,4)`。
- `testCrossMonthSelectsFullRowsInEachSection`。
- `testMonthScopeDoesNotLeakToOtherSections`。
- `testHorizontalDragSelectsWholeRow`。
- `testLastRowPartialFill`：itemCount 不是 columns 整数倍时，最后一行只取存在的 item。
- `testSelectionStateCachedSetMatchesArray`：随机 1,000 次操作后 `selectedSet == Set(selected)`。

**UI 测试**

- `testVerticalSlideSelectSelectsLeftColumns`：3 列网格，从首屏右列 cell 中心按住向下拖 4 行；断言 `Selection-Count` ≥ 12，且最左列某 cell 的 `accessibilityValue` 含 `selected`。这是对用户 bug 的直接回归。
- `testTwoFingerScrollInSelectionMode`：多选模式下双指上滑，断言网格滚动且选择数不变。
- `testSlideSelectDragBackRestores`：拖选 6 个后回拖到起点，断言计数回到原值。
- `testSlideSelectHapticCounter`（DEBUG 钩子）：断言每个新增行触发一次 selection feedback；不依赖真实触觉硬件。
- `testSlideSelectFrameBudget`（DEBUG 计数器）：一次 300pt 拖动，`slideSelectUpdateCount` ≤ 90，`selectionCountLabel` 更新次数 ≤ 30。

**手感验收（真机）**

- 3 列/5 列各 10 次长距离拖选：无跳格、无回弹、无“选了又取消”；边缘自动滚动连续选中；主观评价达到“跟手”。
- 滚动 ≥55 FPS（Core Animation）。

### 5.8 风险

- 双指滚动依赖 `collectionView.panGestureRecognizer.minimumNumberOfTouches = 2` 的行为；若某些 iOS 16 小版本不识别，退化为“选择模式下顶部/底部留出 44pt 滚动带”，并在 docs/24 记录。
- 行带选择会让“只选某一列”变得不可能；这是官方相册语义，符合用户要求。若用户后续要列选择，另开需求。
- 跨月行带在 `sectionItemCounts` 与 `columns` 不一致（首行不满）时要按实际 itemCount 截断，单测覆盖。

- 若 M14-1/2 仍崩溃：立刻停止发布，抓取新 `.ips`；按新栈重新定位，**不得**用“清理缓存/重装”掩盖。
- 若 M14-3/4 仍漂移：抓 `Library-DebugSummary`（`off/anchor/visualY`）与 `position.save.v4`/`position.restore.v4` trace，按状态机阶段定位。
- 若 M14-6/7 仍不对：抓 `Selection-Count` 与滑选调试计数，确认是“行带计算”还是“手势未激活”。
