## 0. 结论摘要

### 0.1 一句话结论

这 12 条不是 12 个孤立 bug，而是 **4 组系统性缺陷** 在同一个版本里集中爆发：

| 组 | 涉及条目 | 共同根因 | 危害 |
|---|---|---|---|
| **A. 查看器生命周期与几何** | 1、2、8、12 | 查看器在「数据源、UICollectionView、cell 复用、PhotoKit 请求」四者之间没有单一事实来源；缩放几何在零尺寸/缩放过程中被直接改写；图片请求不可取消、可能重复 resume | 必现崩溃 / 内存暴涨 / 删错图 |
| **B. 图库快照与索引** | 3、4、11 | `LibraryViewModel` 在主线程同步重算全库；`dataSource.apply` 尚未提交就 `scrollToItem`；月份索引条在快照提交前更新；完整索引未完成时按部分内容恢复位置 | 选年份/跳月份必现崩溃；位置记不住 |
| **C. 月份导航与选择** | 9、10、7 | 只有一条 44pt 的细小索引条，没有月份选择面板；月份头「选择」只进入多选、不全选；长按框选参数（0.28s / 10pt）与滚动手势互斥 | 功能不可用/难用 |
| **D. 布局与控件** | 5、6 | `DSToast` 子视图缺 `translatesAutoresizingMaskIntoConstraints=false`，渲染成空玻璃胶囊且拦截底部触摸；顶部筛选栏独立占一行 | 控件被挡、屏幕空间浪费 |

### 0.2 为什么上一轮 12/12 UI 测试全绿，用户仍必现崩溃

上一轮的测试证明的是「**正常路径能走通**」，不是「**异常路径不崩溃**」：

1. UI 测试只做 20 次下滑 + 1 次提交，没有做 **50 次快速滑动、20 次捏合、连续切换年份、删第一张/中间/最后一张、杀进程重启**。
2. `-uiTestingSessionMock` 用 `MockPhotoWriter` 替代了真实 PhotoKit 写；真实删除/隐藏路径上的 `PHAsset` 失效、系统确认、observer 回调没有进入测试。
3. 性能测试只测冷启动与滚动内存，没有测 **查看器大图请求**（`PHImageManagerMaximumSize`）和 **预取缓存无上限**。
4. 崩溃发生在主线程/UIKit 内部时，XCUITest 往往表现为「下一个断言失败」而不是「崩溃」，测试日志里没有 `NSSetUncaughtExceptionHandler` 的现场。
5. 本机无真机；iOS 15.5 模拟器的内存压力、PhotoKit 回调时序与真机不同。

**本轮必须先补「崩溃取证」和「压力回归」，再谈修复。**

### 0.3 修复原则（执行 Agent 必须遵守）

1. **稳定性优先，功能冻结**：本轮不新增页面、不加重构型功能；只修 12 条 + 必要的测试/诊断。
2. **先复现，后修复**：每条至少有一个在修复前会失败（或会崩溃）的自动化用例；没有复现用例的修复不算完成。
3. **一次只改一个根因**：一个 commit 只对应一条根因；禁止「顺手重构」把多个根因混在一个提交里。
4. **不掩盖症状**：禁止用「关闭动画」「延迟 0.5 秒」「加 `try?` 吞掉」「把 collectionView.reloadData 当万能药」来让测试变绿。

8. **所有结论必须可验证**：本机能跑的 core 测试必须本机跑；iOS 侧必须 CI 跑；截图必须逐张打开确认；不得把「没跑过」写成「已验证」。

### S01 · 捏合缩放必卡死闪退

**现象**：查看器任意一张图，双指放大/缩小几次就卡住，随后闪退；有时双击也会。

**复现**：打开查看器 → 双指张开到 2× 以上 → 双指捏合回 1× → 再张开；重复 5 次。

**代码定位**：
- `PhotoDesk/Features/Viewer/ZoomableImageCell.swift:137-147` `layoutSubviews()`：`if scrollView.zoomScale <= 1.01 { imageView.frame = CGRect(origin: .zero, size: scrollView.bounds.size) }`
- 同文件 `:161-171` `configure(item:image:)`：`imageView.frame = CGRect(origin: .zero, size: scrollView.bounds.size)`；dequeue 时 `scrollView.bounds` 可能为 `.zero`
- 同文件 `:202-230` `handleDoubleTap`：在 `UIView.animate` 内先 `scrollView.zoom(to: rect, animated: false)` 再 `setZoomScale(target, animated: false)`
- 同文件 `:236-252` `scrollViewDidZoom`：直接改写 `imageView.frame` 做居中

**根因（按确定性排序）**：
1. **零尺寸 zoom view**：`configure` 在 cell 尚未布局时把 `imageView.frame` 设为 `scrollView.bounds.size`（`.zero`）。`UIScrollView` 的 `viewForZooming` 返回零尺寸 view 时，捏合会做 `contentSize / zoomScale` 的除法，产生 `NaN`/`inf`，最终 `CALayer position contains NaN` 崩溃。
2. **缩放过程中改写被缩放视图的 frame**：`layoutSubviews` 与 `scrollViewDidZoom` 都在缩放过程中直接改 `imageView.frame`。`UIScrollView` 的缩放是通过 transform 实现的，外部改 frame 会与内部 `contentSize`/`contentOffset` 计算打架，轻则跳动，重则几何非法。
3. **双击重复应用缩放**：`zoom(to:)` 本身会设置 zoomScale，紧接着又 `setZoomScale(target)`；且 `rect` 可能用零 bounds 计算，产生 `CGRect` 非法值。
4. **无有限值守卫**：没有检查 `bounds.width/height > 0`、`image.size > 0`、`zoomScale.isFinite`、`rect` 是否 finite。

**修复策略**：
1. 重写 `ZoomableImageCell`：新增 `PhotoDeskCore/ZoomGeometry.swift`（纯 Double，零 Apple 依赖）：
   - `aspectFitSize(imageSize:viewportSize:) -> DoubleSize`
   - `centeredInset(contentSize:viewportSize:zoomScale:) -> DoubleInsets`
   - `clampedZoomRect(zoomScale:point:viewportSize:imageSize:) -> DoubleRect?`（返回 nil = 不缩放）
   - 所有函数对 0/负数/NaN/∞ 返回安全值。
2. `ZoomableImageCell` 只保留一个 `zoomContentView`（`UIView`），`imageView` 作为其子视图；`viewForZooming` 返回 `zoomContentView`。
3. `layoutSubviews`：
   - 仅当 `bounds.width > 0 && bounds.height > 0 && image != nil` 时布局；
   - `zoomContentView.frame = CGRect(origin: .zero, size: fitSize)`；`scrollView.contentSize = fitSize`；
   - `zoomScale <= 1.001` 时才允许重设 frame；缩放中绝不改 `zoomContentView.frame`。
4. `scrollViewDidZoom`：只更新 `scrollView.contentInset`（居中用），不改任何子视图 frame；`contentInset` 用 `ZoomGeometry.centeredInset` 计算并 clamp 到非负。
5. `configure`：先 `resetZoom()`（`setZoomScale(1, animated:false)` 仅在 bounds 有效时调用），再设置图片；`image == nil` 时 `scrollView.isUserInteractionEnabled = false`，禁止捏合。
6. `handleDoubleTap`：只调用一次 `scrollView.zoom(to: rect, animated: !reduceMotion)`；`rect` 由 `ZoomGeometry.clampedZoomRect` 计算，nil 则 return；禁止在 `UIView.animate` 内再 `setZoomScale`。
7. `prepareForReuse`：取消加载、清图、`isUserInteractionEnabled=false`、`resetZoom` 前先判断 bounds。
8. DEBUG 横幅增加 `zoom=<%.2f> img=<ok|nil>`，UI 测试断言 `zoom` 是有限数字（不含 `nan`/`inf`）。

**验收**：
- 新增 `ZoomGeometryTests`（≥12 条：宽图/高图/方图/零尺寸/负尺寸/NaN/极限缩放/双击 rect 钳制/居中 inset）。
- 新增 UI `testPinchZoom20Times`：查看器内 `pinch(withScale: 2.5, velocity: 2)`、`pinch(withScale: 0.4, velocity: -2)` 循环 20 次，每次后 `app.state == .runningForeground`，DEBUG 横幅 `zoom` 不含 `nan`。
- 手动：iPhone 上连续捏合 30 次、双击 10 次、旋转屏幕后再捏合，不卡不崩。

### S02 · 快速滑动必卡死闪退

**现象**：查看器里快速左右连续滑十几张，画面卡住，随后闪退（有时是系统杀掉 App）。

**复现**：打开查看器 → 以最快速度连续左滑 30 张 → 再右滑 30 张。

**代码定位**：
- `PhotoDesk/Features/Viewer/ViewerViewController.swift:817-825` `prefetchAround(index:)`
- 同文件 `:912-928` `scrollViewDidScroll`：每次页码变化调用 `prefetchAround`
- `PhotoDesk/Core/Imaging/ImagePipeline.swift:120-132` `prefetch(ids:size:)`：只 `startCachingImages`，从不 `stopCachingImages`
- 同文件 `:151-175` `fullImage`：`PHImageManagerMaximumSize` + `.opportunistic` + `withCheckedContinuation`，无取消、无单次 resume 保护
- 同文件 `:214-241` `requestThumbnail`：取消时回调 + `box.id == PHInvalidImageRequestID` 两条路径都可能 resume
- `PhotoDesk/Features/Viewer/FilmStripView.swift:53-61` `highlight`：每次翻页 `reloadData()`

**根因**：
1. **预取缓存无上限**：每次页码变化都把新 3-4 张以「屏幕像素尺寸」`startCachingImages`，旧的一组从不 `stopCachingImages`。快速滑 30 张 = 90-120 张全屏尺寸图被 `PHCachingImageManager` 缓存，内存瞬间上涨，触发 jetsam。
2. **大图请求不可取消**：`fullImage` 没有保存 `PHImageRequestID`，cell 复用/离屏后旧请求继续解码；`PHImageManagerMaximumSize` 对 48MP 图可产生 ~190MB 解码缓冲。
3. **continuation 可能重复 resume**：`.opportunistic` 会多次回调；取消路径与回调路径可能同时 resume；Swift 运行时直接 `Fatal error: SWIFT TASK CONTINUATION MISUSE`。
4. **胶片条 reload 风暴**：每次翻页 `reloadData()`，44pt 的小 collection view 也参与预取/布局，放大主线程压力。
5. **滚动回调里做重活**：`prefetchAround` 构造数组、`PHAsset.fetchAssets`、`startCachingImages` 都在主线程。

**修复策略**：
1. `ImagePipeline` 重写为「可取消、单次 resume、有预算」：
   - 新增 `ResumeOnce<T>`（`NSLock` + `didResume`）包住所有 `withCheckedContinuation`；`resume` 第二次直接忽略并 `os_log` 警告（DEBUG 下 `assertionFailure` 只在测试开关下触发）。
   - `fullImage` 改为 `deliveryMode = .highQualityFormat`（单次回调）、`resizeMode = .fast`、`targetSize = min(screenPixel * 1.25, 2048)`；保存 `PHImageRequestID`，`cancel(requestID)` 可取消。
   - `requestThumbnail` 同理；删除 `box.id == PHInvalidImageRequestID` 的立即 resume 分支，统一在回调里 resume；取消时用 `withTaskCancellationHandler` 调 `cancelImageRequest`。
   - 新增 `fullImageCache: NSCache<NSString, UIImage>`（countLimit 6，costLimit 60MB），滑动回看命中缓存。
   - `prefetch` 维护 `prefetchedIDs: Set<String>` 与 `prefetchPixelSize`；每次调用计算 `new - old` / `old - new`，对旧集合 `stopCachingImages`；窗口上限 7 张；尺寸上限 `min(screen*1.25, 2048)`。
   - `cancel(id:)` 同时取消 thumbnail/fullImage 的 requestID 与缓存预取。
   - 监听 `UIApplication.didReceiveMemoryWarningNotification`，清空内存缓存与预取。
2. `ZoomableImageCell` 持有 `loadTask: Task<Void,Never>?`，`prepareForReuse`/`didEndDisplaying` 取消；`loadImage` 保存任务，不再只靠 token。
3. `ViewerViewController`：
   - `prefetchAround` 只在页码变化时调用（已有），加 100ms 防抖；`items` 为空或 index 越界直接 return。
   - 删除 `FilmStripView.highlight` 里的 `reloadData()`，改为只刷新旧/新两个 cell 的 `isCurrent`；`reload` 只在 ids 变化时调用。
   - `viewDidDisappear` 调 `pipeline.cancelAll()`（新增协议方法）。
4. `ImagePipelineProtocol` 增加 `cancelAll()`；`AppContainer` 无需改。

**验收**：
- 新增 `ImagePipelineResumeTests`（Fake requester 连续回调两次、回调后取消、取消后回调，断言不崩、只 resume 一次）。
- 新增 UI `testFastSwipe50Times`：连续 `swipeLeft(velocity:.fast)` 50 次 + 右滑 50 次，`app.state` 始终 running，DEBUG 横幅 `items` 不变。
- 性能 `testViewerMemoryUnderFastSwipe`：5,000 张库，滑 100 次，峰值 < 250MB（XCTMemoryMetric）。
- 手动：真机 100 次快速滑动，Instruments 无内存尖峰。

### S03 · 选择年份后卡死闪退

**现象**：在筛选面板选一个年份并应用，或点右侧年份刻度，界面卡住随后闪退；重启后若筛选条件仍生效，启动也可能崩。

**复现**：
1. 打开筛选 → 选择「2024 年」→ 完成；
2. 反复切换 2026/2024/2020 各 5 次；
3. 杀进程重启（筛选条件已持久化）。

**代码定位**：
- `PhotoDesk/Features/Library/LibraryViewModel.swift:152-157` `setFilter`：主线程同步 `rebuildDerived`
- 同文件 `:359-378` `rebuildDerived`/`rebuildSections`：`PhotoFilter.apply` + `DateSectionizer` + `Dictionary` + 快照数组全在主线程
- `PhotoDesk/Features/Library/LibraryViewController.swift:684-704` `applySnapshot`：先改 `currentSections/currentItemsBySection`，再 `dataSource.apply`，**紧接着** `restorePositionIfNeeded()` 与 `syncIndexBar()`
- 同文件 `:725-757` `restorePositionIfNeeded`：`collectionView.layoutIfNeeded()` + `scrollToItem`，没有等 `dataSource.apply` 完成，也没有校验 `numberOfSections`
- 同文件 `:837-852` `syncIndexBar`：在 `dataSource.apply` 之后立即更新索引条
- `PhotoDesk/Features/Library/LibraryFilterSheet.swift:213-215` `previewCount`：每次 body 计算都对 `visibleItems` 全量 `PhotoFilter.apply`

**根因**：
1. **快照 apply 与 scrollToItem 竞态**：`dataSource.apply` 是异步提交；`restorePositionIfNeeded` 在提交前按新 `currentItemsBySection` 的 section index 调 `scrollToItem`，collectionView 仍持有旧快照（甚至 0 个 section），越界 → `NSInternalInconsistencyException` 崩溃。持久化年份筛选在启动时首快照就会走这条路径，所以「选年份后重启也崩」。
2. **索引条先于快照更新**：`syncIndexBar` 在 apply 后立即执行，用户点年份刻度时 `currentSections` 已是新数据，但 collectionView 还是旧快照；`scrollToSection` 只校验 `index < currentSections.count`，没校验 `collectionView.numberOfSections` → 越界崩溃。
3. **主线程全量重算**：5,470 张的 `PhotoFilter.apply` + 分组 + `Dictionary` 在主线程同步执行，外加 `previewCount` 在 SwiftUI body 每次重算，主线程阻塞可达数秒；触发 watchdog（0x8badf00d）表现为「卡死后闪退」。
4. **快照重复 apply**：后台索引每 2,000 条 `rebuildDerived(animated:true)`，用户同时切换年份，两个 `dataSource.apply` 交错，可能产生「无效更新」异常。
5. **重复 item id**：`runIndexCompletion` 用 `offset: allItems.count` 续拉；如果索引期间照片库发生插入，offset 会偏移，导致同一 asset 被追加两次；Diffable 快照遇到重复 item identifier 直接 fatal。

**修复策略**：
1. **后台过滤 + 代际令牌**：`LibraryViewModel.setFilter` 立即更新 `query.filter`（UI 状态），启动 `Task.detached(priority: .userInitiated)` 计算 `visible/filtered/sections/itemsBySection`；用 `filterGeneration` 丢弃过期结果；主线程只做赋值与 `onSnapshotUpdate`。
2. **快照协调器**：`LibraryViewController` 增加 `isApplyingSnapshot` + `pendingSnapshot`；同一时间只允许一个 `dataSource.apply`；新快照到来时覆盖 `pendingSnapshot`，在 completion 里再 apply 最新一个；筛选/年份切换一律 `animatingDifferences: false`，增量索引只有 delta < 200 且不在滚动/多选时才 animated。
3. **apply completion 后再做三件事**：更新 `currentSections/currentItemsBySection`（或至少在 completion 里同步）、`syncIndexBar()`、`restorePositionIfNeeded()`；`scrollToItem` 前用 `dataSource.indexPath(for:)` 或 `collectionView.numberOfSections/numberOfItems` 校验。
4. **去重**：`rebuildSections` 前对 `filteredItems` 按 id 去重（保序）；`runIndexCompletion` 每次追加后对 `allItems` 去重；DEBUG 下在 `applySnapshot` 前断言 `Set(ids).count == ids.count`，Release 下去重后继续。
5. **筛选面板预览计数**：`previewCount` 改为 `@State`，在 `onAppear` 与 `draft` 变化后 200ms debounce 计算一次；计算期间显示「计算中…」，不在 body 里全量扫描。
6. **索引条禁用窗口**：`isApplyingSnapshot == true` 时 `indexBar.isUserInteractionEnabled = false`；completion 后恢复。

**验收**：
- 新增 UI `testFilterYearsRepeatedly`：2026→2024→2020→2026 循环 5 次，每次等网格稳定，`app.state` running；断言 section header 年份正确。
- 新增 UI `testFilterPersistedAfterRelaunch`：选 2024 → 杀进程 → 重启 → 首屏只显示 2024，且不崩。
- 单测 `LibraryViewModelTests`：后台过滤结果与同步结果一致；代际令牌丢弃旧结果；重复 id 去重。
- 性能：5,470 张筛选 < 500ms（`XCTClockMetric` 或 signpost），主线程无 >100ms 阻塞。

### S04 · 无法记住上次整理到的位置

**现象**：滚到某个月/某张，切 Tab 或杀进程重启，回到顶部或错误位置；有时提示「已回到上次整理的位置」但位置不对。

**复现**：滚到 2024 年 5 月 → 切到「工具」→ 回「照片库」；再杀进程重启。

**代码定位**：
- `PhotoDesk/Core/Support/LibraryPositionStore.swift:33-45`：按 `queryKey` 存 `assetID/sectionID/offsetRatio/savedAt`
- `PhotoDesk/Features/Library/LibraryViewController.swift:709-722` `savePositionIfNeeded`
- 同文件 `:725-757` `restorePositionIfNeeded`
- 同文件 `:871-880` `scrollViewDidScroll`：0.5s Timer 保存
- 同文件 `:759-764` `scrollToSection`：不主动保存

**根因**：
1. **只恢复一次**：`didRestorePosition = true` 在 `positionStore.load` 之前就置位；首快照只有 500 张（后台索引未完成），如果保存的 asset 在更早的年份，`firstIndex` 找不到 → 走 `offsetRatio` 回退（按 500 张的 contentSize 算比例），位置必然错；之后完整索引到了也不会再试。
2. **保存时机不足**：只有滚动停止 0.5s 和 `viewWillDisappear`；切 Tab 时 `viewWillDisappear` 可能不触发（SwiftUI TabView 子控制器生命周期）；杀进程更不会触发。`scrollToSection` 跳转后如果用户立刻杀 App，0.5s Timer 还没到。
3. **queryKey 读的是保存时的值**：`savePositionIfNeeded` 用 `viewModel.query.key`；如果用户在滚动后立刻改筛选，旧内容偏移会被写到新筛选的 key 下。
4. **索引条跳转不保存**：`scrollToSection` 只 scroll，不写 `LibraryPosition`；`scrollViewDidScroll` 的 Timer 可能被下一次拖动取消。
5. **offsetRatio 用部分 contentSize**：`contentSize.height` 在索引未完成时是 500 张的高度，比例不可比。
6. **恢复提示 Toast 每次启动都弹**：`restorePositionIfNeeded` 成功就 `batchToast.show`，正好落在底部，形成用户看到的「气泡」。

**修复策略**：
1. `LibraryPosition` v2：`assetID/sectionID/itemIndexInSection/offsetRatio/savedAt/schemaVersion`；`LibraryPositionStore` 用 `library.lastPosition.v2.<queryKey>` 存 JSON，读取时兼容 v1（v1 解码失败则忽略，不崩）；新增 `clearAll`。
2. `LibraryViewController` 捕获 `currentSnapshotQueryKey`（在 `applySnapshot` 时赋值），保存时用它，不用 `viewModel.query.key`。
3. 保存触发点（全部走同一个 `savePositionNow(reason:)`）：
   - `scrollViewDidEndDecelerating`
   - `scrollViewDidEndDragging(willDecelerate: false)`
   - `viewWillDisappear`
   - `UIApplication.willResignActiveNotification`
   - `LibraryRootView` 的 `scenePhase == .background`
   - `scrollToSection` 完成后立即保存
   - 0.3s debounce 的滚动停止兜底
4. 恢复策略（`pendingRestore`）：
   - 每次 `applySnapshot` completion 后尝试；
   - 保存的 `assetID` 在当前快照中 → 精确定位；
   - 找不到且 `viewModel.isIndexComplete == false` → **不标记完成**，等下一批索引；
   - 索引完成仍找不到 → 用 `sectionID` 找 section，再用 `itemIndexInSection` 钳制；
   - 再失败 → `offsetRatio`（此时 contentSize 已完整）；
   - 成功后 `pendingRestore = nil`，**不弹 Toast**，只在 DEBUG 横幅显示 `restore=ok section=2024-05`。
5. `LibraryViewModel` 增加 `@Published private(set) var isIndexComplete: Bool`（`runIndexCompletion` 完成时置 true），供恢复与全选使用。
6. 新增设置页「上次位置」状态文案（可选）：显示 `sectionID` 与保存时间；「清除位置记忆」保持。

**验收**：
- 单测 `LibraryPositionStoreTests`：v1→v2 兼容、损坏 JSON 不崩、clearAll。
- UI `testPositionRestoredAfterRelaunch`：滚到 2024-05 → `app.terminate()` → `app.launch()` → 断言首可见 section header 含「2024年5月」。
- UI `testPositionSavedOnTabSwitch`：切 Tab 再回来，位置不变。
- 手动：大库（5,000+）滚到 2021 年，杀进程重启，误差 ≤ 1 行。

### S07 · 多选时不能滑动选择

**现象**：多选模式下只能一格一格点；按住拖动不会连续选中，或者一拖就变成滚动。

**代码定位**：
- `PhotoDesk/Features/Library/LibraryViewController.swift:349-354`：`UILongPressGestureRecognizer(minimumPressDuration: 0.28, allowableMovement: 10)`
- 同文件 `:469-529` `onBoxLongPress` / `updateBoxSelection`：只有长按后移动 >10pt 才进入框选；框选只加选，不处理跨 section 的连续范围
- `PhotoDeskCore/SelectionPolicy.swift`：只有 `toggle/select/selectAll/invert/intersectScope`，没有范围选择

**根因**：
1. `allowableMovement = 10` 太小：用户按住后自然拖动 10pt 就超过阈值，长按识别失败，collectionView 的 pan 接管 → 变成滚动。
2. `minimumPressDuration = 0.28` 偏长：快速「按住-拖」在 0.28s 前就移动，长按失败。
3. 没有 `SelectionRange` 纯逻辑：跨 cell / 跨 section 的连续范围无法一次算出来，只能逐 cell 命中，容易漏。
4. 框选期间 `collectionView.isScrollEnabled = false` 是进入后才设；在长按失败时永远不会进入，用户感知就是「不能滑动选择」。
5. 没有视觉提示（长按提示/选中反馈延迟）。

**修复策略**：
1. `PhotoDeskCore/SelectionPolicy.swift` 增加：
   - `public struct SelectionRange { public static func ids(in orderedIDs: [String], from anchor: String, to target: String) -> [String] }`（双向、缺失返回空、重复 id 去重）；
   - `SelectionState.select(_ ids: [String])`（批量加选）、`replaceSelection(_ ids: [String])`（范围替换，保留 scope 外过滤）、`selectRange(in:from:to:)`。
2. `LibraryViewController`：
   - 长按参数改为 `minimumPressDuration = 0.15`、`allowableMovement = .greatestFiniteMagnitude`；`delaysTouchesBegan = false`。
   - 进入 `.began`：若未多选，按 anchor 进入多选并选中 anchor；记录 `baseSelected = selectionState.selectedSet`、`anchorID`、`didMove = false`。
   - `.changed`：位移 > 4pt 置 `didMove`；用 `collectionView.indexPathForItem(at:)` 取当前 cell（超出 bounds 时按最近 cell 钳制）；`orderedIDs = currentItemsBySection.flatMap`；`range = SelectionRange.ids(...)`；`selectionState.replaceSelection(baseSelected ∪ range)`；刷新可见角标；显示 `selectionOverlay` 矩形。
   - 边缘自动滚：保留 CADisplayLink，距顶/底 < 60pt 时 8-10pt/帧；滚动后重新取 indexPath。
   - `.ended`：若 `didMove == false` 且当前 cell 与 anchor 相同，视为点按 toggle（避免与 tap 重复）；清理 overlay，恢复 `isScrollEnabled = true`。
   - 快速滑动（未按住 0.15s）不触发长按，collectionView 正常滚动；`testScrollWorksInSelectionMode` 必须继续通过。
3. 多选工具栏加提示文案「按住滑动可连续选择」；首次进入多选时 Toast/提示 2 秒。
4. 增加 DEBUG 角标值：已选 cell 的 `accessibilityValue` 继续带 `selected`。

**验收**：

### S08 · 滑动照片闪退

### S11 · 通过时间刻度跳转后，重启应用无法记住位置

**现象**：拖右侧年份/月份刻度跳到某月，马上杀进程重启，回到顶部/旧位置。

**代码定位**：
- `LibraryViewController.swift:759-764` `scrollToSection`：只 scroll，不保存
- 同文件 `:871-880`：0.5s Timer 保存，跳转后立即杀进程来不及
- `LibraryPositionStore`：`sectionID` 存了但 `restorePositionIfNeeded` 完全没用（只用 assetID / offsetRatio）

**根因**：与 S04 同源，但更具体：
1. `scrollToSection` 没有同步保存；
2. 索引条跳转是程序化滚动，`scrollViewDidScroll` 里 `isRestoringPosition` 可能为 true，直接 return；
3. 索引条跳转后 `currentItemsBySection` 已更新，但 `savePositionIfNeeded` 用 `indexPathsForVisibleItems.min()`，在 `scrollToItem` 刚执行、layout 未完成时取到旧 cell；
4. `sectionID` 没参与恢复，assetID 找不到就只靠 ratio。

**修复策略**：
1. `scrollToSection` 在 `scrollToItem` 后 `collectionView.layoutIfNeeded()`，取目标 section 的 `item 0` 的 `assetID`，直接构造 `LibraryPosition(assetID:..., sectionID:..., itemIndexInSection:0, offsetRatio:..., savedAt: Date())` 并 `positionStore.save(..., queryKey: currentSnapshotQueryKey)`；不依赖滚动回调。
2. `restorePositionIfNeeded` 增加 `sectionID` 优先：
   - 先按 assetID；
   - 找不到则按 `sectionID` 找 section index；
   - 再按 `itemIndexInSection` 钳制；
   - 最后 ratio。
3. `LibraryRootView` 在 `scenePhase == .background` / `.inactive` 时调用 `selectionBridge.controller?.savePositionNow(reason:)`；`viewWillDisappear` 也调用。
4. 时间刻度跳转后显示 1.5s 的顶部细横幅「已跳到 2024年5月」，不挡住网格；不写 Toast。

**验收**：

### S12 · 删除、隐藏图片必闪退（先跳第一张，再闪退）

**现象**：查看器里下滑删除/隐藏任意一张，画面先跳到第一张，然后闪退；多选批量删除也可能闪退。

**复现**：查看器打开第 8 张 → 下滑（删除/隐藏）→ 必现。

**代码定位**：
- `PhotoDesk/Features/Viewer/ViewerViewModel.swift:104-113` `stage`：先 `items.remove(at: index)`，再算 `ReplacementPlan`；`currentIndex = plan.nextIndex ?? 0`
- `PhotoDesk/Features/Viewer/ViewerViewController.swift:416-455` `performStaged` / `applyRemoval`：`flyOut` 动画 0.35s 后才 `performBatchUpdates { deleteItems }`
- 同文件 `:512-533` `flyOut`
- 同文件 `:862-881` `cellForItemAt`：`viewModel.items[indexPath.item]` 无边界检查
- 同文件 `:817-825` `prefetchAround`：`viewModel.items[index...]` 等切片

**根因（按确定性排序）**：
1. **数据源先变、cell 后删**：`stage` 已经把 `items` 减 1，但 collectionView 仍显示 N 个 cell；在 0.35s 飞出动画期间，任何布局/滚动/预取都会让 collectionView 按旧 index 取新数组 → 越界；`cellForItemAt` 的 `viewModel.items[indexPath.item]` 直接 crash。
2. **`performBatchUpdates` 时机错误**：等动画结束再删 cell，但此时 collectionView 可能已经在某次 layout 中把内部 count 更新为 N-1；再 `deleteItems` 就变成「删一个不存在的 item」→ `NSInternalInconsistencyException`。
3. **`currentIndex = plan.nextIndex ?? 0`**：如果 `plan.nextIndex` 为 nil（`shouldClose`）或计算错，`currentIndex` 变 0 → 画面跳第一张；随后 `applyRemoval` 用旧 `removedIndex` 删 cell，越界。
4. **无串行化**：连续两次下滑，第二次 `stage` 在第一次 `performBatchUpdates` 之前执行，index 基于已减 1 的数组，cell index 却基于旧 collectionView → 错位/越界。
5. **隐藏/删除提交期间 observer 回调**：`ReviewSession` 只入队，不写 PhotoKit；但 `LibraryViewModel.applyPendingChanges` 会 `rebuildDerived`，网格 diffable apply 与查看器无关，不会直接崩；真正崩的是查看器自身的数组/索引。

**修复策略（核心：删除事务）**：
1. `ViewerViewModel` 拆分：
   - `func planRemoval(action:forItemID:exitEdge:) -> StagedPlan?`：只做 `reviewSession.enqueue*` + 计算 `removedIndex/plan/removedItem`，**不改 `items`、不改 `currentIndex`**；
   - `func commitRemoval(_ plan: StagedPlan) -> RemovalResult`：`items.remove(at:)`、`currentIndex = plan.nextIndex ?? 0`、`isFavoriteCurrent` 更新；返回 `nextIndex/shouldClose`；
   - `func rollbackRemoval(_ plan:)`：入队失败时把 item 插回原位（用于 enqueue 失败/取消）。
2. `ViewerViewController`：
   - 新增 `isRemovalInFlight`；`performStaged` 开头 `guard !isRemovalInFlight else { return }`，置 true；completion 置 false。
   - `guard let plan = viewModel.planRemoval(...)`；若 nil 直接 return。
   - 取当前 cell 的 `snapshotView(afterScreenUpdates: false)`，加到 `view`（在 collectionView 之上）；若 nil 则跳过动画。
   - **立即**（同一 runloop）执行：
     ```swift
     collectionView.performBatchUpdates({
         let result = viewModel.commitRemoval(plan)
         collectionView.deleteItems(at: [IndexPath(item: plan.removedIndex, section: 0)])
         self.pendingRemovalResult = result
     }, completion: { _ in
         // 用 result.nextIndex 定位；shouldClose → dismiss
         // 动画结束移除 snapshot
         // isRemovalInFlight = false
     })
     ```
     `commitRemoval` 与 `deleteItems` 必须在同一个 block 内；不要等 `flyOut` 完成。
   - snapshot 飞出动画与 batch update 并行（0.25s），不影响数据源。
   - `scrollTo(index:next, animated:false)` 放在 completion；先 `collectionView.layoutIfNeeded()`；校验 `next < items.count`。
   - `prefetchAround(index:)` 加 `guard !items.isEmpty, items.indices.contains(index)`；切片用 `items[index..<min(index+4, count)]`。
   - `cellForItemAt` 加 `guard indexPath.item < viewModel.items.count else { return placeholderCell }`；`willDisplay`/`prefetchItemsAt` 同样。
   - `numberOfItemsInSection` 返回 `max(0, viewModel.items.count)`。
3. `flyOut` 改为只动画 snapshot，不再冻结/移动真实 cell；删除 `flyOut(direction:index:completion:)` 或改成 `animateSnapshotOut`。
4. 连续删除：`isRemovalInFlight` 期间忽略新手势（最多丢一次滑动），比崩溃可接受；动画 0.25s 后恢复。
5. 删除/隐藏后 `refreshChrome` / `refreshFilmStrip` 在 completion 里执行；`filmStrip.reload` 用新的 ids。
6. 多选批量删除：`LibraryViewController.batchDeleteTapped` 只是入队 + 打开 review，不直接操作网格；网格通过 `applyPendingChanges` 的 diffable 快照移除，已有 diffable 保护；补 `removeAll` 与去重测试。
7. `applyRemoval` 的 `performBatchUpdates` 完成回调里如果 `staged.plan.shouldClose`，先 `dismiss` 再清理，避免空 collection view 的 layout。

**验收**：
- 单测 `ViewerRemovalPlannerTests`（≥8 条：首/中/末/唯一/连续两次/plan 不改数组/commit 后 index/回滚）。

## 3. 目标架构

### 3.1 查看器：单一事实来源 + 删除事务

**不变量（invariants）**：
- `I1`：任意时刻 `viewModel.items.count == collectionView.numberOfItems(inSection: 0)`，除了 `performBatchUpdates` 的 block 内部。
- `I2`：`viewModel.currentIndex` 永远在 `0..<items.count`，空数组时为 `0` 且查看器关闭。
- `I3`：任何 cell 的 `itemID` 与 `viewModel.items[indexPath.item].id` 一致；回填前校验 token + itemID。
- `I4`：任何 PhotoKit 请求都有 requestID，可取消；continuation 只 resume 一次。
- `I5`：缩放几何只在 bounds > 0 且 image != nil 时计算；`zoomScale` 永远 finite。

**删除事务状态机**：
```
idle
  └─ planRemoval (enqueue + 计算 plan，不改数组)
       └─ capturingSnapshot (可选)
            └─ applying (performBatchUpdates: commitRemoval + deleteItems)
                 └─ settling (scrollTo next / dismiss / 刷新 filmstrip)
                      └─ idle
```
- `isRemovalInFlight` 保证同时只有一个事务。
- `commitRemoval` 只在 `applying` 内调用一次。

### 3.2 ImagePipeline v2

**协议新增**：
```swift
protocol ImagePipelineProtocol: AnyObject {
    func thumbnail(for id: String, size: CGSize, scale: CGFloat) async -> UIImage?
    func prefetch(ids: [String], size: CGSize)
    func cancel(id: String)
    func cancelAll()
    func fullImage(for id: String, progress: @escaping (Double) -> Void, allowNetwork: Bool) async -> UIImage?
    func videoAsset(for id: String) async -> (asset: AVAsset, audioMix: AVAudioMix?)?
    var diskCacheBytes: Int64 { get }
    func clearCaches()
}
```

**请求层**：
- `ResumeOnce<T>`：`NSLock` + `didResume`；`resume(_:)` 第二次忽略并 `os_log`。
- `PhotoKitImageRequester` 协议（可注入 Fake）：
  ```swift
  protocol ImageRequesting: AnyObject {
      @discardableResult
      func requestImage(for asset: PHAsset, targetSize: CGSize, contentMode: PHImageContentMode,
                        options: PHImageRequestOptions,
                        resultHandler: @escaping (UIImage?, [AnyHashable: Any]?) -> Void) -> PHImageRequestID
      func cancelImageRequest(_ id: PHImageRequestID)

  ```
- `ImagePipeline` 只依赖 `ImageRequesting`；生产用 `PHCachingImageManager`，测试用 `FakeImageRequester`（可手动触发两次回调/取消后回调）。
- 全尺寸请求：`targetSize = min(screenPixel * 1.25, 2048)`；`deliveryMode = .highQualityFormat`；`resizeMode = .fast`；`isNetworkAccessAllowed` 按设置；`progressHandler` 转发。
- 预算：`fullImageCache` countLimit 6 / costLimit 60MB；`AsyncSemaphore(limit: 2)` 限制全尺寸并发；thumbnail 并发 4。
- 预取：`prefetchedIDs` 差量 stop；窗口 7；`prefetchPixelSize` 变化时先 stop 全部再 start。

### 3.3 ZoomableImageCell v2

- 视图层级：`contentView → scrollView → zoomContentView → imageView`；`imageView` 只负责显示，`zoomContentView` 是 `viewForZooming` 返回的 view。
- 布局：
  ```
  viewport = scrollView.bounds
  fit = ZoomGeometry.aspectFitSize(imageSize, viewport)
  zoomContentView.frame = CGRect(origin: .zero, size: fit)
  scrollView.contentSize = fit
  scrollView.contentInset = ZoomGeometry.centeredInset(contentSize: fit * zoomScale, viewport, zoomScale)
  ```
- `scrollViewDidZoom` 只更新 `contentInset`（`UIView.animate` 关闭，避免抖动）。
- 双击：`rect = ZoomGeometry.clampedZoomRect(...)`；`scrollView.zoom(to: rect, animated: !reduceMotion)`；不再二次 `setZoomScale`。
- 最小/最大：1.0 / 5.0；`bouncesZoom = true`；`showsVertical/HorizontalScrollIndicator = false`。
- 图片 nil：`scrollView.isUserInteractionEnabled = false`；显示占位/云下载。
- 复用：`cancelLoad` + `imageView.image = nil` + `resetZoomIfPossible`。

### 3.4 Library 快照协调器

- `LibraryViewModel` 输出 `Snapshot` 值类型（`sections/itemsBySection/queryKey/generation/isIndexComplete`）。
- `LibraryViewController` 持有 `pendingSnapshot: Snapshot?`、`isApplyingSnapshot`。
- `apply(snapshot)`：
  ```
  currentSnapshotQueryKey = snapshot.queryKey
  pendingSnapshot = snapshot
  guard !isApplyingSnapshot else { return }
  drain()
  ```
  `drain()`：取 `pendingSnapshot` → `dataSource.apply(animatingDifferences: shouldAnimate)` → completion → `currentSections/currentItemsBySection = snapshot...` → `syncIndexBar` → `restoreIfNeeded` → `isApplyingSnapshot=false` → 如果 pending 又有新值，继续 drain。
- `shouldAnimate`：仅当 `snapshot.isIncremental && delta < 200 && !isSelecting && !collectionView.isTracking && !collectionView.isDecelerating`。
- 去重：`Snapshot` 构建前 `uniqueByID`；DEBUG `assert`。
- 位置恢复与索引条更新只在 completion 里。

## 7. 风险与平台限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| PhotoKit 回调时序在模拟器/真机不同 | 单次 resume 测试通过但真机仍有边角 | Fake requester 覆盖双回调/取消后回调；真机 trace 验证 |
| iOS 15 `UICollectionViewDiffableDataSource` 对快速 apply 的容忍度低 | 快照串行化后仍可能偶发 | 串行 + coalesce + `animatingDifferences:false`；DEBUG assert；CI 压测 |
| 大图解码内存 | 真机 jetsam | 目标尺寸上限 2048 + 并发 2 + 缓存 60MB + 内存警告清理 |
| `UIScrollView` 缩放几何在不同 iOS 版本有差异 | 捏合手感/边界不同 | `ZoomGeometry` 纯函数固定口径；真机 15/17/18 各测 10 次 |
| 长按 0.15s 与滚动冲突 | 快速滑动误触发选择 | `didMove` 阈值 + 快速滑动不满足 0.15s；UI 测试双向覆盖 |

| 无真机 | 真机崩溃无法本机复现 | `ViewerTrace` + `last-exception.log`；docs/12 真机清单；用户回传日志 |

// ViewerViewModel
struct StagedPlan {
    let action: SwipeAction
    let removedIndex: Int
    let removedItem: PhotoItem
    let plan: ReplacementPlan
}

func planRemoval(action: SwipeAction, forItemID id: String, exitEdge: VerticalEdge?) -> StagedPlan? {
    guard let index = items.firstIndex(where: { $0.id == id }) else { return nil }
    let item = items[index]
    let kind: PendingKind = action == .moveToRecentlyDeleted ? .delete : .hide
    let ok = kind == .delete
        ? reviewSession.enqueueDelete(id: id, originIndex: index)
        : reviewSession.enqueueHide(id: id, originIndex: index)
    guard ok else { return nil }
    let plan = ReplacementPlanner.plan(currentIndex: index,
                                       countAfterRemoval: items.count - 1,
                                       exitEdge: exitEdge,
                                       hasNext: index + 1 < items.count,
                                       hasPrevious: index > 0)
    return StagedPlan(action: action, removedIndex: index, removedItem: item, plan: plan)
}

struct RemovalResult { let nextIndex: Int?; let shouldClose: Bool }

func commitRemoval(_ plan: StagedPlan) -> RemovalResult {
    guard items.indices.contains(plan.removedIndex),
          items[plan.removedIndex].id == plan.removedItem.id else {
        return RemovalResult(nextIndex: nil, shouldClose: items.isEmpty)
    }
    items.remove(at: plan.removedIndex)
    currentIndex = min(plan.plan.nextIndex ?? 0, max(0, items.count - 1))
    isFavoriteCurrent = current?.isFavorite ?? false
    return RemovalResult(nextIndex: plan.plan.nextIndex, shouldClose: plan.plan.shouldClose)
}

// ViewerViewController
private func performStaged(action: SwipeAction, exitEdge: VerticalEdge?) {
    guard !isRemovalInFlight, let item = viewModel.current,
          let plan = viewModel.planRemoval(action: action, forItemID: item.id, exitEdge: exitEdge) else { return }
    isRemovalInFlight = true
    let indexPath = IndexPath(item: plan.removedIndex, section: 0)
    let snapshot = collectionView.cellForItem(at: indexPath)?.snapshotView(afterScreenUpdates: false)
    if let snapshot {
        view.addSubview(snapshot)
        // 动画到屏幕外；不阻塞数据源
        UIView.animate(withDuration: DSMotion.flyOutDuration, animations: {
            snapshot.transform = CGAffineTransform(translationX: 0, y: exitEdge == .top ? -self.view.bounds.height : self.view.bounds.height)
            snapshot.alpha = 0
        }, completion: { _ in snapshot.removeFromSuperview() })
    }
    var result: RemovalResult?
    collectionView.performBatchUpdates({
        result = viewModel.commitRemoval(plan)
        collectionView.deleteItems(at: [indexPath])
    }, completion: { [weak self] _ in
        guard let self, let result else { return }
        self.isRemovalInFlight = false
        if result.shouldClose { self.closeTapped(); return }
        if let next = result.nextIndex {
            self.collectionView.layoutIfNeeded()
            self.scrollTo(index: next, animated: false)
            self.refreshFilmStrip(current: next)
            self.prefetchAround(index: next)
        }
    })
}

public enum ZoomGeometry {
    public static func aspectFitSize(imageWidth: Double, imageHeight: Double,
                                     viewportWidth: Double, viewportHeight: Double) -> DoubleSize {
        guard imageWidth > 0, imageHeight > 0, viewportWidth > 0, viewportHeight > 0,
              imageWidth.isFinite, imageHeight.isFinite else { return .zero }
        let scale = min(viewportWidth / imageWidth, viewportHeight / imageHeight)
        return DoubleSize(width: imageWidth * scale, height: imageHeight * scale)
    }
    public static func centeredInset(contentWidth: Double, contentHeight: Double,
                                     viewportWidth: Double, viewportHeight: Double,
                                     zoomScale: Double) -> DoubleInsets {
        let w = max(0, (viewportWidth - contentWidth * zoomScale) / 2)
        let h = max(0, (viewportHeight - contentHeight * zoomScale) / 2)
        return DoubleInsets(top: h, left: w, bottom: h, right: w)
    }
}
