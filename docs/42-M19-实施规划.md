# docs/42 — M19 实施规划：行带轨迹滑选（右侧下滑选整行）

> 状态：**T01 已复核修订（2026-11-20，见 §10 T01 修订记录）**，作为 T02–T10 唯一事实源；与 `docs/45-M19-审查报告.md` 冲突处以 T01 实测为准。
> 用户语义：**滑动多选时手指滑到哪就选到哪，且「右侧下滑 = 选整行」；不要再要求逐格触摸；允许滚动；不要框选。**
> 基线：iOS 16.0 / Swift 5.9+ / UIKit 网格 + Diffable / 0 三方依赖 / `PhotoDeskCore` 零 Apple 依赖。

## 1. 选择语义（本轮唯一真值）

### 1.1 行带定义

**选择单元 = 行带（row band）**：某个 section 内的**一整行**，包含该行在网格上的所有列。

| 概念 | 定义 |
|---|---|
| 行带 | `(section, row)`，items 为 `row*columns ..< min((row+1)*columns, itemCount)` |
| 平铺序 | 先按 section 升序，再按 row 升序，把所有行带排成一个一维序列（跨月自然衔接） |
| 行带索引 | 该一维序列中的下标；轨迹事务按它单调推进 |
| 展开 | 行带 → 该行全部 item → `dataSource.itemIdentifier` → assetID 有序数组 → `SlideSelectTrail.consume` |

### 1.2 行为表

| 场景 | 行为 |
|---|---|
| 多选模式，长按后从**右列**向下拖 3 行 | 该 3 行**全部列**选中；计数 = 3 × columns（末行不满按实际） |
| 多选模式，长按后从**左列**向下拖 | **同样整行**（行带语义左右一致；见 §9 冲突声明） |
| 横向拖过一行 | 该行整行选中（不是只选划过的格） |
| 斜向拖 | 手指经过的行带序列全部选中（含中间行），不补全矩形 |
| 回滑（反向拖） | 按行带出栈：本次新增的行逐行取消；手势前已选的行/格保持 |
| 从已选 cell 起手 | 取消模式：滑过的行带整体从选中集移除；回滑把整行恢复 |
| 跨月份分组 | 中间完整经过的 section 整段选中（行带序列天然覆盖） |
| 单月 scope | 只在当月行带内生效，scope 外 item 过滤 |
| 末行不满 | 只展开真实存在的 item，不补空位 |
| 纵向**直接**快速滑（未长按） | **滚动**，计数不变（用户要求「允许滚动」） |
| 拖到上下 60pt 边缘 | 自动滚动；内容流过时按行带顺序继续入栈 |

### 1.3 为什么不是「矩形/线段」

- 线段：只命中手指真正穿过的格 → 就是当前「必须每一格都摸到」的根因，**必须替换**。
- 矩形：会把没经过的格也选进来（历史已否决），**继续禁止**。
- 行带：与行号一一对应，纵向拖动天然覆盖整行，横向拖动也不会漏列。

## 2. 不变量（违反即打回）

1. **行带是唯一选择单元**；生产路径不得再以「线段穿过的 cell 集合」直接作为选择结果。
2. **允许滚动**：未长按的纵向拖动必须继续走滚动让位（`releaseScroll`），计数不变。
3. **不做矩形**：不得恢复 `HitRect`/`hitTest(rectInContent:)`/选框覆盖层。
4. **不用奇偶 toggle**：回滑按路径出栈，不是把同一格 toggle 回来。
5. **不用双指规则**：`minimumNumberOfTouches = 2` 在 `PhotoDesk/` 下 0 命中。
6. **不接管系统多选**：不启用 `collectionView(_:shouldBeginMultipleSelectionInteractionAt:)`，选中集唯一事实源是 `SelectionState`。
7. **唯一写入口**：行带展开 → `SlideSelectTrail.consume` → `SlideSelectDelta` → `SelectionState.applyDelta` → 可见 cell diff + 计数。
8. **几何来源**：行带几何一律来自真实 `layoutAttributes`（`firstRowMinY/rowHeight/itemCount/columns`），禁止用 `DSSpacing` 推算。
9. **iOS 16**：不引入 iOS 17+ API、不写双实现；Core 只 `import Foundation`；AGENTS 两条红线不变（删除仍只到「移到最近删除」）。

## 3. 目标架构

```text
UIKit 触摸
  ↓ LibrarySelectionController（窗口坐标、CADisplayLink、事件映射）
SelectionGestureMachine（长按/方向锁/边缘进出/触觉节流；本轮不改状态表）
  ↓ rowBandHitProvider(from, to)
GridHitTester.rowBandHitTest(from:to:)（真实 attributes → RowBandMap）
  ↓ [IndexPath]（按行带顺序展开，整行全列）
dataSource.itemIdentifier → [assetID]（有序）
  ↓
SlideSelectTrail.consume（路径栈 + 回滑截断 + 净 delta）
  ↓ add/remove
SelectionState.applyDelta → applySelectionChanges(previous:current:) → 可见 cell diff / 计数
```

### 3.1 Core 新增（Foundation only）

- `RowBandMap.swift`
  - `RowBandSection`：`section: Int, itemCount: Int, columns: Int, rowHeight: Double, firstRowMinY: Double, headerHeight: Double`
  - `RowBandMap.Band`：`section: Int, row: Int, items: [Int]`
  - `init(sections: [RowBandSection])`：按 section 顺序平铺；空 section 跳过；`itemCount == 0` 跳过
  - `bandIndex(atContentY:clipTop:) -> Int?`：y → 行带下标；粘性头下缘以下才可命中；落在间距/行底时钳到最近行
  - `bandSequence(from:to:) -> [Int]`：包含两端、保持方向、越界钳制
  - `items(forBandIndices:) -> [RowBandItem]`：`RowBandItem(section:item:)`，行内列升序、去重、保持输入顺序
- `RowBandExpander.swift`（可选，若 T01 判定放 App 更合适则记录理由）
  - `expand(bands:scope:itemID:) -> [String]` 需要 App 提供 `(section,item)->String?` 闭包；若 Core 不便持有映射，则只输出 `RowBandItem`，由 App 映射。
- `SlideSelectConfig.swift`：补 `rowBandSnapTolerance`（y 落在行间空隙时的吸附容差）、`rowBandMaxExpandPerFrame`（单帧展开上限，防异常跳变卡顿；默认 0 = 不限，由 T01 实测后定）。

### 3.2 App 改造

### 3.3 手势仲裁（本轮不改状态机）

现状已满足：长按 0.28s → `armed` → 任意方向拖 → `dragging`；未长按的纵向拖 → `releaseScroll` 交还滚动。
→ **M19 不改 `SelectionGestureMachine` 行为，只改命中粒度**。若 T01 实测发现「长按后纵向拖仍被滚动抢走」，只允许改 App 层手势代理/让位顺序，并在报告里写证据。

## 10. T01 修订记录（2026-11-20，依据 docs/45-M19-审查报告.md 实测）

1. **`RowBandExpander.swift` 不新增**（§3.1「可选」裁决）：App 侧 `GridHitTester.rowBandHitTest` 输出 `[IndexPath]`，经 `dataSource.itemIdentifier` 映射 assetID；Core 只输出 `RowBandItem(section:item:)`。理由：App 已有 Diffable 映射通道，Core 持有 id 闭包徒增耦合（红线 2 输入输出保持纯数值）。
2. **`rowBandMaxExpandPerFrame` 定值 0（不限）**：自动滚动每帧位移被 `SlideSelectConfig.minStep/maxStep`（2–12pt）钳制，单帧行带跨度天然受控；常量位保留（T02 落地），T07 性能实测异常才启用。
3. **补充行为表「起点在空白」**：空白起手不进入轨迹——`SelectionGestureMachine.handleTouchDown` 对 `hitID == nil` 忽略，`gestureRecognizerShouldBegin` 要求 `indexPathForItem(at:) != nil`，双重闸门现状即满足，行带展开以锚点存在为前提，零改动。
4. **`hitTestLine` 保留为降级路径**（§3.2 微调）：不标 deprecated 立即删除——`LibraryGridGeometryTests` 的暴力基准与粘性头回归锁依赖其口径，T07 视引用与覆盖决定去留；`audit-m19.ps1` 的 `info-hitTestLine-refs` 持续跟踪，`production-trail-provider-band`（B2）确保生产主路径切 `rowBandHitTest`。
5. **`RowBandSection.headerHeight` 传递方式确认**：Core 只收 `Double`；App 侧换算（先例：`GridHitTester` 缓存 `headerNaturalMinY = firstRowMinY - DSSpacing.monthHeaderHeight`），Core 零 `DSSpacing` 依赖，红线 2 不破。
6. **静态审查基线**：`audit-m19.ps1`（24 条检查）在改造前报 5 条 BLOCKING FAIL + 6 条 PRESENT FAIL（红基线，`artifacts/audit/m19/baseline-A|B`，确定性验证见同目录 `determinism.txt`）——与 §6 文件改造清单一致，作为 T02–T08 完成判据。
