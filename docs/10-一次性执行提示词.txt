- 第三方依赖：0 个；只用系统框架；完全离线，禁止 URLSession 外发、禁止分析/广告 SDK。
- Bundle ID：com.example.PhotoDesk；DEVELOPMENT_TEAM 从环境变量注入。
- 本机：Windows 10 原生，无 Xcode、无 iOS 模拟器。**本机不能编译 iOS，不要尝试 xcodebuild / simctl。**
- 本地唯一可跑的测试：Docker 容器 swift:6.0-noble，入口：
  powershell -ExecutionPolicy Bypass -File scripts/test-core.ps1
- iOS 编译/测试/出包：GitHub Actions（macos-14，Xcode 15.4，iOS 15.5 模拟器），workflow：.github/workflows/ios.yml。
- 仓库已配置：origin = https://github.com/c4c-club/PhotoDesk.git；gh CLI 已安装并登录（gh 2.103+）。
- 本机未安装 AltServer / idevice_id；**不要假装真机验证**。模拟器/CI 能验证的必须由你亲自验证；真机专属项输出清单。
- 出包：CI 产出未签名 `PhotoDesk-unsigned-ipa`，用户在 Windows 用 AltStore/Sideloadly 自签安装；你只负责
  产出 IPA + SHA256 + docs/12，不负责替用户签名，也不要把“未验证真机”写成已验证。
- 删除平台事实：`PHAssetChangeRequest.deleteAssets` 每次调用都会触发系统确认，公共 API 不能关闭；
  因此**禁止在逐张滑动路径调用**。正确做法是 D16 的会话暂存 + 结尾一次批量提交；系统确认从 N 次降到 1 次。
- 隐藏平台事实：`isHidden` 是公开 API，通常无系统确认；真机若出现确认，也只允许批量一次，不能逐张调用。
- `PhotoDeskCore` 纯逻辑除现有模块外，还要放 `ReviewSession` / `ReplacementPlanner` / `BatchCommitPlanner`，
  并为它们写 XCTest。
- 不要安装 Ubuntu、不要迁移 Linux、不要用 Hackintosh/macOS 虚拟机/Windows 原生 Swift 工具链。

两条红线（违反即打回，任何情况下不得突破）：
1. 永不永久删除：应用内所有“删除”只能走 `PHAssetChangeRequest.deleteAssets` → 系统「最近删除」（30 天）。
   禁止永久擦除、禁止清空「最近删除」、禁止绕过系统回收站、禁止把删除实现成沙盒内删除。
   UI 文案统一说「移到最近删除」，不得出现「彻底删除」「永久删除」（否定句说明除外）。
2. `PhotoDeskCore/` 零 Apple 依赖：只能 import Foundation；禁止 import UIKit/SwiftUI/Photos/PhotosUI/
   Vision/CoreImage/Accelerate。输入用基础类型；纯逻辑（手势判定/日期分组/哈希/去重/选择状态/位置距离/
   统计聚合）必须放 PhotoDeskCore 并写 XCTest；App 侧只做类型适配。

其他硬约束：
- iOS 15 API 黑名单：NavigationStack / NavigationPath / PhotosPicker(SwiftUI) / ShareLink / Swift Charts /
  @Observable / @Bindable / ContentUnavailableView / .scrollContentBackground / .scrollTargetBehavior /

  需要新 API 时写 `if #available(iOS 16, *) { ... } else { ... }` 双实现。
- 网格/全屏浏览器必须用 UIKit（UICollectionView + Compositional Layout + Diffable DataSource + Prefetching）；
  不要改成 SwiftUI LazyVGrid（主库性能不达标）。
- 所有 PhotoKit 写操作必须在 `PHPhotoLibrary.shared().performChanges` 内并处理 completion error。
- 主网格 `includeHiddenAssets = false`；「已隐藏」scope 才为 true。
- 图片加载必须走 ImagePipeline，禁止在 View 里直接 requestImage。
- 新增文件必须加入 Xcode target membership（XcodeGen 下自动包含，注意 excludes）。
- 不新增第三方依赖；不新增网络权限；不新增 Capability（免费签名会失败）。
- 每个文件顶部写一行 `// MARK: - 职责说明`；颜色/字体/间距只用 DesignSystem token；禁止 try! / 强制解包

D01 查看大图永远显示最新一张
- 现象：点任意缩略图，查看器总停在第 1 张（最新）。
- 根因：ViewerViewController 在 viewDidLoad 里对未布局的 collectionView 调 scrollToItem；初次布局后
  scrollViewDidScroll 把 page=0 写回 currentIndex；跨层传的是扁平 index 而非 assetID。
- 必须做到：查看器用 `ViewerContext(items:startItemID:)` 按 assetID 定位；首次 viewDidLayoutSubviews
  设置 contentOffset；滚动回调只在 isTracking || isDecelerating 时更新 index；程序化滚动有标志位。
- 验收：点第 8 张，DEBUG 横幅显示的 assetID 与第 8 张一致；左右滑动顺序正确。

D02 图片显示错误导致删错图片
- 根因：删除后只改 ViewerViewModel.items，不通知 UICollectionView；加载 token 按 index 不按 cell+assetID；
  ZoomableImageCell 复用不清图；执行期间 currentIndex 会漂移。
- 必须做到：
  1) 删除/隐藏改为“会话暂存”（见 D16）：滑动只入队 + 本地移除，不 await PhotoKit；
  2) VM 返回 ReplacementPlan（nextIndex/entryEdge），VC 用 performBatchUpdates 删除 cell，按 entryEdge 做 snapshot 补位；
  3) cell 级加载 token，回填前校验 cell.itemID == item.id；
  4) ZoomableImageCell.configure 设置新 item 时清空 imageView、resetZoom、取消旧任务；
  5) 删除/隐藏保持当前 index（原位置变成下一张），不要 currentIndex+1 跳一张；最后一张回退一张；空列表关闭查看器；
  6) 上滑→下一张从底部补位，下滑→下一张从顶部补位，末尾回退时从与飞出方向相同的一侧补位；
  7) 预取后 3 张，补位不得显示上一张或白屏。
- 验收：连续标记 3 张，逐张核对 assetID；删除后不跳图、不显示上一张；左右滑不串图；补位方向正确。

D03 删除时“是否允许照片管家删除”提示
- 平台事实（已核实）：`PHAssetChangeRequest.deleteAssets` 必然触发 iOS 系统确认弹窗，公共 API 无法关闭/
  自定义/预授权。市面 App 也没有绕过：Swipewipe 是“标记→review→批量删除”，Slider 仍会出现
  “Allow Slider to delete this photo?”。禁止私有 API、非 PhotoKit 删除、沙盒删除或永久删除。
- 真正根因：当前每滑一张就调用一次 deleteAssets（ViewerViewModel.moveToRecentlyDeleted），所以每张弹一次；
  这不是 App 二次确认的问题。
- 必须做到（会话暂存 + 一次批量提交）：
  1) 新增 PhotoDeskCore/ReviewSession.swift：pendingDelete/pendingHide 队列（assetID/kind/originIndex/时间）；
  2) 新增 PendingActionStore（Application Support/PendingActions/session-v1.json，原子写、损坏备份、上限 10,000）；
  3) 新增 ReviewSessionController：enqueueDelete/enqueueHide/unmark/commitDeletes/commitHides；
  4) 滑动删除只 enqueue + 本地移除 + Toast「已标记待删除 · 撤销」，全程不调用 deleteAssets；
  5) 用户点「完成整理」→ SessionReviewView → 「全部移到最近删除」→ 一次 `PHAssetChangeRequest.deleteAssets`
     提交所有 id；系统确认恰好 1 次（单批上限内；超过上限按批，每批一次，不是每张）；
  6) 系统确认取消：队列保留，提示「系统未允许删除，N 张仍在待删除」；不丢数据；
  7) 移除 App 自己的删除二次确认（presentConfirmation 删除分支、batchDeleteTapped alert、CleanupView
     confirmationDialog）；**不保留 confirmDestructive/confirmDeleteInApp 设置开关**；
     SwipeGestureEngine.config 的 confirmRequired 固定 false 或删除该参数；
  8) `deleteAssets` 全仓库只允许出现在 PhotoWriter.moveToRecentlyDeleted；其他位置出现即失败。
- 验收：连续下滑 20 张 → 0 次系统弹窗、计数 20；提交 → 恰好 1 次系统确认；取消 → 20 张仍 pending；
  杀 App 重启 → 队列恢复；多选 100 张删除 → 1 次确认。
- 如果要求“连最后 1 次也没有”：公共 API + 真删除做不到。只能改成“仅隐藏、不释放空间”或接受批量 1 次；
  不要用私有 API，不要假装能做到。

D04 隐藏时“是否允许照片管家隐藏”提示
- 从代码看是 App 自己的 UIAlertController（SwipeAction.isDestructive 把 .hide 也标成破坏性；
  SettingsStore.confirmDestructive 默认 true）；先移除。`isHidden` 是公开 API，通常无系统确认；
  真机若出现系统确认，按“批量一次”处理，不绕过。
- 必须做到：
  1) SwipeAction.isDestructive 只保留 .moveToRecentlyDeleted；隐藏/批量隐藏不弹任何 App 确认；
  2) 隐藏走 ReviewSession.enqueueHide：滑动只入队 + 本地移除 + 补位，不等待 PhotoKit；
  3) 在“完成整理/进入 Vault/App 进后台/队列到 500”时一次 `performChanges` 批量 isHidden=true；
  4) VaultViewModel 合并 pendingHideIDs，进入 Vault 前 flushHidesIfNeeded，未提交也能查看；
  5) 取消隐藏立即 setHidden(false)，失败恢复 item；
  6) 文案「已隐藏到系统「已隐藏」相册 · 撤销」；隐藏不等于删除，不释放空间。
- 验收：连续下滑隐藏 20 张 → 0 次 App 弹窗、画面连续补位；进入 Vault 能看到 20 张（含 pending）；
  提交只发生一次批量 performChanges；系统「已隐藏」可见；若系统确认存在，只 1 次不是 20 次。

- 验收：隐藏 1 张 → 工具→已隐藏 → 看到 → 点开大图 → 取消隐藏 → 列表空、主库恢复。

- 现状：BiometricGate 只在保险箱用，且模拟器静默放行；没有 App 启动锁；没有失败/不可用态；没有后台遮罩。

  4) 设置→隐私与锁定新增启动锁、保险箱锁、立即锁定、宽限时间；

  UI 显示环形进度 + 已统计 N/M + 取消；

  未知大小计数脚注。
- 验收：mock 数据 5 秒内出结果；真实 5,300 张 <90 秒；取消立即停止；缓存命中 <1 秒；绝不永久转圈。

D16 会话式无感整理（暂存删除/暂存隐藏/智能补位）——2026-11-03 补充，优先级最高
- 目标：上下滑期间不做任何 PhotoKit 写操作；只做本地队列 + 乐观 UI + 预取补位。删除在会话结束
  一次批量提交；隐藏按队列批量提交。连续滑 100 张不应出现 100 次系统弹窗，也不应每张等待写库。
- PhotoDeskCore 新增（先写测试）：
  1) ReviewSession.swift：PendingEntry(assetID/kind/originIndex/markedAt)、pendingDeleteIDs/pendingHideIDs、
     markDelete/markHide/unmark/removeCommitted、上限 10,000、Codable；
  2) ReplacementPlanner.swift：plan(currentIndex,countAfterRemoval,exitEdge,hasNext,hasPrevious) ->
     ReplacementPlan(nextIndex,entryEdge,shouldClose)；
  3) BatchCommitPlanner.swift：5,000 分批、缺失 id、取消、幂等。
- App 层新增：
  1) PendingActionStore：Application Support/PendingActions/session-v1.json，原子写、损坏备份、
     0.2s debounce、启动恢复、不新增 Core Data 实体；
  2) ReviewSessionController（@MainActor）：enqueueDelete/enqueueHide/undoPending/commitDeletes/
     commitHides/flushHidesIfNeeded；pendingDeleteCount/pendingHideCount/isCommitting/commitProgress；
  3) BatchCommitCoordinator：删除时一次 deleteAssets；隐藏时一次 setHidden；安全副本统一在提交前做；
  4) SessionReviewView：待删除/待隐藏缩略图、逐张恢复、继续整理、全部移到最近删除、全部隐藏、关闭；
  5) SessionBadgeView：照片库/查看器顶部「待删除 N / 待隐藏 M」。
- 交互：
  1) 上滑/下滑删除或隐藏 → 同步入队（<16ms）→ 从 items 移除 → ReplacementPlan → 飞出 + 下一张补位；
  2) Toast「已标记待删除 · 撤销」/「已加入待隐藏 · 撤销」；顶部计数 +1；
  3) 补位规则：上滑→底部、下滑→顶部、末尾回退→与飞出同侧、工具栏无方向→底部、空列表→关闭；
  4) 滑完或点「完成整理」→ SessionReviewView；用户可恢复任意项；
  5) 「全部移到最近删除」→ 一次系统确认；取消→队列保留；成功→Toast 并清空；
  6) 杀 App 重启→恢复队列，不自动提交、不自动弹系统框；
  7) 网格立即排除 pendingDelete/pendingHide；Vault 合并 pendingHide；全选/筛选不包含 pending；
  8) 进入 Vault、离开会话、App 进后台时 flushHidesIfNeeded。
- 性能硬指标：入队+动画 <16ms；连续 100 次 0 系统弹窗、0 主线程 >50ms、内存增长 <20MB；
  补位首帧命中缓存 <100ms；5,000 张连续整理 10 分钟无泄漏；杀进程恢复 10,000 条 <200ms。
- 测试：ReviewSessionTests/ReplacementPlannerTests/BatchCommitPlannerTests；
  ReviewSessionControllerTests（20 次滑动 0 次 writer、提交 1 次、取消保留、重启恢复）；
  SessionUITests（20 次滑动 0 alert、提交 1 alert、取消、重启、补位方向）；性能测试 100 次滑动。
- 验收：连续下滑删除 20 张 → 0 弹窗、计数 20、每次立即补位；提交 → 1 次系统确认；
  取消 → 队列保留；重启 → 恢复；隐藏 20 张 → Vault 可见；多选 100 张 → 1 次确认；全程不因弹窗/等待中断。
