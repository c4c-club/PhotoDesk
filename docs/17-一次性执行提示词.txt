【R01 · 无法查看大图（P0）】
现象：网格缩略图正常，点开全屏黑屏/空白；present 信息/编辑/分享或切 Tab 返回后白屏；iCloud 图
纯黑且无下载按钮。
代码证据（4 个独立根因）：
  A1 决定性：ZoomableImageCell.swift 的 imageView 只在 init 里 addSubview；约束表里没有 imageView /
     zoomContentView 约束；layoutImageContent 只设 zoomContentView.frame 与 scrollView.contentSize；
     configure / applyDownloadedImage / layoutSubviews 都不设 imageView.frame。UIImageView() 默认
     frame=.zero、autoresizingMask=.none → 恒零尺寸，赋 image 也不可见。对照 PhotoGridCell、
     FilmStripView 都有四边约束，精确解释「缩略图可见、全屏看不到」。
  A2：AssetRepository.isCloudOnly 恒 false；ImagePipeline.fullImage 只查 PHImageResultIsDegradedKey，
     不查 PHImageResultIsInCloudKey；禁网时返回 nil → applyDownloadedImage 不调用；
     ZoomableImageCell.configure 的 cloudBox 因 isCloudOnly=false 恒隐藏 → 无占位无自救。
  A3：ViewerViewController.viewDidDisappear 无条件 pipeline.cancelAll()（单例），且全类无
     viewWillAppear/viewDidAppear；任一 present 或切 Tab 取消在途加载且返回后不重挂。
  A4：setupCollectionView 在 viewDidLoad 设 layout.itemSize = view.bounds.size；
     viewDidLayoutSubviews 从不刷新 itemSize（仅旋转时改）；fullScreenCover 首布局 bounds 为
     .zero/占位值 → 全部 cell 零尺寸、positionAtCurrentIndex 与 itemSize 失配 → 整页空白。
  附带：ImagePipeline.registerFullImageRequestID 在 requestImage 返回之后，而 ImageRequesting 对
     缺失资产同步回调 nil → unregister 先跑、陈旧 requestID 残留、cancelAll 取消错对象；
     ResumeOnce 取消路径没有强制 resume(nil)，PhotoKit 不再回调时 checked continuation 悬挂
     （SWIFT TASK CONTINUATION MISUSE）；ViewerContainer.updateUIViewController 空实现、onClose
     全项目无赋值 → fullScreenCover(item:) 再次打开复用旧 ViewerViewModel；越界 cellForItemAt
     返回未 configure 的空 cell。
修复：
  1) imageView 加四边约束到 zoomContentView（translatesAutoresizingMaskIntoConstraints=false），
     或在 layoutImageContent 设完 zoomContentView.frame 后同步 imageView.frame = zoomContentView.bounds。
  2) viewDidLayoutSubviews 检测 layout.itemSize != view.bounds.size 时赋值 + invalidateLayout()，
     用 isProgrammaticScroll 包住 positionAtCurrentIndex 重定位。
  3) fullImage 回传 inCloud 状态（App 层新 FullImageResult 或独立 cloud 回调，Core 不参与），
     VC 收到后 cell.showCloudPlaceholder()：占位 + 下载按钮 + 进度 + 回填。
  4) viewDidDisappear 仅在 isBeingDismissed || isMovingFromParent 时 cancelAll()；新增
     viewWillAppear 对 currentIndex 对应 cell 重挂 loadImage。
  5) ViewerContainer.updateUIViewController 在 context 变化时重建/更新 ViewModel，onClose 复位
     viewerContext；ResumeOnce 取消强制 resume(nil)；requestID 注册移到 requestImage 之前并用
     generation 令牌防陈旧注销；越界分支返回已 configure 的空态 cell。
不变量：
  I5′：imageView.frame.size == zoomContentView.frame.size > 0 且 scrollView.contentSize 与之相等；
  isUserInteractionEnabled == (image != nil && bounds > 0 && contentSize > 0)；
  itemSize == collectionView.bounds.size；image == nil 必有可见占位 + 下载入口；
  每次 appear 时当前 cell 必有 image 或有在途 Task。
先写失败测试：testImageViewFrameMatchesZoomContentViewAfterImageApplied、
  testViewerShowsNonBlankImage（截图中心像素 ≠ DSColor.bgViewer）、testFirstLayoutItemSizeEqualsBounds、
  testZeroBoundsThenLayoutRecovers、testCloudOnlyAssetShowsDownloadButton、
  testFullImageReportsInCloud、testPresentInfoThenDismissRestoresImage、testViewerShowsImageOnOpen。

【R02 · 捏合缩小放大必崩溃（P0）】
代码证据：
  B1 最可疑必崩链：ViewerViewController 的 pan.maximumNumberOfTouches = 1 使
     gestureRecognizerShouldBegin 里 pan.numberOfTouches > 1 成死代码；cell.isZoomed 只在
     shouldBegin 起始判一次、此刻 zoomScale == 1 → 放行；shouldRecognizeSimultaneouslyWith
     无条件 true → 捏合两指中单指移动触发 onPan 垂直锁 → collectionView.isScrollEnabled=false →
     triggerAction → performStaged → performBatchUpdates { commitRemoval + deleteItems }
     在 UIScrollView 缩放事务中执行；shouldBegin 还用 viewModel.currentIndex 取 cell，翻页时与
     可见 cell 不一致。AGENTS.md §7「缩放时检查 zoomScale <= 1.01」形同虚设。
  B2：ZoomableImageCell.applyDownloadedImage 先 isUserInteractionEnabled = true，再 resetZoom()
     / layoutImageContent()（零 bounds 都直接 return）；叠加 A4 → viewForZooming 返回
     frame/contentSize 都 .zero 的 view 却允许捏合 → 内部除零 → CALayer position contains NaN。
  B3：updateCenteringInset 读 zoomContentView.frame.width/height（缩放中 frame 是 transform 后
     包围盒）再乘 zoomScale → 双倍缩放 inset；scrollViewDidZoom 内改 contentInset 与内部 offset 竞态。
  B4：ZoomGeometry.clampedZoomRect 要求 focusX/focusY > 0，点 x=0 / y=0 双击静默失败。
  假绿：ViewerViewController.setZoomCallback 先 guard scale.isFinite 才写 debugZoomScale，
     StabilityUITests「横幅不含 nan/inf」恒真；testPinchZoom20Times 只验 app.state，XCUITest
     合成 pinch 打在 ViewerRoot 未命中 cell 内 UIScrollView；Viewer-Debug 横幅全在 #if DEBUG，
     Release IPA 不编译；全项目零「图像可见」断言。
修复：
  1) 手势互斥：shouldRecognizeSimultaneouslyWith 对 UIPinchGestureRecognizer /
     numberOfTouches >= 2 返回 false；gestureRecognizerShouldBegin 增加
     cell.isZooming || zoomScale > 1.01 判定并在 .changed 持续复查；引入
     idle → pinchActive → idle 状态机，pinchActive 期间 executeAction / performStaged /
     triggerAction / performBatchUpdates 一律 guard 早退。
  2) 交互护栏：isUserInteractionEnabled 只在 image != nil && bounds > 0 && contentSize > 0 时由
     layoutImageContent 成功后置 true；resetZoom 用 ZoomGeometry.sanitizedScale 兜底；
     viewForZooming 在零 contentSize 时返回 nil。
  3) updateCenteringInset 改用 zoomContentView.bounds.size，且只在 !zoomBouncing 时更新 inset；
     入参先做有限值/正数钳制。
  4) ZoomGeometry.clampedZoomRect 把 focusX/focusY > 0 放宽为 [0, size] 钳制（0 边界合法），
     保留 NaN/∞/负值守卫并补单测。
  5) 可观测：去掉 setZoomCallback 的 scale.isFinite 过滤（NaN 原样写横幅）；Release 也把
     zoom=... / img=ok|nil 写进 ViewerTrace；testPinchZoom20Times 增
     XCTAssertTrue(banner.label.contains("img=ok"))、XCTAttachment 像素比对、pendingDeleteCount == 0；
     新增真捏合命中 cell 内 UIScrollView 的用例，不得再以 app.state 单独作为证据。
  6) 取证链：ViewerTrace 改异步串行队列写盘，补 scrollViewDidZoom / applyDownloadedImage /
     viewWillAppear 面包屑；DiagnosticsView.export() 把 last-exception.log + viewer-trace.log
     加入 activityItems；AppCrashLogger 补信号级/Swift fatal 兜底并写清能力边界（不宣称能抓 jetsam）。
不变量：缩放事务与删除事务互斥；捏合全过程 pendingDeleteCount 不变、零删除事务、

【R03 · 上次位置记不准、冷启动需要等待跳转（P0）】
代码证据：LibraryPositionStore 的 LibraryPosition v2 已含 assetID / sectionID /
  itemIndexInSection / offsetRatio / savedAt / schemaVersion，键 library.lastPosition.v2.<queryKey>
  —— 数据结构够用，问题不在「存」。LibraryViewModel 首屏只推 500 张，其余 500/批后台补齐；
  reloadForQuery 重置 isIndexComplete=false；LibraryViewController.applySnapshot 等
  dataSource.apply completion 才更新 currentSnapshotQueryKey 再 restorePositionIfNeeded；
  restorePositionIfNeeded 在 isIndexComplete == false 时挂 pending → 两阶段可见跳转；
  scrollViewDidScroll 的 0.3s Timer / didEndDragging / didEndDecelerating 在恢复期间会把中间位置
  当成「上次位置」回写，覆盖锚点。iOS 15 SwiftUI TabView 切页不保证内嵌 VC 的
  viewWillDisappear 触发，另靠 scenePhase / willResignActive 保存。
修复（锚点优先 + 首帧遮罩；允许等效实现，但不变量不可让步）：
  1) 启动读 LibraryPositionStore.load(queryKey:) 得锚点；LibraryViewModel.prepare 首屏不再固定
     「最新 500」：用锚点 assetID 的 creationDate / 在完整 PHFetchResult 中的全局 index 求「锚点
     窗口」（以锚点为中心前后各半批，仍遵守每批 <=500、分批 fetch），把锚点所在批次作为第一批推给数据源。
  2) dataSource.apply completion 且 currentSnapshotQueryKey 更新后，用锚点 assetID 精确
     indexPathForItem + offsetRatio 调 scrollToItem(animated:false)；从首帧到定位完成期间复用现有
     加载骨架/遮罩盖住网格，isRestoringPosition = true，用户看不到中间位置；定位完成才移除遮罩。
  3) 后台继续 500/批补齐其余月份（保留 startIndexCompletion）；用 Diffable 增量 append；若在锚点
     之前插入 section，按插入高度同步补偿 contentOffset。
  4) isRestoringPosition 期间禁用 savePositionNow 的 Timer / didEndDragging / didEndDecelerating
     回写，恢复完成后再启用。
  5) 锚点 asset 已删除/隐藏/不在当前 query 时回退 sectionID + itemIndexInSection + offsetRatio
     的最近可用项；仍失败则落最新月份并写一次新锚点。任何回退都不得触发动画或 showJumpBanner

【R08 · 向下滑动多选做成 iOS 原生相册一样】
代码证据：LibraryViewController 的 selectionOverlay（DSColor.tint 15% 底 + 1pt 边框）直接加到
  view；onBoxLongPress .changed 用 gesture.location(in: collectionView)（content 坐标）构造
  selectionOverlay.frame（overlay 挂在 view = 屏幕坐标）→ contentOffset 后框选框必然错位；
  targetPath = indexPathForItem(at: location) 命中错误；nearestIndexPath(to:) 把 y 当 content
  坐标且未转换；orderedIDs 走 SelectionRange.ids 只做一维连续区间；
  selectionState.replaceSelection(boxBaseSelected + range) 永远只加不减（往回拖不会取消）；
  boxAutoScrollTick 用 lastBoxPoint.y - collectionView.contentOffset.y 混用坐标，setContentOffset
  后仍用旧 start/lastBoxPoint 重算。PhotoDeskCore 的 SelectionRange 是双向一维区间，
  SelectionPolicy 只过滤 scope / 去重，无二维矩形/反选语义。PhotoGridCell.configure 把
  accessibilityValue 重置成 item.id，cell 复用后选中态后缀可能丢失。
iOS 原生相册语义（目标）：长按锚点后拖动，按拖曳矩形与每个 cell 实际可见 frame 的二维相交实时
  增减选中；拖过未选中的加入、往回拖自动移除；手指到上下边缘自动滚动且命中集合随 contentOffset
  重算；松手框选框消失、滚动恢复、选中态稳定；绝不出现「框选框与手指错位」「选中只增不减」。
修复：
  1) 单一坐标系：手势点统一取 gesture.location(in: view) 作为「手指/屏幕」坐标；
     boxStartPoint / lastBoxPoint 全存该坐标；selectionOverlay（挂在 view）直接用该坐标画 rect。
     命中换算改用 view.convert(point, to: collectionView) 得 content 坐标，或（推荐）把
     collectionView.indexPathsForVisibleItems 的 layoutAttributesForItem(at:)?.frame 逐个 convert
     到 view 坐标后与 rect 相交 —— 后者彻底避开 contentOffset 混淆。
  2) 二维相交下沉 Core：在 PhotoDeskCore 新增纯逻辑（只 import Foundation，用自定义
     struct Rect/Point 的 Double 字段，不传 CGRect/CGSize/UIImage/PHAsset），例如
     GridHitRegion.hitIDs(cells: [GridCellRect], rect: Rect, threshold: Double) -> Set<String>；
     处理 0/负/NaN/∞、边界相交阈值（进 DesignSystem/SwipeConfig）、乱序与跨 section。
     App 层只做 CGRect → Rect 适配。SelectionPolicy 复用 replaceSelection，不再累加 range。
  3) 基线重算语义：.began 记录 boxBaseSelected（进入多选前的选中集）与 boxAnchorID；
     每帧 selectionState.replaceSelection(boxBaseSelected ∪ hitIDs)（若锚点初态已选则按锚点初态
     做反选，二选一必须在代码注释与测试中写死）；每帧从基线重算，往回拖自然移除。
     禁止 base ∪ SelectionRange 的一维累加。
  4) 自动滚动：手指坐标固定在 view 坐标；每帧若手指进入上/下边缘区（60pt，SwipeConfig），
     按 10pt/帧 setContentOffset（clamp 到 max(0, contentSize.height - bounds.height)）；
     滚动后用「同一手指 view 坐标 + 当前 contentOffset」重新换算命中并重算 rect；
     CADisplayLink 加 .common mode，松手 invalidate。
  5) 交互与状态：长按 0.15s 起、位移 4pt 阈值（全部进 SwipeConfig）；进入多选时若未选中则
     选中锚点 cell；拖曳期间 collectionView.isScrollEnabled=false 但由自动滚动接管；松手恢复
     滚动、隐藏 overlay、清空临时状态；overlay 颜色/边框只用 DSColor.tint token。
  6) 徽标与可访问性：PhotoGridCell.configure 重置 accessibilityValue 后必须按当前
     isSelectedCell 同步追加 selected/none；reloadSelectionBadges / updateSelectionCount 每帧
     调用但做差量更新（避免全量 reload 掉帧）；每个 cell 的 AX value 保持
     「<assetID> selected/none」契约（docs/09 D11）。
  7) testSlideToSelect 的计数/可见选中 >=6 断言保留并加强，不删。
先写失败测试：testRectSelectionUses2DIntersectionNot1DRange（Core 单测：空白/全包/回拖/
  乱序/NaN/跨 section/动态列数）、testDragSelectionRectMatchesFingerInViewCoordinates、
  testDragBackRemovesPreviouslySelected、testAutoScrollRecomputesHitsWithCurrentContentOffset、
