## 0. 结论摘要

### 0.1 一句话结论

用户这 8 条不是 8 个孤立 bug，而是 **4 组系统性缺陷** 在 M11 之后集中暴露；其中「大图不可见 / 捏合必崩 / 需要等待跳转」三条属于 P0 回归，M11 的 ✅ 结论不成立。

| 组 | 涉及反馈 | 共同根因 | 危害 |
|---|---|---|---|
| **A. 查看器几何与生命周期** | 1、2 | `ZoomableImageCell` 的 `imageView` 从未获得尺寸；`itemSize` 只在 `viewDidLoad` 设一次；`viewDidDisappear` 无条件 `cancelAll()`；捏合与单指 `UIPan` 同时识别，缩放事务里执行删除事务 | 点开大图全黑；双指捏合必崩；present 信息/分享后白屏 |
| **B. 启动索引与位置事务** | 3 | 首屏只推 500 张、其余按 500/批后台补齐；深月份锚点不在首屏时 `restorePositionIfNeeded` 挂起等 `isIndexComplete`；恢复期间仍会回写位置 | 冷启动先显示别处、再可见地跳转；「上次位置」被中间位置覆盖 |
| **C. 顶部/底部 chrome** | 4、5、6、7 | 独立一行的 SwiftUI 五段 `Picker` + `TabView` 两个 tab + `.navigationTitle("照片管家")`；倒计时环层直接叠在「撤销」文字按钮上且与 `UndoCenter` 两套时钟；toast 位置靠魔法数手改 | 顶部占两行、底部占一行；倒计时 UI 错位；iOS 15.5 下 SwiftUI Toolbar 合成点击不可靠 |
| **D. 多选坐标系与语义** | 8 | 用 `location(in: collectionView)`（content 坐标）的矩形去设置挂在 `view` 上的 overlay（屏幕坐标）；命中只走一维 `SelectionRange.ids` 且 `base ∪ range` 只加不减；自动滚动混用两种坐标 | 滚动后框选框整体错位、命中错图、往回拖不会取消选中 |

### 0.2 为什么 M11「已修复 + CI 全绿」不可采信（执行 Agent 必须先看懂）

1. `ViewerViewController.swift:920-927` `setZoomCallback` 先 `guard scale.isFinite else { return }` 才写 `debugZoomScale`；`:210-216` 横幅只格式化该变量 → `StabilityUITests.swift:238-239`「横幅不含 nan/inf」是**恒真断言**，NaN 永远写不进去。
2. `ViewerViewController.swift:177-219` 的 `Viewer-Debug` 全在 `#if DEBUG`，**Release IPA 不编译**；`openViewer` 依赖 `-uiTestingSessionMock`，真机路径完全没被断言覆盖。
3. `StabilityUITests.swift:223-241 testPinchZoom20Times` 只断言 `app.state` 与横幅；XCUITest 合成 pinch 打在 `ViewerRoot`，真实捏合器在 cell 内 `UIScrollView`，**未命中即空跑**。
4. 全项目**没有任何**「`imageView.image != nil` / `imageView.frame > 0` / 截图像素非背景色」断言；`ZoomGeometryTests` 20 条全是纯 Double 函数，零 UIKit 集成。
5. `docs/15 §5` 自认 UI 22/28、`§7` 自认 s01–s12 截图未随 artifact 产出；`docs/15 §3.2` 6 条 🟨（筛选/月份/位置）受 iOS 15 模拟器 AX 限制，不得删断言粉饰成绿。
6. `AppCrashLogger.swift:10-16` 只有 `NSSetUncaughtExceptionHandler`，抓不到 Swift fatal / SIGABRT / EXC_BAD_ACCESS / jetsam；`ViewerTrace.swift:20-30` 主线程同步写盘且全项目无 zoom 面包屑；`DiagnosticsView.swift:63-88` 只导 OSLogStore，`hasLastException/readLastException` 无调用点 → 用户在「设置→诊断」拿不到崩溃日志。

### 0.3 本轮修复原则（违反即打回）

1. **先红后绿**：每条反馈至少有 1 个在修复前会失败/崩溃的自动化用例；禁止先改实现再补测试。
2. **不掩盖症状**：禁止「关闭动画」「延迟 0.5s」「`try?` 吞掉」「`reloadData` 万能药」「把断言删掉/跳测」「只验 `app.state`」来让 CI 变绿。
3. **一个提交只对应一条根因**；禁止顺手重构把多个根因混在一起。
4. **单一事实来源**：查看器由 `ViewerViewModel.currentIndex` + `dataSource` + 可见 cell 唯一决定；位置由 `LibraryPosition` 锚点唯一决定；倒计时由同一个时钟源驱动；多选命中由同一坐标系 + 二维相交唯一决定。
5. **用户可见的「无跳转」是硬指标**：允许内部异步补齐，但不允许用户看到「先在别处、再滚过去」。
6. **不重写整个 App**：按模块替换，每模块有独立测试；不新增功能面，只做本轮 8 条对应的修复与必要的功能补齐（分类菜单、工具按钮、iCloud 下载入口、原生相册式多选、诊断导出）。
7. **红线不变**：永不永久删除（只 `PHAssetChangeRequest.deleteAssets`，TrashBin 仅 5s 撤销保险）；`PhotoDeskCore` 只 `import Foundation`；iOS 16+ API 黑名单；零第三方依赖、零网络；`ImagePipeline` 唯一取图入口；网格/查看器必须 `UICollectionView`；新增文件进 target；DesignSystem token；不增警告；中文文案。
8. **所有结论必须可验证**：本机能跑的 core 测试必须本机跑；iOS 侧必须 CI 跑；截图必须逐张打开确认；「没跑过」不得写成「已验证」。
9. **既有 AX 与功能不删**：`Library-Filter` / `Library-MonthJump` / `Library-Select` / `Batch-Filter` / `Batch-SelectAll` / `Tools-*` / `StorageStats-*` / `Toast-Undo` 全部保留或等价迁移；筛选面板、月份跳转、搜索、Vault、清理、存储统计等页面一个都不能丢。
10. **文档如实登记**：`docs/15 §3.2` 的 6 条 🟨 保持原状；真机未回填的项写「未验证」，不写成 ✅。

## 2. 逐项根因与修复方案（R01–R08）

> 每项的「先写失败测试」必须在实现**之前**落地并确认在基线代码上是红的；测试名可直接用于 `XCTest` / `XCUITest`。

### 2.1 R01 · 无法查看大图（P0）

**现象**：网格缩略图正常，点开全屏查看器黑屏/空白；部分照片 present 信息页、编辑、分享或切 Tab 后返回变白屏；iCloud 图无占位、无下载按钮。

**代码证据（4 个独立根因）**

| 编号 | 位置 | 事实 |
|---|---|---|
| A1（决定性） | `ZoomableImageCell.swift:80` / `:116-137` / `:224-239` | 只 `zoomContentView.addSubview(imageView)`；约束表里**没有 imageView / zoomContentView 约束**；`layoutImageContent` 只设 `zoomContentView.frame` 与 `scrollView.contentSize`，`:154-162` / `:176-187` / `:190-197` 均不设 `imageView.frame`。`UIImageView()` 默认 `.zero` 且 `autoresizingMask = .none` → 恒零尺寸，赋 `image` 也不可见。对照 `PhotoGridCell.swift:106-110`、`FilmStripView.swift:132-137` 都有四边约束 —— 精确解释「缩略图可见、全屏看不到」 |
| A2 | `AssetRepository.swift:194-199` / `ImagePipeline.swift:220-225` / `ViewerViewController.swift:871` | `isCloudOnly(_:)` 恒 `false`；`fullImage` 只查 `PHImageResultIsDegradedKey`、**不查 `PHImageResultIsInCloudKey`**；禁网时返回 nil → `if let image` 不成立 → `applyDownloadedImage` 不调用；`configure:180-183` 的 `cloudBox` 因 `isCloudOnly=false` 恒隐藏 → 纯黑且无法自救 |
| A3 | `ViewerViewController.swift:117-121` | `viewDidDisappear` **无条件** `pipeline.cancelAll()`（单例 `AppContainer.shared.imagePipeline`），且全类**无** `viewWillAppear/viewDidAppear`；`:727-731` / `:793-795` / `:799-803` / `:814` 任一 present 或切 Tab → 在途加载被取消且返回后无重挂 |
| A4 | `ViewerViewController.swift:140-156` / `:95-114` | `viewDidLoad` 里 `layout.itemSize = view.bounds.size`；`viewDidLayoutSubviews` 从不刷新 itemSize（仅 `:124-136` 旋转时改）；fullScreenCover 首布局 bounds 为 .zero/占位值 → 所有 cell 零尺寸，`:163` 的 `index * collectionView.bounds.width` 与 itemSize 失配 → 整页空白 |

**附带修复（同一根因族）**：`ImagePipeline.swift:213-235` `registerFullImageRequestID` 在 `requestImage` 返回**之后**，而 `ImageRequesting.swift:47-51` 对缺失资产**同步**回调 nil → `unregister` 先跑、陈旧 requestID 残留、`cancelAll` 取消错对象；`ResumeOnce.swift:13-34` 取消路径没有强制 `resume(nil)`，PhotoKit 不再回调时 `withCheckedContinuation` 悬挂（`SWIFT TASK CONTINUATION MISUSE`）；`ViewerContainer.swift:15-22` `updateUIViewController` 空实现、`onClose` 全项目无赋值 → `fullScreenCover(item:)` 再次打开可能复用旧 `ViewerViewModel`；`ViewerViewController.swift:901-904` 越界分支返回未 configure 的空 cell。

**修复方案（含不变量）**

1. `imageView` 加四边约束到 `zoomContentView`（`translatesAutoresizingMaskIntoConstraints = false`），或在 `layoutImageContent` 设完 `zoomContentView.frame` 后同步 `imageView.frame = zoomContentView.bounds`。**不变量 I5′**：`imageView.frame.size == zoomContentView.frame.size > 0` 且 `scrollView.contentSize == zoomContentView.frame.size`；`isUserInteractionEnabled == (image != nil && bounds > 0 && contentSize > 0)`（与 R02/B2 共用）。
2. `viewDidLayoutSubviews` 检测 `layout.itemSize != view.bounds.size` 时赋值 + `invalidateLayout()`，并用 `isProgrammaticScroll` 包住 `positionAtCurrentIndex` 重定位。**不变量**：`itemSize == collectionView.bounds.size`，零 bounds → 正常 bounds 后能自恢复。
3. `fullImage` 回传 inCloud 状态（新 `FullImageResult` 或独立 cloud 回调；`PhotoDeskCore` 不参与，属 App 层），VC 收到后 `cell.showCloudPlaceholder()` 显示占位 + 下载按钮 + 进度；**不变量**：`image == nil` 必有可见占位与下载入口，不出现无提示纯黑。
4. `viewDidDisappear` 仅在 `isBeingDismissed || isMovingFromParent` 时 `cancelAll()`；新增 `viewWillAppear` 对 `currentIndex` 对应 cell 重挂 `loadImage`；**不变量**：每次 appear 时当前 cell 必有 image 或有在途 Task。
5. `ViewerContainer.updateUIViewController` 在 `context` 变化时重建/更新 `ViewerViewModel`，`onClose` 接线复位 `viewerContext`；`ResumeOnce` 取消路径强制 `resume(nil)`；`requestID` 注册改到 `requestImage` 之前并用 generation 令牌防陈旧注销；越界 `cellForItemAt` 返回已 configure 的空态 cell。

**先写失败测试**：`testImageViewFrameMatchesZoomContentViewAfterImageApplied`、`testViewerShowsNonBlankImage`（截图中心像素 ≠ `DSColor.bgViewer`）、`testFirstLayoutItemSizeEqualsBounds`、`testZeroBoundsThenLayoutRecovers`、`testCloudOnlyAssetShowsDownloadButton`、`testFullImageReportsInCloud`、`testPresentInfoThenDismissRestoresImage`、`testViewerShowsImageOnOpen`。

**验收**：点任意缩略图 1s 内显示与网格一致大图；连续 20 次开关 + 每次 present 信息页返回仍显示；iCloud-only 显示占位/下载按钮，点下载进度可见且回填大图。

### 2.3 R03 · 上次位置记不准、冷启动需等待跳转（P0）

**现象**：打开软件先停在别处，过一会儿才跳到上次位置；有时干脆记错。

**代码证据**

- `LibraryPositionStore.swift:10-45`：`LibraryPosition v2` 已含 `assetID / sectionID / itemIndexInSection / offsetRatio / savedAt / schemaVersion`，键 `library.lastPosition.v2.<queryKey>`（`:67-84`），v1 兼容 —— **数据结构本身够用，问题不在存**。
- `LibraryViewController.swift:878-969`：`savePositionNow(reason:)` 用 `indexPathsForVisibleItems.sorted().first` + `currentSnapshotQueryKey`；`restorePositionIfNeeded` 按 assetID 精确 → `isIndexComplete == false` 则挂 pending → 回退 `sectionID + itemIndexInSection` → `offsetRatio`；`applyRestore` 用 `scrollToItem(animated:false)`。
- `LibraryViewController.swift:803-845`：`applySnapshot` 等 `dataSource.apply` completion 才更新 `currentSections / currentItemsBySection / currentSnapshotQueryKey`，之后才 `restorePositionIfNeeded`。
- `LibraryViewModel.swift:253-320`：首屏只推 **500 张**，后台 500/批补齐；`:388-466` `rebuildDerivedInBackground` / `pushSections`（`derivedRevision` / `filterGeneration`）；`:476-496` `reloadForQuery` 重置 `isIndexComplete = false` 并重启完成流程。
- `LibraryViewController.swift:1161-1180`：`scrollViewDidScroll` 的 0.3s Timer、`didEndDragging` / `didEndDecelerating` 都会回写位置 —— **恢复期间的中间位置会被当成「上次位置」写回**，覆盖锚点。
- 生命周期：iOS 15 SwiftUI `TabView` 切页不保证内嵌 `LibraryViewController.viewWillDisappear` 触发（`docs/13:277`），另靠 `scenePhase` / `willResignActive` 保存；去掉 TabView 后反而更明确。

**根因**：位置恢复是「先显示部分快照 → 等完整索引 → 再滚动」的**两阶段可见跳转**；且恢复期间的位置回写会污染锚点。

**修复方案（推荐锚点优先 + 首帧遮罩，允许等效实现，但不变量不可让步）**

1. 启动读 `LibraryPositionStore.load(queryKey:)` 得锚点；`LibraryViewModel.prepare` 首屏不再固定「最新 500」：用锚点 `assetID` 的 `creationDate` / 在完整 `PHFetchResult` 中的全局 index 求「锚点窗口」（例如以锚点为中心前后各半批，仍遵守每批 ≤500、分批 fetch 规则），把锚点所在批次作为**第一批**推给数据源。
2. `dataSource.apply(..., completion:)` 完成且 `currentSnapshotQueryKey` 更新后，用锚点 `assetID` 精确 `indexPathForItem` + `offsetRatio` 调 `scrollToItem(animated:false)`；从「首帧」到「定位完成」期间复用现有加载骨架/遮罩盖住网格，`isRestoringPosition = true`，**用户看不到中间位置**；定位完成才移除遮罩。
3. 后台继续 500/批补齐其余月份（保留 `startIndexCompletion`）；补齐用 Diffable 增量 `append`，若在锚点**之前**插入 section，必须按插入高度同步补偿 `contentOffset`。**不变量**：任何快照变更不得让首可见 `assetID` 漂移 > 1 行。
4. `isRestoringPosition` 期间**禁用** `savePositionNow` 的 Timer / `didEndDragging` / `didEndDecelerating` 回写；恢复完成后再启用。**不变量**：恢复期间零位置回写，绝不把「遮罩前的错误位置」写回覆盖锚点。
5. 锚点 asset 已删除/隐藏/不在当前 query 时，回退 `sectionID + itemIndexInSection + offsetRatio` 的最近可用项；仍失败则落最新月份并写一次新锚点。任何回退都**不得**触发动画或 `showJumpBanner`（那是用户主动月份跳转才用的）。
6. 每个 scope/filter 的 `LibraryQuery.key` 保持独立位置键（沿用 `library.filter.<scope>` 各自的筛选保持逻辑 `LibraryViewModel.swift:504-525`），切类不清空别类位置。
7. `viewWillDisappear` / `scenePhase` / `willResignActive` 三条保存路径统一调 `savePositionNow(reason:)`，保证杀进程前落盘；去 TabView（R07）后生命周期更明确。

**先写失败测试**：`testColdLaunchRestoresDeepMonthAnchorWithoutVisibleJump`（断言遮罩移除时首可见 assetID、无跳转 banner/无动画）、`testRestoreDoesNotOverwriteAnchorWithIntermediatePosition`、`testPerScopePositionKeysAreIndependent`、`testDeletedAnchorFallsBackToNearestSection`、`testRotationKeepsAnchorWithinOneRow`、`testPositionRestoredAfterRelaunch`（保留并改为真冷启动，不再只靠 `-uiTestingMonthJump` + 小幅拖动）。

**验收**：杀进程冷启动，深月份 / 大图库（≥5000 张）/ 筛选态三种场景下首帧遮罩移除时即锚点位置，误差 ≤ 1 行，无可见跳转、无 banner；恢复期间零回写。

- `PhotoDeskCore/Sources/PhotoDeskCore/SelectionRange.swift:15-29` 双向一维区间；`SelectionPolicy.swift:62-83` `replaceSelection/selectRange` 只过滤 scope、去重，**无二维矩形/反选语义**。
- `PhotoGridCell.swift:82-90` `setSelected` 改边框 + `accessibilityValue` 追加 `selected/none`；`:161-162` `configure` 把 `accessibilityValue` 重置成 `item.id`（cell 复用后选中态后缀可能丢失，需同步）。

**iOS 原生相册语义（目标）**：长按锚点后拖动，按**拖曳矩形与每个 cell 实际可见 frame 的二维相交**实时增减选中；拖过未选中的加入、往回拖自动移除；手指到上下边缘自动滚动且命中集合随 `contentOffset` 重算；松手后框选框消失、滚动恢复、选中态稳定；绝不出现「框选框与手指错位」「选中只增不减」。

**修复方案**

1. **单一坐标系**：手势点统一取 `gesture.location(in: view)` 作为「手指 / 屏幕」坐标；`boxStartPoint` / `lastBoxPoint` 全部存该坐标；`selectionOverlay`（挂在 `view`）直接用该坐标画 rect。命中换算改用 `view.convert(point, to: collectionView)` 得 content 坐标，或（推荐）把 `collectionView.visibleCells` / `indexPathsForVisibleItems` 的 `layoutAttributesForItem(at:)?.frame` 逐个 `convert` 到 `view` 坐标后与 rect 相交 —— 后者彻底避开 `contentOffset` 混淆。
2. **二维相交下沉 Core**：在 `PhotoDeskCore` 新增纯逻辑（**只 `import Foundation`**，用自定义 `struct Rect/Point`（Double 字段），不传 `CGRect`/`CGSize`/`UIImage`/`PHAsset`），例如 `GridHitRegion.hitIDs(cells: [GridCellRect], rect: Rect, threshold: Double) -> Set<String>`；处理 0/负/NaN/∞、边界相交阈值（进 DesignSystem/SwipeConfig）、乱序与跨 section。App 层只做 `CGRect → Rect` 适配。`SelectionPolicy` 复用 `replaceSelection`（不再累加 range）。
3. **基线重算语义**：`.began` 记录 `boxBaseSelected`（进入多选前的选中集）与 `boxAnchorID`；每帧 `selectionState.replaceSelection(boxBaseSelected ∪ hitIDs)`（若锚点初态已选则按锚点初态做 `⊕` 反选，二选一需在文档中写死并测试）；**每帧从基线重算**，往回拖自然移除。禁止 `base ∪ SelectionRange` 的一维累加。
4. **自动滚动**：手指坐标固定在 `view` 坐标；每帧若手指进入上/下边缘区（60pt，`SwipeConfig`），按 10pt/帧 `setContentOffset`（clamp 到 `max(0, contentSize.height - bounds.height)`）；滚动后用「同一手指 view 坐标 + 当前 contentOffset」重新换算命中并重算 rect（锚点也存 view 坐标，起始 rect 用两点 view 坐标构造，不再用旧 content 坐标）；`CADisplayLink` 加 `.common` mode，松手 invalidate。
5. **交互与状态**：长按 0.15s 起、位移 4pt 阈值（全部进 `SwipeConfig`）；进入多选时若未选中则选中锚点 cell；拖曳期间 `collectionView.isScrollEnabled = false` 但由自动滚动接管；松手恢复滚动、隐藏 overlay、清空临时状态；overlay 颜色/边框只用 `DSColor.tint` token。
6. **徽标与可访问性**：`PhotoGridCell.configure` 重置 `accessibilityValue` 后必须按当前 `isSelectedCell` 同步追加 `selected/none`；`reloadSelectionBadges` / `updateSelectionCount` 每帧调用但做差量更新（避免全量 reload 掉帧）；每个 cell 的 AX value 保持「`<assetID> selected/none`」契约（`docs/09 D11`）。
7. 保留 `testSlideToSelect`（`StabilityUITests.swift:365-395`）的计数/可见选中 ≥6 断言并加强坐标断言，不删。

**先写失败测试**：`testRectSelectionUses2DIntersectionNot1DRange`（Core 单测：空白/全包/回拖/乱序/NaN/跨 section/动态列数）、`testDragSelectionRectMatchesFingerInViewCoordinates`、`testDragBackRemovesPreviouslySelected`、`testAutoScrollRecomputesHitsWithCurrentContentOffset`、`testSelectionBadgesStayInSyncAfterConfigure`、`testSlideToSelect`（保留加强）。

**验收**：滚动任意距离后框选框与手指严丝合缝；往回拖取消选中；边缘自动滚动时命中随 `contentOffset` 正确重算；cell 复用后选中徽标与 AX 一致；≥55 FPS。

## 8. 红线与合规检查（Phase 8 逐条 grep）

1. `PhotoDeskCore/` 只允许 `import Foundation`；`Package.swift` `platforms:` 留空；Linux `swift build && swift test` 通过。
2. 删除只走 `PHAssetChangeRequest.deleteAssets` → 系统「最近删除」；UI 文案只说「移到最近删除」；TrashBin 仅 5s 撤销保险（上限 2GB、可关闭）。
3. 无 iOS 16+ API：`NavigationStack` / `PhotosPicker` / `ShareLink` / Swift Charts / `@Observable` / `ContentUnavailableView` / `.scrollContentBackground` / `.scrollTargetBehavior` / `.scrollPosition` / `ImageRenderer` / `.fontDesign` / `.toolbarBackground` / SwiftData；确需新 API 必须 `if #available(iOS 16, *)` 双实现（本轮不应需要）。
4. 零第三方依赖、零 `URLSession` 外发；`ImagePipeline` 是唯一取图入口；网格/查看器仍 `UICollectionView` + Compositional Layout + Diffable DataSource + Prefetching。
5. `.limited` 授权、`PHPhotoLibraryChangeObserver` 增量更新、分批 500、写操作 `performChanges` 全部保留。
6. 新增文件进 target（XcodeGen 自动包含，检查 `excludes`）；颜色/字体/间距/魔法数只用 DesignSystem token；每文件顶部 `// MARK: - 职责说明`；无 `try!` / 强制解包；无新增警告；中文文案按 `docs/04 §7` 校对。
7. commit 格式：`feat(viewer): ...` / `fix(library): ...` / `test: ...` / `docs: ...`。
