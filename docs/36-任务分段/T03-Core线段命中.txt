# T03 — Core 线段命中解析

> 自包含任务卡。只读本文件 + `docs/37 §4/§7` + `docs/38 §2/§3/§4`。

## 0. 目标

把「矩形 ∩ cell」换成「指尖线段 ∩ cell」，输出**按经过顺序**的 id 序列。Core 只 `import Foundation`；不引入 `CGRect/CGPoint`。

## 1. 只读范围

- `PhotoDeskCore/Sources/PhotoDeskCore/GridHitRegion.swift`（`GridPoint` 复用）
- `PhotoDeskCore/Sources/PhotoDeskCore/MarqueeHitResolver.swift`（`CellFrame` 抽出处）
- `PhotoDeskCore/Sources/PhotoDeskCore/SlideSelectConfig.swift`
- `PhotoDeskCore/Tests/PhotoDeskCoreTests/MarqueeHitResolverTests.swift`（旧用例仅作边界参考）
- `PhotoDesk/Features/Library/GridHitTester.swift`（理解 App 将喂什么 frame；本卡不改它）

## 2. 步骤

1. 红测试 `PhotoDeskCore/Tests/PhotoDeskCoreTests/TrailHitResolverTests.swift`（≥18 条）：
   - 水平/垂直/斜线；反向线段必须产出反向 id 顺序；零长度线段命中起手 cell；快速一帧跨 5 格补扫。
   - 贴边 1pt 扩展命中；完全不交；cell 乱序/同 id 重复；`clipTop` 半裁/全裁/低于上边不生效。
   - `NaN`、`±∞`、负宽 frame、退化 frame；`expansion < 0` 钳制；2 万 frame <20ms。
   - 排序稳定性：相同 `tMin` 时按 id 排序，结果确定。
2. 跑 `scripts/test-core.ps1` 得红编译失败 → `artifacts/audit/m18/t03/red-compile-failure.log` → 提交红测试。
3. 新增 `PhotoDeskCore/Sources/PhotoDeskCore/GridCellFrame.swift`：把 `CellFrame` 定义从 `MarqueeHitResolver.swift` 搬来；旧文件改为 `typealias CellFrame = GridCellFrame`（或保留同名并标 deprecated，二选一，必须保证旧测试编译）。
4. 在 `SlideSelectConfig.swift` 补 `hitExpansion = 1`、`segmentEpsilon`；保留 `edgeBuffer/minStep/maxStep`。
5. 新增 `PhotoDeskCore/Sources/PhotoDeskCore/TrailHitResolver.swift`：
   - `orderedIDs(from: GridPoint, to: GridPoint, cells: [CellFrame], clipTop: Double?, expansion: Double, epsilon: Double) -> [String]`。
   - 用 Liang–Barsky / slab 法求线段参数 `[tMin,tMax]` 与每个扩展后 cell 矩形的交；`abs(dx) <= epsilon` / `abs(dy) <= epsilon` 走退化分支。
   - `clipTop` 先抬高 cell 下边参与命中（粘性头遮挡区不可命中），不是只过滤 cells。
   - 按 `max(tMin,0)` 升序、id 升序排序；同 id 去重保序；非法 frame 逐个跳过。
6. Core 全绿 + CI core-linux 复验；记录用例总数与性能数字。
