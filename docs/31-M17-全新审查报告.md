## 1. 结论摘要

1. 用户报的三个问题**不是同一个 bug**，而是**三处独立设计缺陷**叠加：手势仲裁（无方向锁 + 双指滚动劫持）、命中几何（用 token 重建网格 + 读粘性头属性）、交互缺位（根本没有长按识别器）。
2. 三个问题**互相放大**：没有长按 → 用户只能点工具栏进多选 → 进多选后单指不能滚动（被改成双指）→ 用户强行单指拖 → 6pt 就触发框选 → 手感「生硬」；同时框选起点取的是 pan `.began`（手指已移动约 10pt）→ 起点错格 → 「动作不明确」。
3. 滚动后错位有**可计算的确定成分**：off-screen section 的 origin 走估算链，每段多算 `gridSpacing` = 2pt（见 §2.2 推导）；另有粘性头属性污染（H1）与 apply 窗口几何整体失效（确定）。
4. 另外发现 **9 类跨页面缺陷**（§3），其中 4 类违反 AGENTS.md 架构红线（Feature 层直接引用 `PHAsset`），2 类会导致用户可见的功能错误（相簿页不刷新、搜索页数据陈旧）。

## 2. 用户三问的根因

### 2.1 问题 1：滑动多选「非常生硬」、选/取消动作不明确

| 编号 | 根因 | 证据 | 影响 |
|---|---|---|---|
| G1 | 多选模式把滚动改成了**双指专属**：`panGestureRecognizer.minimumNumberOfTouches = 2`，用户单指一拖就被框选接管 | `LibraryViewController.swift:802`、`:832` | 违反 iOS 直觉；用户以为卡住/误选 |
| G2 | 框选激活**无方向锁**：只要位移 ≥6pt 就进入框选（`activationThreshold = 6`），纵向下滑也变框选 | `SlideSelectConfig.swift:11`、`SlideSelectGestureController.swift:132-140`；旧的方向锁 `SlideSelectPolicy.shouldActivate` 在 App 内 **0 引用** | 轻微手抖即误选 → 「生硬」 |
| G3 | 起点取 `gesture.location` at `.began`。`UIPanGestureRecognizer` 需约 10pt 位移才 `.began`，此时手指已离开按下点；锚点 cell 可能是**邻居格**，矩形起点也不是按下点 | `SlideSelectGestureController.swift:110-126` | 「我明明按住的是这张」 |
| G4 | 没有任何可视反馈：无选框 overlay、无按下态、无选中动画、无 dim；只有角标突然出现/消失 | `SlideSelectGestureController.swift`（全文无 overlay）、`PhotoGridCell.swift:60-100` | 不知道当前是「加选」还是「减选」 |
| G5 | 每帧 `replaceSelection(Array(ids).sorted())`：O(n log n) 排序 + 全量替换；全选 2 万张时每帧排序 | `LibraryViewController.swift:994`、`SelectionPolicy.swift:replaceSelection` | 拖动掉帧、计数跳动 |
| G6 | 触觉反馈对**每个集合变化**都 `selectionChanged()`，高频拖动时变成连续震动 | `SlideSelectGestureController.swift:186` | 「生硬」的体感来源之一 |

### 2.2 问题 2：滚动后多选错位

命中几何由 `marqueeGeometry()` **按设计 token 重建**（`LibraryViewController.swift:958-989`）：

```
itemSide = (W − s·(c−1)) / c
pitchY   = itemSide + s
top      = sectionOriginY[i] + headerHeight
```

三处确定缺陷：

| 编号 | 根因 | 证据 / 推导 |
|---|---|---|
| G7 | **估算链每段多算 2pt**。真实段高 = `header + rows·itemSide + (rows−1)·s`；估算写的是 `maxY + rows·(itemSide+s)`，每段多 `s = 2pt`。月分组越多，偏移越大（48 个段 ≈ 96pt ≈ 整行） | `LibraryViewController.swift:976`；`DSSpacing.gridSpacing = 2` |
| G8 | **粘性头污染 originY（H1）**。`layoutAttributesForSupplementaryView` 对 `pinToVisibleBounds = true` 的头，可视区内的返回 frame 可能已按钉住位置平移，此时 `minY` 是「视口顶」而不是「段内容顶」→ 整段行坐标下移数百 pt | `LibraryViewController.swift:972-976`、`:1748`；需 T05 的单测实测（见 docs/32 §4.2） |
| G9 | **apply 窗口整体失效**：`guard counts.count == currentItemsBySection.count` 不成立时直接返回 nil，`processFinger` 静默 return → 拖动不跟手、松手前突然跳变 | `LibraryViewController.swift:966`、`SlideSelectGestureController.swift:168-171` |
| G10 | **每帧 O(S) 次布局查询**：为每个 section 调一次 `layoutAttributesForSupplementaryView`；S=数百月时每帧数百次布局计算 | `LibraryViewController.swift:970-981` |
| G11 | 粘性头覆盖的 48pt 区域内的 cell 也会被矩形命中（用户看不见却被选中） | 同上，命中未裁剪可视区 |
| G12 | 自动滚动时 `scrollView.isTracking == true` → 位置记忆把拖选期间的 offset 当「用户滚动」保存 | `LibraryViewController.swift:1861-1867` |

**结论**：G7 是可算的确定偏差，G8 是「滚动后突然大偏移」的最可能主因（H1），G9/G10 是「不跟手/掉帧」的确定原因。三者都源于同一个错误决策——**用参数重建几何，而不是读取真实 layout attributes**。修复必须整体删除 `marqueeGeometry()`，不是调参。

### 2.3 问题 3：无法长按进入多选

| 编号 | 根因 | 证据 |

### 2.4 与 iOS 原生相册的行为差距（目标基线）

| 场景 | iOS 原生 | 当前实现 | 差距 |
|---|---|---|---|
| 长按缩略图 | 进入多选，该图选中，轻触觉，不弹菜单 | 无反应 | ❌ |
| 多选中单指上下滑 | 正常滚动 | 不滚动（需双指） | ❌ |
| 多选中单指横向/斜向拖过缩略图 | 框选，实时角标 | 6pt 即触发，无方向锁 | ⚠️ |
| 框选视觉 | 半透明选框 + 角标 + 轻微压暗 | 仅角标 | ❌ |
| 从已选图起拖 | 沿途取消选择，选框色不同 | 逻辑有，视觉无区分 | ⚠️ |
| 边缘自动滚动 | 平滑加速，选到屏外 | 有，但几何漂移 | ⚠️ |
| 双指拖过多张 | 连续多选（iOS 原生特性） | 无 | ⚠️（P2 增强） |
| 计数与角标 | 严格一致 | 一致，但 scope 缺口（G17） | ⚠️ |

## 4. 测试与门禁缺口

1. `MarqueeSelectionUITests` 全是**范围断言**（`≥3`、`≤8`、`≤12`），没有任何「指定 assetID 必须在/不在选中集」的精确断言 → 错位 20~200pt 也能通过。
2. 一条测试自比较：`let total = waitForSelectionCountEqual(app, to: selectionCount(app), timeout: 0.1)`——永远成立，等于没测全选总数（`MarqueeSelectionUITests.swift:268`）。
3. 无长按进入、无「多选下单指滚动」、无「框选 overlay 存在」、无「粘性头下不误选」用例。
4. `PhotoDeskTests` 里没有任何**真实 UICollectionView + 真实 layout** 的几何测试，`MarqueeSelectionPolicy` 只用合成 metrics 自证 → 布局参数一变就失真。
5. `audit-m16.ps1` 的必检文件清单与断言语义面向 M16 三项 P0，已不覆盖本轮问题（本轮已重写为 `audit-m17.ps1`，19 项，含 9 项 BLOCKING）。
