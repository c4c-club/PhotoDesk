## 1. 平台策略

| 项 | 决策 | 理由 |
|---|---|---|
| 开发方式 | **原生 Swift** | 深度依赖 PhotoKit / PHAsset / 系统相册互通，跨平台方案在此场景只有劣势 |
| UI 框架 | **SwiftUI 为壳 + UIKit 为核** | iOS 15 下 SwiftUI 缺 `NavigationStack`/`PhotosPicker`/`ShareLink`；且万级网格与分页浏览器用 SwiftUI 性能不达标 |
| 最低系统 | **iOS 15.0** | 用户指定 |
| 设备 | iPhone 优先；iPad 保证可用（不崩不变形），不专门优化 | 首版聚焦 |
| 语言 | Swift 5.9+，启用 `async/await`（iOS 15 已支持 back-deploy 到 13） | — |
| 第三方依赖 | **0 个**（目标） | 自签名 + 隐私承诺；Core Data / PhotoKit / Vision / Core Image / MapKit 全为系统框架 |
| 数据存储 | Core Data（`NSPersistentContainer`）+ `UserDefaults`（设置） | 无 App Groups，数据库放默认沙盒目录 |
| 工程生成 | XcodeGen（`project.yml`）首选；无 brew 时退化为 Xcode 手工工程 | 命令行友好，便于 Agent 与 CI |
| **核心逻辑包** | `PhotoDeskCore` 独立 SwiftPM 包：**零 Apple 框架依赖**（手势判定、日期分组、dHash/pHash、去重分组、撤销策略、回收站淘汰策略） | 可在 **Linux 上 `swift build && swift test`**，无 Mac 也有秒级反馈（见 06 §7.4） |

## 3. 技术选型与理由

### 3.1 网格与浏览器用 UIKit（`UICollectionView`）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| SwiftUI `LazyVGrid` | 代码少 | iOS 15 上万 cell 滚动掉帧、内存高、无 prefetch 精细控制 | ✗ |
| `UICollectionView` + Compositional Layout + Diffable DataSource | 预取、cell 复用、内存可控、`UICollectionViewDataSourcePrefetching`、iOS 13+ 可用 | 代码量大 | ✓ **采用** |

- 网格：Compositional Layout，列数变化只改 layout，不重建数据源。
- 浏览器：自定义 `UICollectionView`（paging，cell = 屏幕宽）+ 每 cell 内嵌 `UIScrollView`（缩放）+ `UIPanGestureRecognizer`（上下滑）。
- 两者都用 `UIViewControllerRepresentable` 嵌进 SwiftUI 导航壳。

### 3.2 图片加载三级缓存

```
内存 NSCache（按屏幕缩略图数量 × 3 屏，totalCostLimit 60MB）
   ↓ miss
磁盘缓存（Library/Caches/ThumbCache，key = localIdentifier + 尺寸，LRU，上限 200MB）
   ↓ miss
PHCachingImageManager → PHImageManager.requestImage（targetSize = 屏幕像素 × 2）
```

- 滚动时用 `startCachingImages(for:targetSize:contentMode:options:)` 预取可视区 ± 20 个。
- cell 离屏 `cancelImageRequest(_:)`。
- 大图页：`deliveryMode = .opportunistic`（先给低清再高清），`isNetworkAccessAllowed` 由设置控制。

### 3.3 重复 / 相似检测

| 步骤 | 方案 |
|---|---|
| 指纹 | 缩到 32×32 灰度 → **dHash**（64 bit，存 2×Int64）+ 可选 **pHash**（DCT 8×8，64 bit） |
| 快速分组 | 按 (像素宽高比 + 创建时间戳 ±2s + dHash) 先做粗筛，降低比较量级 |
| 判定 | 汉明距离 ≤ 8 → 疑似重复；≤ 4 → 高置信 |
| 相似（非完全重复） | 可选：`VNGenerateImageFeaturePrintRequest`（iOS 13+，本地）计算特征距离 |
| 推荐保留 | 原图 > 尺寸最大 > 有编辑 > 最新修改 |
| 性能 | 缩略图批量取 256px；后台 `DispatchQueue.global(qos: .utility)`；每 200 张 yield 一次进度；结果写入 Core Data |

### 3.4 隐藏的两种实现（已确认 A 可行）

- **方案 A（采用）**：`PHAssetChangeRequest(for: asset).isHidden = true` —— 已确认为公开 API（iOS 8+）。配合 `PHFetchOptions.includeHiddenAssets = false` 让主网格不显示，并提供「已隐藏」入口。
- **方案 B（备用）**：自建用户相簿「应用内保险箱」+ App 内过滤。仅在 A 出现兼容问题时启用。

### 3.5 删除语义与撤销体系（★ 产品红线：永不永久删除）

**删除的唯一实现**：`PHAssetChangeRequest.deleteAssets` → 照片移入**系统「最近删除」**，由系统保留 **30 天后自动清除**。

- **应用内滑动 / 批量清理，都只做"移到最近删除"这一件事**，App 不提供永久擦除、不二次清除「最近删除」。
- 系统会自动弹一次确认框（无法绕过），App 侧再加一层可选确认（`confirmDestructive`）。

**撤销的两条路（缺一不可）**：

| 路径 | 时间窗 | 实现 |
|---|---|---|
| ① App 内一键撤销 | 执行后 5 秒（可设 3/5/10s） | 撤销窗口内点 Toast「撤销」→ 从 App 沙盒副本重建并写回系统相册 |
| ② 系统相册自助恢复 | 30 天 | 用户在系统相册「最近删除」恢复；App 内「最近删除」页提供跳转入口 |

> ⚠️ **为什么还需要沙盒副本？** iOS **没有公开 API 可以从「最近删除」程序化恢复**。若不预存副本，App 内的"撤销"就做不到。
> 因此：执行 `deleteAssets` **之前**，先 `requestContentEditingInput` 拿到原件（视频走 `AVAssetExportSession`）拷进 `ApplicationSupport/_Trash`，并记下 `creationDate` / `location` / UTType；
> 撤销时用 `PHAssetCreationRequest.fromImage(atFileURL:)` / `fromVideo(atFileURL:)` 重新写回系统相册，再还原元数据。
> - 沙盒副本**只是短期撤销保险，不是备份**：默认上限 2GB、按时间淘汰、可关闭；真正兜底的是系统「最近删除」的 30 天。
> - iCloud-only 资源未下载时**拒绝执行删除**（拿不到原件就没有撤销能力），提示用户先下载。
> - 内存：`UndoEntry` 队列 + Toast 交互；持久化：Core Data `ActionLog`（含 `prevState`），App 重启后 10 秒内仍提示可撤销。

## 4. 执行环境方案（已锁定）

> 完整方案见 [06 §7](06-构建签名与测试发布方案.md)。本节为结论摘要。

**🔒 锁定方案：Windows 编辑 → Git 推送 → Actions 编译 → 手机验证**（2026-10-24 拍板）

**硬事实**：iOS 应用**只能**在 macOS 上编译、签名、跑模拟器。Windows 与 Linux 都做不到（Xcode 是 macOS 专有、许可限制、无 iOS SDK / 链接器 / 模拟器）。

**环境已探测**（见 [08](08-环境探测报告.md)）：Agent 与用户同为 **Windows 10 原生**（MINGW64），`xcode-select` / `xcrun` 均不存在。

| 实测项 | 结果 | 在锁定方案中的角色 |
|---|---|---|
| OS / Xcode | Windows 10 19045 原生；无 Xcode | 编辑端；编译 100% 交给 Actions |
| 本机 iOS 模拟器 | 无 | 不用——验证走真机 |
| WSL2 | 已启用，仅 `docker-desktop`，无 Ubuntu | **维持原状，不装 Ubuntu** |
| Docker | 29.8.2 已装，daemon 待启动 | ★ 本地跑 `swift test` 的唯一途径 |
| ZCode「iOS 模拟器」插件 | macOS 本地包装，含 `platform === "darwin"` 硬检 | 不装，搁置 |

**三条通路，缺一不可：**

| 通路 | 手段 | 说明 |
|---|---|---|
| ① 本地秒级反馈 | **Docker `swift:6.0-noble` 容器** + `scripts/test-core.ps1` | **不装 Ubuntu**；容器用完即弃，不引入 Linux 系统 |
| ② 编译 / 测试 / 出包 | **GitHub Actions `macos-14`** | 公开仓库免费；私有 Free 2000 分钟/月（macOS 按 10× 计费 ≈ 200 分钟）。产出模拟器 `.app` 与**未签名 ipa** |
| ③ 手机验证 | **AltServer(Windows) 签名安装** | 免费 Apple ID，7 天续签；付费账号（¥688/年）可升级为 CI 全自动签名 |

**工作流**：Windows 写代码 → Docker 跑 `swift test` → git push → Actions 编译测试出包 → 下载未签名 ipa → AltServer 装到 iPhone → 真机验证手势 → 需要 Instruments 时临时租云 Mac。

**备选（非主路径）**：云端 iOS 模拟器 Appetize.io（手边没手机时快速看一眼）；二手 Mac mini（长期迭代）。

**不做的**：安装 WSL2 Ubuntu、安装 ZCode「iOS 模拟器」插件、Hackintosh、Windows 原生 Swift 工具链、迁移操作系统。

**模拟器注意（CI 侧）**：iOS 15 模拟器需在 macOS runner 上用 `xcrun simctl` 创建；模拟器**不需要签名**；往模拟器放测试照片用 `simctl addmedia booted <images...>`。

## 8. 验收 Definition of Done（每个里程碑通用）

1. 在 **iOS 15.5 模拟器** 与 **iOS 最新真机** 上均可编译、启动、核心路径不崩。
2. 新增代码有单元测试（核心逻辑）或 UI 测试（交互路径）。
3. 滚动/内存通过 Instruments 检查（FPS ≥ 55，峰值 < 250MB）。
4. 无 Xcode 警告；`AGENTS.md` 规则全部遵守。
5. 更新 `docs/05` 进度表与变更日志。
6. Git commit 并按规范命名。
